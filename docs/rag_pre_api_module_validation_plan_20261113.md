# API前逐模块验证约定与第一轮范围

用户要求先解决不调用API的前段问题，每次只改一个问题、比较API前结果，最后再验证答案。

当前运行代码已恢复到 `reports/rag_support_graph_20261113/baseline_src`。QueryPlan增强、结构化回答、答案二次审核和语义澄清关闭。基础问题解析仍运行。

本次只读取冻结A组91题的检索轨迹并重新统计，未重新运行模型、未调用远程API、未修改业务代码。本地文件哈希与A基线一致。结果保存在 `reports/rag_pre_api_baseline_20261113/summary.json`。旧答案判分不得用于选择本轮前段候选方案。

## 3. 第一轮只处理一个问题：同文档硬配额

待检验的问题：同一文件中的互补证据，是否被“每文件最多3段”在无需排除的情况下丢掉。

原始轨迹直接记录的例子：019场景页、021条件分支页、023报警表格行、030质控数据处理页、电压题供电范围页。它们用于追踪机制，不能在运行逻辑中根据题号、页码或答案值保护。

第一轮固定：问题解析、原始切片、索引、全部召回候选、融合分数、重排分数及顺序、条件判断及顺序、最低质量阈值、最终总Top-K、Context字符预算。

第一轮只允许改变：文档配额是否一票排除。先用冻结候选做隔离对照；“放宽或移除单文档配额”只是待检验假设，不直接改成默认。不能同时增加总Top-K、放宽质量阈值、修改条件排序或增加字段覆盖模型。

步骤：

1. 用回退后的当前实现重放原始候选，证明基线输出与已保存A组实际Context一致；不一致先定位，不能开始比较。
2. 对全部91题应用同一个配额候选方案，记录保留、移除、替换和截断；不只跑受益例题。
3. 检查相关资料增加是否带来重复堆积、错误报警/型号混入、跨文档必要证据被挤出。
4. 对每条正确证据损失和新增强负例查看实际行/正文、对象和条件，不能仅凭相同页码或文件名认定支持或冲突。
5. 只有完整证据保留有跨问题收益、已有完整题不退化且没有新增确认的对象/范围错误，才采用该单项修改。若失败，保留旧实现并记录原因，不继续围绕题号补例外。

004/006的最终Top-K丢失，以及条码来源选择，可能涉及条件排序或重复文本占位，不强行放进同文档配额修复；它们必须作为回归观察，不承诺本轮解决。

## 4. 每轮只比较API前的结果

固定使用现有source-quote-v3判分，不改Gold、不改review_status、不修改组和分母。

- 各阶段Recall@1/3/5、MRR及完整引文覆盖；区分首次出现、排名下降、首次退出。
- 实际发送Context的完整Gold引文保留率；不能用整个原始chunk或同页相似内容代替实际included_text。
- 已有正确证据是否被挤掉；跨页互补内容是否齐全；被排除的具体原因。
- 强负例的实际正文与对象是否被作为有效证据保留。一个页面同时含正确表格行和邻近错误行，不能仅因同页出现负例就认定错误使用。
- Context段数、字符数、来源分布和重复占用。保持总预算相同，不能靠无限扩容宣称算法改善。
- 正式集合、待审诊断集合及业务组宏平均分开。

不使用答案一致率、LLM裁判分数或最终回答好坏决定前段改动。前段证据正确只证明生成具备所需输入，不保证最终回答必然正确。

## 5. 不调用API的执行约束

- 实验在 `credential_read`、`gateway.generate` 等任何远程生成入口之前结束。
- 禁止调用语义澄清、结构化计划、答案审核、远程Embedding/重排服务和GoldAnswerJudge。
- 优先重放已冻结的本地候选与分数。确需重新运行检索时，只使用已下载的本地向量/重排模型；不可用则记录阻塞，不自动切换远程服务。
- 实验入口应使用会抛错的远程网关替身，验证误入远程链路会立即失败；不能仅靠“本次看起来没有调用”保证边界。
- Gold只进入离线计分和复核，不进入查询、排序或选段决策。

## 6. 后续模块顺序

不机械地按“切片→query→检索”把所有模块重写一遍，而是按剩余证据损失的最早可确认环节选下一项。

1. 本轮：文档配额单项隔离。
2. 若仍有“前面高分、条件排序后落到截断外”：单独核对条件排序及未知条件处理，配额和其他模块冻结。
3. 若融合候选有证据、重排后没有：单独检查重排输入、评分与截断，不能同时调检索。
4. 若关键词/向量候选就没有：再逐步区分查询词、融合深度、索引缺失与切片断裂。先检查原文和已索引正文，证实切片有问题才改切片。
5. 每采用一项，冻结新的前段基线再开始下一项；未通过的试验不能叠加进入下一轮。
6. 前段达到退出条件后，固定Context再统一调用API验证最终答案。不能在前段每改一次就重跑答案并反过来调整检索。

## 7. 前段退出条件

不承诺“所有问题100%召回”才结束。结束条件为：已确认的主要前段损失完成修复或被明确归类；原正确题无新增实质证据损失；强负例与对象/范围风险经过核对；剩余资料缺失或版本争议明确列出；有未参与参数选择的样本验证。

当前91题已有多轮调试历史，只能称开发/回归集合，不能重新包装成独立验收集。独立验证需要事先冻结未参与该轮调试的问题与证据；新标注保持pending，不混入正式分母。

## 8. 交付

每轮生成report.html，沿用原程序格式，展示API前A/B阶段排名、实际Context、来源位置、得失和排除理由；答案栏明确“本轮未运行”，不得拿旧答案冒充新答案。另保留原始JSON、变更文件、实验开关、冻结哈希、采用/不采用结论。

当前完成的是前段基线定位；第一轮配额候选尚未实施、尚无收益结论。
