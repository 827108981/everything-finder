# 通用证据支持链路：实施前审计与冻结协议

本轮从当前工作区快照开始，所有现存业务题库、活动清单及 evaluation Python 文件已逐文件 SHA256 冻结；不改变 Gold、分母、状态或判分逻辑。当前发布 AI bundle：g000033-71ec3c52f3。

## 审计结论
- QueryAnalyzer → QueryInterpreter → enrich_plan 产生计划；question_rule 是语义匹配来源，不是检索证据。原问题始终保留。
- 当前 stage/scope/direction 及 legacy device/topic 可成为硬条件；ConstraintMatcher 先排序，EvidencePolicy 对 hard conflict 淘汰、对关键条件 unknown 整题拒答。
- identifier_evidence 保护有限精确代表；证据仍受同文档 3 段、总 TopK、字符预算限制。不同答案字段没有共同覆盖目标。
- source_consensus 只合并明确范围的枚举字段；fact_schema 以原文行提取，缺少可追溯支持图。未知对象不会被当成同对象。
- ContextBuilder 只对已进入上下文的文本形成事实；source_map 记录真实来源，但原始行序号不能代表跨片段业务步骤。
- generation/structured 逐主张计划并审核；把短引文当作所有标识符/数字的唯一核验窗口，易误拒；解析或审核失败整题拒答，没有兼容回退。
- AnswerReviewParser 在 verdict=insufficient 或部分最终引用不匹配时收敛整题拒答，会丢掉已核验主张。
- 旧阶段歧义判断只看到两种阶段即追问；语义判断已有引用原句验证，但无已知事实交付机制。
- 引用校验主要验证 S 编号存在，不等于事实正确。LLM 审核也不是业务人工裁决。
- 当前持久化配置：QueryPlan/Structured 未写入（有效默认关闭）；review=false、strict=true、semantic clarification=false。旧完整答题没有执行后两者。
- 已有评测读取 Gold，仅用于检索完成后的来源映射/裁判。线上模块不得导入 evaluation 或 fixtures。

## 实施层与约束
1. 解析层：明确型号/标识符继续约束；阶段、数量范围、方向和主题降为软条件。未知适用范围保留并明确限定，不等于已适用。
2. 证据层：在合格候选中加入有界字段/数值角色覆盖；保护原始高相关证据，不越过硬型号/报警冲突门禁。
3. 事实层：来源、事实、范围、条件节点；仅原文明确支持的步骤/父子关系建边。字段状态区分检出提示和已审核支持，不将关键词命中冒充充分支持。
4. 答案层：同一个主张可绑定多个真实引文；结构检查+语义审核；有缺失字段时从旧链路提取、核验再合并，不直接混入自由答案。
5. 故障路径：网络/解析失败有明确审计记录，保留旧自然语言入口与配置开关；审核失败 non-strict 告知用户未核验。
6. 配置：基础机制测试后启用新配置，同时保留可逆备份。若全量业务门槛失败，明确标记未通过，不能以启用状态代替验收。
