## 1. 为什么进行这一轮

上一轮的“先整理证据清单，再生成回答”候选没有达到采用条件。正式 48 题首轮，现行流程与候选均有 35 题被自动裁判判为 consistent；008、015 有三轮稳定改善，但其他题出现漏答、错条件或无依据扩展。自动裁判一致数不是人工确认正确率。

来源审计共核验 124 条正向引文：124 条均在原资料和当前 AI 索引中找到，两臂实际上下文各覆盖 105 条。这里的差额是 **19 条引文，不是 19 道题，也不是已经证实的 19 项必要事实缺失**。

本轮必须先解决三个未知点：

1. 哪些缺失引文对应真正必要、且没有等价资料支持的事实？
2. 必要事实在哪个处理环节首次丢失？
3. 把这些事实的原始资料送给现行回答模型，是否真的带来稳定、可复核的改善？

只有回答了这些问题，才能决定下一项算法开发。不能仅因某道题没答出来，就继续调整重排权重、扩大上下文或增加回答提示。

## 3. 本轮必须遵守的通用原则

- 候选运行时只能看到真实用户问题、当前资料、结构及来源元数据。题号、Gold、预期答案、人工选中的正确段落编号不得进入自动候选决策。
- 条件来自具体问题与资料，可以是任意会改变答案的属性。机型、阶段、报警、单个或多个项目只是例子，不能变成全部业务的固定判断模板。
- 未知条件保持未知。不能默认适用，也不能默认冲突；方法型问题可以回答条件分支，不应一律追问。
- 同一文件、相邻页、相同关键词或编号不能单独证明适用。表格须绑定行列、表头和单位；跨页须核实章节延续及对象关系。
- 原文逐字存在只证明存在。判分同时检查所问事实、适用对象、条件、顺序、数值单位，以及回答实际引用是否支持实际断言。
- 每轮冻结后不调提示、不改阈值、不换题、不改 Gold。必要修正产生新版本和新报告，不回写原始结果。
- 每一步都写输入、检查、发现、结论和下一步。结论只允许通过、失败、待核实或不适用；不适用必须注明前置门槛为何未满足。
- 不在完成某一步后停下来等待常规确认。继续执行所有已满足前置条件的阶段；遇到具体业务冲突只暂停依赖部分，完成其他审计与最终报告。

## 6. 阶段 1：判断是否真的缺少必要事实

### 6.1 审计范围

完整审计上轮未送达的 19 条引文，并检查其所属问题的全部实际上下文，而非仅查 Gold 指定文件。同时审查 035、032 这类“资料可能齐全但回答仍错”的代表题，作为归因对照。

逐条完成以下核对：

1. 阅读用户问题，写出回答请求，不添加用户没问的操作。
2. 将必答内容拆为最少的事实单元：事实本身、适用条件、确需保留的顺序或数值单位。只供审计判分，不交给候选。
3. 在真实 PDF/PPTX/DOCX 中核实位置及布局，表格与跨页关系必要时看原始页面图像；PPTX 备注与画面正文明确区分。
4. 检查 Gold 要求是否过多：可选背景不能成为必答，安全要求须确实适用于题目操作。
5. 搜索本题实际发送文本中的适用等价证据，包括不同格式同正文及用户已认可的替代来源。
6. 根据事实支持程度分类；来源无法确认时不得用文本相似度代替业务确认。

### 6.2 分类口径

| 分类 | 含义 | 后续处理 |
|---|---|---|
| necessary_gap | 必答事实没有适用来源进入实际上下文 | 进入最早失败定位与补齐诊断 |
| equivalent_present | 指定引文没进来，但其他适用资料已完整支持 | 不算资料缺口；检查回答是否正确使用 |
| optional_missing | 缺失内容不是本题必须回答的事实 | 不修算法来追求该引文命中 |
| partial_support | 只有部分事实，或缺必要条件/步骤/单位 | 明确缺的部分，再做定位 |
| applicability_unresolved | 文字存在，但对象或条件关系尚未确定 | 单列争议，不进入确定收益分母 |
| gold_disputed | Gold 本身错误、过度要求或来源冲突 | 保留原判，另存复核；不自行改状态 |

## 7. 阶段 2：找到最早有证据支持的失败环节

按同一题的完整 trace 检查：

| 环节 | 必须检查的材料 | 不能替代的判断 |
|---|---|---|
| 原文/解析 | 原页、表格/图片/备注、解析正文 | 原文存在不代表对象关系已解析正确 |
| AI 索引 | 当前 bundle 中对应正文与来源映射 | 文件在清单中不代表具体事实已收录 |
| 召回 | 原始词法、向量及合并候选 | 后来手动找到不代表当时已召回 |
| 重排 | 同一候选的前后名次与分数 | 未进入候选不能归因于重排 |
| 适用性/选择 | 被排除的原因、单文档限制、总段数与去重记录 | 有限制不证明本题就是被该限制排除 |

## 9. 阶段 4：补入真实原文的诊断实验

这一步回答“给足资料能否答对”，不证明自动系统已经会找到这些资料。

### 9.1 三种输入的用途

| 臂 | 上下文 | 唯一用途 |
|---|---|---|
| A | 冻结的现行实际上下文 | 基线 |
| B | 按预先审计结果加入最少完整的适用原文，保持与 A 相同字符预算 | 验证同预算下证据组合能否改善 |
| C | 仅当 B 无法在同预算保留全部必要证据时启用；原 A 完整保留并增加原文，明确放宽预算 | 区分预算不足与回答漏用，仅作上限诊断 |

B 的剔除或替换在看答案前完成，仅可移除已确认重复或非必要背景，保留原文内容和来源身份；没有可合理移除内容则记录 B 无法构造，不偷偷多给预算。人工决定该换哪段属于诊断性知识，不能把 B 描述成通用自动策略。C 必须单独报告字数变化及额外资料，不能把 C 的收益称为同预算收益。

所有补入文本必须来自已发布索引中的真实片段，保留标题、限定条件、表头单位或完整步骤关系。不得用 Gold 摘要、解释性答案、人工改写“标准答案”作为原文。注入上下文映射由实验审计文件提供，进入请求的只包含问题与带可追溯来源的资料。

### 9.2 执行与复核

1. 先静态核对 A/B/C 的新增、移除、保留、截断、来源编号及预算，确认没有编号错绑。
2. D 与 C 对照集中的每题 A/B 各 3 次；需 C 臂的题 C 同样 3 次，控制组无需无意义扩容。三臂生成提示与当前生产回答一致，不调用旧证据清单候选。
3. 使用生产生成组件做固定上下文诊断，并明确它暂时绕过检索选段；该结果不能替代真实入口验收。
4. 评测器可读 Gold，回答器不可读。保存完整请求快照（脱敏）、回答、引用、裁判原判、人工复核意见。
5. 复核所有改善、退步、不确定项和随机抽取的两臂一致项。核对真实答案中的事实是否完整、适用，而不是只看自动标签。

### 9.3 诊断门槛

“稳定改善业务组”定义：相同必要事实缺失在 A 至少 2/3 轮出现，B 至少 2/3 轮解决，且 B 三轮没有新增已确认实质性错误。C 结果单列。

- 至少两个不同业务组出现 B 的稳定改善，且共同失败层已确认：允许开发对应自动候选。
- 只有 C 改善：说明同预算尚不能解决，需另立预算/组合假设；不直接解除全部限制，不开发未经证实的同预算方案。
- B/C 都无稳定收益：本轮不继续开发证据补全，转为记录生成漏用或评测争议，阶段 5—8 不适用。
- 只有单一业务组改善：只报告局部结果，不能宣称通用；若有可靠资料结构边界，可提出限定范围方案，但须同样验收。
- 有实质性退步：定位原因，当前方案失败；不得靠删除该题满足门槛。

产出 `diagnostic_contexts.jsonl`、`context_delta.jsonl`、`diagnostic_runs.jsonl`、`diagnostic_review.jsonl`、`diagnostic_gate.md`。

## 10. 阶段 5：只开发被诊断支持的一个通用候选

### 10.1 按故障层选择实现

| 已确认最早失败 | 候选可改内容 | 必须固定 |
|---|---|---|
| 解析/结构关联 | 保留原文结构及来源关系 | 不能把改索引收益说成选段收益；用隔离索引包，不覆盖发布包 |
| 召回漏失 | 增加可追溯结构扩展或检索路径 | 下游重排、选段、生成配置 |
| 重排排走 | 同一候选池的排序机制 | 原始召回候选与分数输入 |
| 选段漏失 | 证据组合、去冗余、必要关系保留 | 召回池、重排及总预算 |
| 实际截断 | 按完整结构单元装配与明确剔除记录 | 同一可用证据与预算 |
| 证据齐全但误用 | 本轮不开发补全候选 | 另写回答使用证据的假设 |

不能同时改上述多层后只给一个 A/B 结果。如果索引确需变化，须明确新 bundle、固定相同源文件、记录变更范围，旧发布包保留，比较中的所有模型与非实验参数一致。

### 10.2 候选接口与边界

建议先放在 `tools/` 的独立候选模块，参数化接收问题、真实候选、结构元数据、来源关系和预算，输出证据选择/扩展结果与原因。具体模块名在阶段 2 定位后确定，不提前建立一套无用途框架。

候选需要满足：

1. 不读取 Gold、case_id、expected_behavior、required_facts、人工正确 chunk 列表或验收题文件。
2. 关联必须有来源证据：章节、续表、引用关系、对象标签或内容明确延续。仅页号相邻、词相似、同部件号不够。
3. 主证据和补充证据都要核对适用性；不能因为一段排第一就豁免。
4. 通用机制可以是同节步骤延续、表格上下文恢复、完整原文单元选择等，但实际选哪一种以诊断结果为准。跨文件补充需要明确支持关系与适用性，不能默认同主题互通。
5. 未知适用性保留为未知及可追踪原因，不直接移为“已确认”，也不按固定报警码/机型白名单决定。
6. 必须记录预算消耗。合并多个片段仍按真实正文计数，不能把多个片段包装成“一段”来逃避约束。若段数口径变化必须作为显式实验变量。
7. 不生成或重写资料内容，不虚构来源 ID；相同正文多来源只去冗余，保留原来源关系。
8. 无触发机会或候选不适用时返回原基线结果；错误降级要记录，不能静默宣称候选成功。
9. 触发、未触发、候选存在但未采用、执行失败分别记录。没有触发的普通题不能作为“机制有效”的证据。

### 10.3 开发检查

优先复用 `ContextBuilder`、来源模型和现行计分器；不复制 `AnswerService`。必要的测试围绕真实风险：表格错行、相邻页对象改变、条件截断、跨文件错机型、步骤完整性、重复来源、预算边界、未触发一致、实际来源编号错绑，以及不含 Gold 的候选输入契约。

运行前审查代码及依赖：任何业务题号特判、答案关键词奖励、专为一份教材设置的文件名分支都判失败。保存逐题静态证据变化，在没有丢掉必要事实或引入错对象后再调用模型。

产出 `candidate_spec.md`、候选代码与测试、`candidate_input_contract.json`、`candidate_context_delta.jsonl`、`candidate_static_gate.md`。

## 11. 阶段 6：开发集回答验证

使用与诊断相同的 D/C 集合、同一当前生产回答提示；A 是基线，B 是自动候选。两臂从相同上游快照出发，只有阶段 5 所声明层发生变化。

每题 A/B 各三次，全部保留。不复用诊断中人工补齐 B 的结果代替自动候选。先检查自动候选实际送达的是不是阶段 4 已证明有用的资料，再检查回答。

门槛：

- 至少两个业务组有自动候选的稳定收益（沿用阶段 4 定义）。
- 必须报告补全触发机会数、实际触发数、有效送达数和真实回答改善数。
- 所有控制组无新增经复核的错对象、错条件、关键事实遗漏、无依据建议或不当拒答/追问。
- 不要求逐字复现答案；要求事实、条件和来源一致。
- 出现任何已确认实质性退步，候选不得进入采用。仍完成已冻结的有限对照并报告；修订只能使用新定位证据，不能逐题加例外。

产出 `development_runs.jsonl`、`development_review.jsonl`、`development_gate.md`。门槛未过，阶段 7 的上线验收不适用，已有控制检查和失败总结仍要完成。

## 12. 阶段 7：新独立验收和固定全集回归

### 12.1 新独立验收

候选冻结后，在 H 上每题 A/B 各三次，通过真实 `AnswerService` 入口运行受控候选开关，保留正常澄清/拒答/复核路径，不直接调用生成器代替验收。

独立通过条件：

1. 存在至少两个不同、未参与开发的业务组出现可复核的同机制稳定收益，且至少跨两份来源资料；若达不到，只能报告范围有限。
2. 触发样本确实触发候选；未触发原因必须解释，不能把“没出错”写成“补全有效”。
3. 无新增已确认实质性错误；强负例没有因相似性被错误补入并使用。
4. 新标签仍 pending，正式验收状态不擅自更改。对业务含义无法确定的项，给出具体原文和争议问题；相关采用结论待确认，其他检查继续。

### 12.2 固定集合真实入口回归

- 48 正式题、30 原回归题、12 旧独立题分别运行 A/B 首轮，不合成一个总体分数。
- 开跑前规定：所有两臂判定不同、不确定、错对象/来源信号或任一臂执行/裁判失败的题，各补两轮；此外固定保护题 019、021、032、035、050、008、015、016 补足三轮。题号仅用于报告与实验抽样，不进入算法。
- 若某题本轮已有完全相同的真实入口请求，可复用并标明；集合覆盖计一次，统计重复时不能重算同一请求。
- 正式集按题和 group 两种口径报告，pending 只给工程观察。不改变分母来美化结果。
- 对新退步逐条核实实际原文、引用和 Gold；裁判错误保留原判并另写复核，不覆盖数据。

回归门槛：正式首轮经同口径复核无净下降，且所有集合无新增已确认实质性退步；首次错误即使复测恢复，也仍作为风险，不用平均数抵消。裁判失败与未执行项单列，关键采用条件依赖缺测时不能判通过。

产出 `holdout_runs.jsonl`、`holdout_review.jsonl`、`regression_runs.jsonl`、`regression_review.jsonl`、`group_summary.json`、`adoption_gate.md`。

## 13. 阶段 8：最小集成与可恢复验证

只有阶段 6、7 门槛通过才执行本阶段。

1. 将通过验证的机制放到实际所属层，生产入口采用显式依赖或配置开关；实验脚本不能反向导入并修改生产类。
2. 初始默认关闭，不顺带修改模型、提示、澄清、拒答、评分、Gold 或发布索引。
3. 若单纯迁移代码，固定上游输入验证“实验候选”与“集成候选”的选段、included_text、来源映射、实际发送请求逐字一致。相同请求可复用已有生成记录，不虚增模型调用。
4. 关闭开关时验证回到基线上下文及请求；异常降级路径要有记录。
5. 执行对应模块的回归测试，以及默认问答入口、数据加载、来源绑定、报告生成检查。
6. 提交拆分建议：只读评测工具；自动候选与测试；集成开关。不得混成一项无法归因的变化。本任务后续执行若没有明确 Git 提交授权，只准备可审查 diff。
7. 如果迁移改变了请求或来源关系，不能视为同一候选；修复后重跑受影响对照。

结束时说明是否已写入工作区、是否已提交、默认开关状态、使用哪个 bundle，以及如何关闭恢复。

## 14. 指标、错误与判分要求

### 14.1 每层都要有分母

| 指标 | 分母 | 解释 |
|---|---|---|
| 必要事实送达率 | 本题经核实必要事实 | 等价支持可计入；非必要引文不纳入 |
| 候选触发率 | 存在该机制机会的业务组 | 不以全题数掩盖无法触发 |
| 自动补全有效率 | 实际触发组 | 检查对象、条件、步骤与预算 |
| 回答成功率 | 相应集合的有效题/轮 | 自动原判和人工复核分栏 |
| 稳定改善组数 | 预先冻结业务组 | 同义改写不重复放大 |
| 新增实质性错误 | 全部被检查题/轮 | 不被其他题收益抵消 |
| 运行完整性 | 计划请求 | 完成、传输失败、裁判失败、复用、缺测分开 |

引文命中率继续保留作检索诊断，但不取代必要事实送达率；两者不能混为一个“正确率”。新评测口径先只读核验，对 A/B 同样应用，原有判分保留，不能只给候选放宽标准。

### 14.2 必须保存的逐题证据

每题保存问题、group、数据状态、请求配置哈希、来源原文与位置、原始候选及排名、选择/排除原因、上下文差异、source_id、真实 included_text、完整请求哈希、实际答案、实际引用、原判、复核结论、最早失败层。

语义适用性不能只写一个 true。应说明某断言由哪段文字、哪一对象和条件支持；尚未确认就写未知。

## 16. 停止条件与最终结论格式

### 必须停止当前候选采用的情况

- 因果定位不清，却需要同时改多个环节才能继续。
- 补齐适用原文没有稳定回答收益。
- 增益只来自额外预算，尚无同预算或经单独验证的新预算机制。
- 只在开发题、同一资料或改写题上有效。
- 新增已确认的错对象、错条件、必要事实丢失或无依据建议。
- 独立题被用于调参后仍被当作独立验收。
- 输入漂移未定位、来源关系无法核实、关键缺测或争议支配采用结论。

停止采用不等于停止交付。完成已冻结且仍有效的有限对照、争议核验和最终报告；不继续随机调提示或无上限重复运行。

最终报告必须逐项回答：

1. **共同原因是什么？** 哪些业务组具有该原因，哪些没有，最早失败层有什么直接证据？
2. **改了哪一层？** 诊断人工注入与自动实现分别是什么，实际改变了哪些输入？
3. **哪些题变好或变坏？** 首轮、三轮稳定性、按业务组、真实引用和复核理由分别列出。
4. **是否有泛化证据？** 新独立样本是否真的未用于调试，触发机会和来源覆盖是什么？
5. **是否值得采用？** 使用“建议采用”“限定范围采用”“暂不采用”之一；pending 业务标注未确认时注明采用仍待确认。
6. **落地状态是什么？** 代码保留范围、是否提交、默认开关、索引状态、恢复办法。

本轮完成的标准是得到以上可复核结论。没有收益也是有效结论，但必须能说明为什么；不能用“继续尝试”代替阶段 9 的最终判定。
