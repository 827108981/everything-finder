## 状态定义

每个需求只能处于以下状态之一：

1. `未实现`
2. `部分实现`
3. `代码完成`
4. `源码验收`
5. `冻结版验收`
6. `真实语料验收`

状态只能按顺序前进。缺少前一级证据时不得跳级。

“失败测试证据”是进入开发的必要条件；没有先在修改前失败的行为测试，不得将该编号更新为“代码完成”。

## 总体门禁

- 任一编号没有达到其规定的最终状态，不得使用“完全完成”。
- 任一 P0 发布门禁没有达到“真实语料验收”，不得进入最终发行打包。
- 开发过程允许生成临时冻结版用于专项验证，但不得命名为最终发行版。
- 修改前性能基线保留同设备、同语料、同设置、同缓存条件下 3 次中位数；按 2026-08-01 最新决策，修改后候选只执行 1 次完整冷索引，以该次结果判定当前候选，不再补跑两次，也不得把单次结果描述为三次中位数。
- 视频只排除，不解析正文。
- 不允许固定单文件总耗时上限。
- 不允许通过跳过文件、减少 OCR 范围或沿用旧正文换取性能。
