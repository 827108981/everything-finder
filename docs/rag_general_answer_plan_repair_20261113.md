# 答案计划核验的通用修复（第二阶段）

第一版全量固定 Context 实验已经观察到大量错误拒答。日志中主要原因是 `condition_not_bound_to_quote` 和 `scope_not_bound_to_quote`：实现错误地要求模型对条件和范围的语义概括也必须是所摘短句的逐字子串。它把“原文引文必须真实”和“答案描述必须照抄原文”混为一谈。

例子不限于任何题号：原文“如果至少一次结果为阳性”可支持问题给定“一阳一阴”的条件分支；概括条件不应因改写就被字符串门禁删掉。型号/对象也可能在同一来源的标题或表头，而不在数值短句中，仍需语义核对绑定关系。

修复边界：

1. 原文 quote 必须实际存在于所引用 Context 正文，保持硬校验。
2. 数字、标识符、明确型号冲突和确认性断言继续保留硬校验；不修改 Gold 或裁判。
3. 范围与条件概括不再用逐字相等证明真假。将未字面匹配的部分明确交给独立语义审核；审核必须逐条覆盖所有主张及其元数据，失败时不发布。
4. 第二步只渲染已核验计划，不自由补写事实。
5. 第一版所有完成结果保留；第二版使用同一冻结 B Context，单独输出，不覆盖失败。完成全量重评，再做预定 8 题、每题 3 次稳定性实验。

该修复改变的是来源绑定验证的职责，不是放宽业务评分。仍不能把语义审核模型视为完备证明；需要报告漏答、无依据主张与运行错误。
