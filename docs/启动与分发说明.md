# 本地全文搜索工具：分发与启动说明

## 分发方式

1. 分发 `本地多格式全文搜索工具` 整个目录，目录内的 EXE 和 `_internal` 必须保持在同一层级。
2. 接收方先将整个目录解压到本机 SSD 的普通目录，再双击 `本地多格式全文搜索工具.exe`。
3. 不要只复制 EXE；不要从压缩包预览、网络共享、网盘同步目录或 U 盘直接运行。
4. 若 ZIP 文件属性中有“解除锁定”，先解除锁定后再解压运行。
5. 收到目录后，可用“发行资料”目录内的 `SHA256SUMS.txt` 核对文件完整性。

发行目录根部只保留 EXE、`_internal`、PDF 使用说明和“发行资料”目录。构建信息、SHA-256 清单、验证结果和开发验证截图统一放在“发行资料”内，不能散落在 EXE 同级目录。

## 启动提示与诊断

- 程序会在 Python 入口后立即记录启动阶段。超过 15 秒仍未显示窗口时，会显示当前阶段和诊断日志位置。
- Python 入口建立日志后会启用 `faulthandler`，并为每个启动阶段记录应用版本、EXE 路径、工作目录、冻结状态、Windows 版本、设置路径、数据库路径、耗时和最后状态。
- 启动失败时会显示原生错误提示，并区分程序文件缺失、用户数据目录不可写、数据库锁定/损坏/迁移失败、Qt/DLL 加载失败和未知异常。请将实际提示中的日志路径及日志文件提供给支持人员。
- 默认日志位于 `%LOCALAPPDATA%\LocalFullTextSearch\logs\startup.log`；该目录不可写时自动回退到 `%TEMP%\LocalFullTextSearch\startup.log`，错误框会显示实际位置。
- 若该日志不存在，说明程序可能在 Python 入口前被 Defender、企业 EDR、SmartScreen、DLL 加载或权限策略阻止。请检查 Windows 安全中心“保护历史记录”、企业安全软件日志和事件查看器。
- 首次使用没有旧索引数据库时，正常本机 SSD 环境不应出现数分钟无窗口等待；优先检查完整目录是否被拆分、是否在网络/同步目录运行，以及安全软件是否正在扫描。
- 从旧版数据库升级时，程序先创建 `search_index.schema-v<旧版本>.backup.db`，再执行字段和索引迁移。迁移失败时不要删除原数据库或备份，应保留日志并联系支持人员。

## 索引模式

- `更新全部` 使用普通配置。
- `性能模式更新` 只在用户点击一次后执行本次索引。程序会探测 CPU、可用内存和索引盘类型，为本次任务选择并发与内存预算；完成、取消或重启后自动恢复普通配置。
- 首次全量索引必须处理完全部可解析文件后才开放搜索；视频不参与解析，并单独计入“排除视频”。
- 点击“暂停”后先进入“正在暂停…”。只有活动任务到达页、OCR 区域或其他安全检查点，界面确认“已暂停”后，普通/性能模式切换才会开放；点击“继续”时已完成文件不会重复解析。
- 预计剩余时间在样本不足时显示“正在估算…”，稳定后只显示一个约数。暂停期间不继续变化，继续后重新估算。
- 程序不会根据空闲时间、定时器、开机事件、键鼠活动或文件变化自动启动性能模式索引。
- ZIP 内的可解析成员会作为独立来源调度；目录文件与 ZIP 成员只有在完整 SHA-256 一致、解析器版本一致时才复用解析结果。
- 长文件使用“无有效进展超时”，不限制总解析时长。页码、工作表、ZIP 成员或 OCR 区域等游标持续前进时可继续运行；同一阶段和游标长期不变时才会回收对应进程并从检查点重试。

## 支持信息

反馈启动或索引问题时，请一并提供：`BUILD-INFO.txt`、`SHA256SUMS.txt` 校验结果、`startup.log`、失败文件列表，以及问题文件所在盘符是本地 SSD、机械盘、网络盘还是可移动盘。
