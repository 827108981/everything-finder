# 本地多格式全文搜索工具阶段一二合并开发需求

## 1. 背景

当前版本已经具备基础桌面界面、目录索引、文本/PDF/DOCX/XLSX/PPTX 基础解析、搜索和 EXE 打包能力，但从实际导出的失败清单看，仍存在以下问题：

- 部分 `.xlsx` 文件因为空单元格触发解析失败。
- `.jpg` 图片未启用 OCR 时被归为“不支持”，用户体验不清晰。
- `.doc`、`.ppt` 等老版 Office 文件暂未解析。
- `.zip` 压缩包暂未递归索引。
- 失败文件、未支持文件、跳过文件混在同一类结果中，不利于排查。
- 当前代码注释偏少，后续维护和扩展成本较高。

本需求将原先“第一阶段问题修复”和“第二阶段格式增强”合并为一个新的开发阶段，目标是明显提高实际资料目录的可索引覆盖率和失败可诊断性。

## 2. 本阶段目标

本阶段目标不是重写整个项目，而是在现有可运行版本基础上完成一次“解析覆盖率增强 + 稳定性增强 + 可维护性增强”。

必须达到：

1. 修复当前真实失败的 `.xlsx` 解析问题。
2. 支持图片 OCR 索引，覆盖 `.jpg`、`.jpeg`、`.png`、`.bmp`、`.tif`、`.tiff`。
3. 支持扫描 PDF OCR。
4. 支持老版 Office 文件 `.doc`、`.xls`、`.ppt` 的可用解析方案。
5. 支持 `.zip` 压缩包内文件递归索引。
6. `.mp4` 可暂不做内容解析，但必须至少做到“不当成错误文件”；可只索引文件名/路径或按配置跳过。
7. 区分“真实失败”“暂不支持”“配置未启用”“主动跳过”四类状态。
8. OCR 版作为团队主要交付版本，OCR 默认启用。
9. 增加必要代码注释，特别是解析器、索引、OCR、压缩包和错误处理逻辑。
10. 重新打包 OCR 版 EXE，并完成端到端验证。

## 3. 文件格式支持范围

### 3.1 必须稳定支持

- `.txt`
- `.log`
- `.csv`
- `.md`
- `.json`
- `.xml`
- `.ini`
- `.pdf`
- `.docx`
- `.xlsx`
- `.xlsm`
- `.pptx`

### 3.2 本阶段新增必须支持

- `.jpg`
- `.jpeg`
- `.png`
- `.bmp`
- `.tif`
- `.tiff`
- `.doc`
- `.xls`
- `.ppt`
- `.zip`

### 3.3 可暂不解析正文但不得作为失败

- `.mp4`

处理策略：

- 默认只索引文件名和路径。
- 在失败清单中不得显示为 `failed`。
- 可在状态中显示为 `skipped` 或 `metadata_only`。

## 4. Excel 解析增强需求

### 4.1 必须修复

当前错误：

```text
'EmptyCell' object has no attribute 'row'
```

修复要求：

- 在访问 `cell.row`、`cell.column`、`cell.coordinate` 之前必须判断是否为空单元格。
- 对 `openpyxl.cell.read_only.EmptyCell` 做兼容处理。
- 不能因为某一行存在空单元格导致整个文件失败。
- 保留行号、Sheet 名和命中单元格坐标。

### 4.2 Excel 解析范围

至少提取：

- 工作表名称。
- 单元格坐标。
- 单元格值。
- 公式文本。
- 批注文本，能读取时必须读取。
- 合并单元格信息，能读取时记录到 `extra`。

### 4.3 大文件要求

- 必须继续使用只读模式。
- 不允许一次性将整个工作簿加载成普通列表。
- 每行作为一个内容块。
- 单个 sheet 失败不得中断整个工作簿，允许标记为部分成功。

## 5. 图片 OCR 和扫描 PDF OCR

### 5.1 图片 OCR

必须支持：

- `.jpg`
- `.jpeg`
- `.png`
- `.bmp`
- `.tif`
- `.tiff`

OCR 结果应写入独立内容块：

- `source_type = "ocr"`
- 保存 OCR 原文。
- 保存平均置信度。
- 保存 OCR 引擎名称和版本。
- 保存 OCR 缓存 key。

### 5.2 扫描 PDF OCR

PDF 页面满足以下条件时，应进入 OCR 候选：

- 原生可提取文本很少。
- 页面包含图片。
- 用户启用了扫描 PDF OCR。

要求：

- 默认不对所有 PDF 强制 OCR。
- OCR 结果必须按页保存。
- PDF 原生文本和 OCR 文本分开记录。

### 5.3 OCR 默认策略

本工具面向团队资料检索使用，OCR 是核心能力，不应默认关闭。

默认策略：

- 默认启用 OCR。
- 默认启用图片 OCR。
- 默认启用扫描 PDF OCR。
- 默认不启用 Office 内嵌图片 OCR，作为后续增强或高级选项。
- 默认 OCR 线程数为 1。
- 普通文档索引优先完成，OCR 任务可在后台继续运行。
- 用户可以暂停、继续、取消 OCR 队列。

界面上不应把 OCR 设计成“隐藏高级功能”，而应提供两个清晰索引模式：

```text
完整索引（推荐，默认）
- 文件名/路径
- 普通文档正文
- 图片 OCR
- 扫描 PDF OCR

快速索引
- 文件名/路径
- 普通文档正文
- 不执行 OCR
```

### 5.4 OCR 打包策略

需要提供两种交付模式：

1. OCR 版：主要交付版本，带 OCR 依赖和模型，支持图片和扫描 PDF 正文检索。
2. 标准版：备选版本，不带 OCR 模型，体积小，图片只索引文件名/路径。

团队交付必须优先提供 OCR 版。

如果 OCR 未安装或未启用：

- 图片不得标为 `failed`。
- 状态应为 `ocr_disabled` 或 `metadata_only`。
- 用户界面需要给出明确说明。
- OCR 版验收时，图片和扫描 PDF 必须实际 OCR 命中，不能只验证文件名命中。

## 6. 老版 Office 文件支持

### 6.1 支持范围

- `.doc`
- `.xls`
- `.ppt`

### 6.2 优先实现方案

优先使用 Microsoft Office COM 转换：

- `.doc` 转 `.docx`
- `.xls` 转 `.xlsx`
- `.ppt` 转 `.pptx`

转换后复用现有解析器。

### 6.3 备选方案

如果未安装 Microsoft Office：

- 可尝试 LibreOffice headless 转换。
- 如果两者都不可用，标记为 `converter_missing`，不得标记为 `failed`。

### 6.4 安全要求

- 转换文件必须放入应用临时目录。
- 不得修改用户原文件。
- 转换失败要记录原因。
- 临时文件要可清理。

## 7. ZIP 压缩包索引

### 7.1 支持范围

必须支持 `.zip`。

### 7.2 解析策略

- 读取 zip 内文件列表。
- 对支持格式的内部文件进行递归解析。
- 内容块定位必须显示压缩包路径和内部路径。

示例：

```text
资料包.zip > 子目录/说明.docx > 正文第 5 段
```

### 7.3 安全限制

必须防止压缩包风险：

- 最大压缩包大小限制。
- 最大解压后总大小限制。
- 最大内部文件数量限制。
- 最大递归层级限制。
- 跳过带密码的 zip。
- 防止路径穿越，例如 `../evil.txt`。

### 7.4 失败处理

- 单个内部文件失败不得导致整个 zip 失败。
- zip 可标记为 `partial_success`。
- 内部失败文件需要能在失败清单中看到。

## 8. 失败状态重构

必须区分以下状态：

```text
success
partial_success
failed
unsupported
skipped
metadata_only
ocr_disabled
converter_missing
password_protected
deleted
```

### 8.1 真实失败

定义：原本应该支持解析，但因为解析器 bug、文件损坏、权限、占用等原因失败。

示例：

- `.xlsx` 解析异常。
- `.docx` 文件损坏。
- PDF 页面读取异常。

### 8.2 暂不支持

定义：格式不在当前支持列表中。

### 8.3 配置未启用

示例：

- 图片 OCR 关闭。
- 扫描 PDF OCR 关闭。

### 8.4 主动跳过

示例：

- `.mp4` 按配置只索引文件名。
- 超过大小限制的 zip。

## 9. 失败文件窗口和导出增强

失败文件窗口必须支持：

- 按状态筛选。

- 按错误码筛选。
- 查看失败详情。
- 导出 CSV。
- 导出汇总 CSV。

导出字段至少包含：

- 扩展名。
- 状态。
- 错误码。

## 10. 搜索和索引要求

### 10.1 索引

- 所有支持格式必须至少建立文件名和路径索引。
- 正文解析成功时建立正文内容块索引。
- OCR 成功时建立 OCR 内容块索引。
- 部分成功时不能丢弃已成功内容。

### 10.2 搜索

- 继续保持强匹配。
- 普通文本命中和 OCR 命中要区分显示。
- metadata-only 文件只能命中文件名/路径。

## 11. 代码注释要求

开发本阶段时必须增加注释，但不能写无意义注释。

### 11.1 必须加注释的位置

- 每个解析器文件顶部说明解析策略和限制。
- Excel 空单元格兼容逻辑。
- 老版 Office 转换逻辑。
- ZIP 安全检查逻辑。
- OCR 初始化和缓存逻辑。
- 失败状态分类逻辑。
- 数据库事务边界。
- 后台任务取消/暂停检查点。

### 11.2 注释风格

要求：

- 注释必须解释“为什么这样处理”，不是重复代码做了什么。
- 复杂函数必须有 docstring。
- 关键分支必须说明边界场景。
- TODO 必须说明触发条件和后续方案。

不允许：

```python
# 获取值
value = cell.value
```

推荐：

```python
# read_only 模式下 openpyxl 会为稀疏区域返回 EmptyCell。
# EmptyCell 没有 row/coordinate 属性，所以必须先跳过空值，再访问定位字段。
if isinstance(cell, EmptyCell) or cell.value is None:
    continue
```

## 14. 验收标准

使用当前用户导出的失败清单对应目录重新索引后：

- 19 个 `.xlsx` 不应再因为 `EmptyCell` 失败。
- `.jpg` 不应再显示为“不支持的文件格式”；OCR 版中必须能 OCR 正文命中。

## 15. UI 设计与前端开发合并要求

本阶段必须同步完成 UI 升级。UI 目标是打造一款高级、简洁、专业、克制、易用的 Windows 本地全文搜索工具界面。

核心体验：

```text
像 Everything 一样直接
像 Windows 11 一样简洁
像 Notion 一样清晰
同时具备专业文档定位能力
```

UI 必须围绕以下目标展开：

- 快速搜索。
- 清晰结果。
- 准确定位。
- 低学习成本。
- 长时间办公使用不疲劳。

## 16. UI 视觉定位

整体风格：

- 高级。
- 简洁。
- 专业。
- 克制。
- 现代。
- 信息层级清晰。

推荐视觉方向：

## 18. 主窗口结构

主窗口采用三栏布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 应用标题                         索引状态   主题   设置       │
├──────────────┬──────────────────────────────┬────────────────┤
│ 左侧导航栏    │ 中央搜索与结果区              │ 右侧预览区      │
└──────────────┴──────────────────────────────┴────────────────┘
```

三栏职责：

- 左侧：文件类型、搜索范围、索引管理入口。
- 中间：搜索框、筛选条件、搜索结果。
- 右侧：当前选中结果的预览与定位信息。

右侧预览区必须可折叠。窗口较小时自动关闭右侧预览区，只保留中央结果区。

窗口规格：

- 默认窗口尺寸：1440×900。
- 最小窗口尺寸：1100×700。
- 左侧导航栏宽度：210～230 px。
- 右侧预览区宽度：360～520 px。
- 顶部栏高度：56～64 px。
- 搜索框高度：48～52 px。

不得大量使用固定坐标。

搜索框内包含：

- 搜索图标。
- 输入区域。
- 清空按钮。
- 搜索历史按钮。
- 可选搜索按钮。

交互规则：

- Enter 立即搜索。
- 停止输入 300 ms 后自动搜索。
- 新搜索开始后取消旧搜索。
- Esc 清空当前搜索。
- Ctrl+F 聚焦搜索框。
- 搜索中不锁死输入框。
- 搜索失败不得弹出阻塞式弹窗，应使用页面内提示或 Toast。

快速筛选区只显示常用条件：

```text
[完全包含 ▼] [全部范围 ▼] [全部格式 ▼] [更多筛选]
```

搜索模式：

- 完全包含。
- 完整短语。
- 全部关键词。
- 任意关键词。
- 正则表达式。

更多筛选默认收起，展开后包含：

- 修改时间。
- 文件大小。
- 搜索文件名。
- 搜索路径。
- 搜索正文。
- 包含 OCR 结果。
- 只看精确结果。
- 只看 OCR 疑似结果。
- 大小写敏感。
- 排除文件夹。
- 排除文件格式。

## 22. 搜索结果区要求

搜索结果不使用传统 Excel 式表格，应采用纵向结果列表或自定义卡片列表。

每条结果高度建议：

```text
95～125 px
```

每条结果至少显示：

- 文件类型图标。
- 文件名。
- 命中次数。
- 文件格式。
- 命中位置。
- 命中上下文。
- 文件路径。
- 修改时间。
- OCR 标签。
- 疑似匹配标签。

搜索关键词使用浅黄色背景高亮，不使用红色作为普通关键词高亮。

PDF 结果示例：

```text
PDF · 第18页
……适用于 BS-2800M2 全自动生化分析仪的维护和校准……
```

Excel 结果示例：

```text
产品配置 · 单元格 D27
设备型号：BS-2800M2
```

图片 OCR 结果示例：

```text
图片文字 · 置信度 94%
报警信息：反应盘温度异常
```

OCR 结果必须添加 `OCR` 标签。易混淆字符兼容命中必须添加 `疑似匹配` 标签，不得把 OCR 疑似结果伪装成精确结果。

结果区顶部显示：

```text
找到 328 条结果 · 用时 0.12 秒
```

右侧可显示排序方式、列表密度、是否显示预览、导出结果。

排序方式：

- 相关度。
- 修改时间。
- 文件名。
- 命中次数。
- 文件大小。

默认按相关度排序。

## 23. 分页、懒加载和性能

必须避免一次性加载全部结果。

推荐：

- 首次加载 50 条。
- 向下滚动自动加载下一批。
- 每批 50 条。
- 最多显示前 1000 条。
- 超过 1000 条时提示缩小范围。
- 支持手动“继续加载”。
- 支持结果虚拟化。
- 不一次性创建大量 QWidget。

结果列表必须在十万级候选结果下保持界面可操作。

以下任务不得阻塞主线程：

- 文件扫描。
- 文件解析。
- OCR。
- 建立索引。
- 全文搜索。
- 结果排序。
- PDF 页面预览。
- 图片缩略图加载。
- 文件哈希计算。
- 批量删除索引。

界面性能要求：

- 主窗口启动后 2 秒内可操作。
- 搜索输入无明显卡顿。
- 结果首屏优先显示。
- 单批结果加载不超过 100 条。
- 滚动列表保持流畅。
- 长任务必须提供取消或暂停能力。
- 后台异常不能导致程序崩溃。

## 24. 右侧预览面板

用户单击搜索结果后，右侧显示预览面板。

预览面板顶部显示：

- 文件名。
- 文件类型。
- 文件大小。
- 修改时间。
- 关闭按钮。

底部操作：

- 打开文件。
- 打开所在文件夹。
- 复制路径。
- 查看全部命中位置。

不同格式预览逻辑：

- PDF：显示命中页缩略图、页码、命中文本、上一处/下一处命中。
- Word：显示命中段落、前后文、表格位置，不做编辑。
- Excel：显示工作表名称、单元格地址、附近 5 行 × 5 列，高亮命中单元格，显示公式和显示值。
- PowerPoint：显示幻灯片缩略图、页码、命中文字和备注。
- 图片：显示原图；保存 OCR 坐标时框出命中区域；显示 OCR 置信度；支持缩放。
- TXT/LOG/CSV：显示命中行和上下文，使用等宽字体并显示行号。

右侧预览区必须可关闭和恢复。

## 25. 首次启动和索引模式

首次启动不得直接显示空白搜索结果页，应显示欢迎页：

```text
本地全文搜索

快速搜索 PDF、Word、Excel、PPT、文本文件和图片中的内容

[选择要搜索的文件夹]

所有文件仅在本机处理，不会上传
```

选择文件夹后显示索引方式：

```text
索引方式

● 完整索引（推荐）
  搜索 Office、文本、文本型 PDF、图片和扫描 PDF 中的文字

○ 快速索引
  搜索 Office、文本和文本型 PDF，不执行 OCR

[开始建立索引]
```

由于本工具交付团队 OCR 版，默认必须选择“完整索引（推荐）”。首次启动不得要求用户配置 OCR 线程数、数据库参数等技术选项。

## 26. 索引管理和任务面板

索引管理页使用简洁范围卡片，不使用复杂数据表格。

范围卡片显示：

- 根目录路径。
- 文件数量。
- 最后更新时间。
- 格式统计。
- 当前状态。
- 更新、暂停、更多菜单。

更多菜单包含：

- 更新索引。
- 暂停监控。
- 设置排除目录。
- 重新建立索引。
- 打开文件夹。
- 删除索引范围。

危险操作必须二次确认。

点击顶部索引状态展开任务面板：

```text
普通文档       12,580 / 12,580   已完成
文本 PDF        2,310 / 2,310    已完成
图片 OCR        1,268 / 8,452    处理中
扫描 PDF          256 / 1,203    等待中

[暂停] [继续] [查看失败文件]
```

要求：

- 普通文档和 OCR 分开显示。
- 显示当前处理文件。
- 显示成功数、失败数。
- 支持暂停、继续。
- 支持查看失败文件。
- 程序关闭后再次启动可以断点继续。
- 不使用阻塞式全屏进度弹窗。

## 27. 失败文件页面 UI

失败文件页面用于查看无法解析的文件。

每条失败记录显示：

- 文件名。
- 文件路径。
- 文件格式。
- 失败原因。
- 失败时间。
- 重试按钮。
- 打开所在文件夹按钮。

支持筛选：

- 失败原因。

- 文件扩展名。

禁止把技术堆栈直接暴露给普通用户；详细堆栈写入日志文件。

## 28. 设置页面 UI

设置页只保留普通用户真正需要的选项。

常规：

- 开机启动。
- 关闭后最小化到托盘。
- 主题。
- 默认打开方式。
- 是否保存搜索历史。

搜索：

- 默认搜索模式。
- 默认搜索范围。
- 默认包含 OCR 结果。
- 默认每批加载数量。
- 是否启用自动搜索。
- 自动搜索延迟。

索引：

- 自动监控文件变化。
- OCR 线程数。
- 最大索引文件大小。
- 忽略隐藏文件。
- 排除扩展名。
- 索引数据库位置。

高级：

- 清理缓存。
- 重建全部索引。
- 导出日志。
- 打开数据库目录。

以下技术参数不应暴露给普通用户：

- SQLite page size。

- FTS tokenizer。
- OCR batch size。
- 数据库 vacuum 策略。

## 29. 空状态、提示和弹窗规范

空状态必须友好清晰：

- 未输入关键词：提示“输入关键词开始搜索”。
- 无搜索结果：给出检查范围、切换关键词模式、开启 OCR 疑似结果等建议。
- 索引未完成：提示当前结果可能不完整，OCR 完成后会自动补充。
- 索引范围为空：提示添加文件夹。
- 文件已删除：搜索结果变灰，并提供从索引中移除。

尽量减少弹窗。

适合弹窗：

- 删除索引范围。
- 重建全部索引。
- 清空缓存。
- 选择索引模式。
- 严重错误。
- 文件夹权限申请。

不适合弹窗：

- 搜索无结果。
- 搜索词太短。
- 索引仍在进行。
- 普通文件解析失败。
- OCR 置信度过低。
- 文件已删除。

普通状态使用顶部提示、页面内提示或 Toast。

Toast 用于：

- 已复制文件路径。
- 已开始更新索引。
- 已暂停 OCR。
- 已删除索引范围。
- 文件已加入重新索引队列。
- 设置已保存。

Toast 显示 2～4 秒，不阻塞用户操作。

## 30. 按钮、图标、快捷键和右键菜单

按钮规范：

- 主按钮：蓝底白字，仅用于主要操作。
- 次级按钮：白底灰边。
- 文字按钮：无背景。
- 危险按钮：红色文字或红色边框，必须二次确认。
- 同一页面不能出现多个同等突出的主按钮。

图标规范：

- 使用统一线性图标体系。
- 禁止不同图标库混用导致线条粗细不一致。
- Office 格式图标可以弱化色区分，但不能过于鲜艳。

快捷键：

| 快捷键 | 功能 |
|---|---|
| Ctrl+F | 聚焦搜索框 |
| Enter | 立即搜索 |
| Esc | 清空搜索或关闭预览 |
| Ctrl+O | 打开选中文件 |
| Ctrl+Shift+O | 打开所在文件夹 |
| Ctrl+C | 复制选中路径 |
| Ctrl+R | 更新当前索引范围 |
| F5 | 刷新搜索结果 |
| ↑ / ↓ | 切换搜索结果 |
| Alt+← | 返回上一页面 |

搜索结果右键菜单：

- 打开文件。
- 打开所在文件夹。
- 复制文件路径。
- 复制命中文本。
- 查看全部命中位置。
- 从结果中隐藏。
- 重新索引该文件。
- 从索引中移除。

索引范围右键菜单：

- 更新索引。
- 暂停监控。
- 设置排除目录。
- 打开文件夹。
- 重新建立索引。
- 删除索引范围。

菜单项目必须简洁，最多 8 项。

## 33. UI 验收标准

必须满足：

1. 程序启动后搜索框是最明显的视觉焦点。
2. 首次使用无需阅读说明即可添加文件夹。
3. 搜索结果能够清晰区分文件名、位置、上下文和路径。
4. OCR 结果和精确结果有明显但克制的标签区分。
5. 结果超过 1000 条时界面不假死。
6. 结果列表滚动流畅。
7. 搜索过程中仍可继续输入。
8. 右侧预览可以关闭。
9. 1366×768 分辨率下控件不被裁切。
10. Windows 125% 缩放下界面正常。
11. 弹窗不会超出屏幕。
12. 主界面不出现无意义大面积空白。
13. 不使用密集传统表格作为主搜索结果。
14. 不出现多个高饱和主按钮。
15. 所有图标风格统一。
16. 路径过长时正常省略。
17. 关键词高亮不会破坏文本可读性。
18. 搜索无结果时有友好的空状态。
19. 索引未完成时有明确提示。
20. 所有长任务都在后台运行。
