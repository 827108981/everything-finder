# 条件排序与同文件限额的独立验证（2026-11-01）

结论：在本批50题中，只取消对象字段的排序加减分，比全面取消条件排序更合适；两者获得相同正确证据收益，前者没有新增指定干扰片段。放宽同文件上限能修复023和补全030，但也引入场景不符的022分支；不宜仅凭这些题统一取消配额。

## 实验控制与校验

- 五组各50题，共250次完整检索流程，无运行错误、无LLM/API调用。基于当前AI包`g000033-71ec3c52f3`及同一reviewed Gold v3。
- 共用纯模型排序，入口之前的关键词、向量、融合、去重和重排五阶段候选及正文逐条一致；基准与上一轮纯模型完整检索结果完全一致。
- 每组复用1000对前轮已重新推理验证的原始模型分，缓存匹配原问题、chunk ID、正文SHA256及模型修订。不是250次重新模型推理，缓存运行耗时不能代表生产延迟。
- 所有组的条件判断、硬冲突判断、关键条件确认门禁和澄清策略保持一致；最终所选证据中硬冲突判定数均为0。只改变排序或最终证据选择处的文档配额。
- 总条数8、上下文预算12000字不变。原应用代码、默认设置和Gold没有因本次实验改动。
- 五组run.json设置相同；实验注入参数另存各组downstream_variant.json，不能只看run.json判断实验差异。实验实现位于tools/verify_rerank_pipeline.py。

## 条件排序：具体改进与风险

- 全面取消条件排序：020证据覆盖由1/2变2/2；021由1/3变2/3；027、037由无正确证据变为命中。没有正向覆盖退步。
- 但022新增“个别项目定标失败”的分支，而问题是几乎全部项目低于1000；028新增已怀疑板卡故障时的通用排查，不能据整体偏低指定板卡。两条都被原判定保留为unknown背景，并非硬冲突，所以仅保留硬冲突门禁还不能防止这些片段排前。
- 更窄的对象中性排序：原有对象判断、冲突过滤仍保存，只在计算排序优先级时不使用OBJECT字段的匹配数/未知数/加减分；阶段、方向、机型等其他条件仍照常参与排序。
- 对象中性排序获得同样的4题正向收益，指定干扰片段仍为10次，没有新增022/028片段。说明本批题的条件排序损失可以通过更窄的字段调整修复，不需要全面取消场景排序。
- 这是针对已分析题目形成的探索性方案，未用独立留出集验证；不能证明所有业务对象都不应参与排序。

## 同文件限额：确实挡住了答案，也有保留多样性的作用

- 只将最终同文件上限从3条改为8条：023由无正确证据变为命中，030由1/2补全为2/2；没有正向覆盖退步。
- 但022的个别项目分支也新增进入。023的指定DCF片段也增加，不过它与正确CSDB行处于同一表、同一索引块，两种证据的映射ID直接重叠：`774fc8ea8748b3f34ca3f1ab8713e3d2240fac66866b529c056c775666c044a9`。
- 因此，023“正向命中”和“强负例计数增加”同时发生是当前块级匹配粒度的结果，不能算成两次独立召回，也不能用它断言检索退步。需要回答使用正确报警行，不能挪用DCF的重启方案。Gold与匹配算法本轮未改动。
- 拒答题045在quota8组少带入一条钠电极物料行，但无生成验证，不能声称拒答改善。

## 交互诊断与边界

全面取消条件排序并放宽限额后，44/46题命中、平均覆盖91.3%，达到这一固定候选集内已定位的证据上限；剩余019、050的正确证据没有进入重排入口。这不证明组合方案适合上线：022/028跨场景背景仍进入，DCF行也随CSDB同表进入，且缺少答案阶段验证。

这一组合只用于理解两个因素的相互作用，不等于已测试“对象中性排序＋放宽限额”的组合，不能把两者混为一谈。

本轮未发现各组之间本地可用资料/不足/澄清状态的切换；仍不能据此认定Gold clarify题真实澄清正确。034、045拒答题仍有上下文，生成是否拒答尚未测量。

## 建议

1. 条件检查优先推进“对象字段不主导排序”的小范围改动验证，保留其他业务条件排序及所有硬门禁；不要直接全面关闭条件检查。
2. 同文档数量限制应从固定上限改进为按证据是否补充新步骤/条件/表格行来选择，但这只是下一项待验证方向。本轮仅验证3与8的差异，未验证自适应策略，也未证明8是合适的生产参数。
3. 在真实回答及独立题集验证前，本轮只提供检索证据层面的结论。特别检查022是否混用个别与全部项目分支、023是否误用DCF行、028是否直接指定板卡故障。
