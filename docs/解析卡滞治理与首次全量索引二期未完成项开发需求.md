## 0. 当前结论

当前 `1.3.0` 已经具备以下基础能力，后续开发必须保留：

- 普通解析、PDF、Office、ZIP、OCR 等主要解析车道使用可回收进程池；
- watchdog 按语义进展判断无进展，不再使用单文件总耗时上限；
- 重复心跳、重复阶段和相同游标不应刷新无进展时间；
- 同一卡点重复发生后停止盲目扩大等待时间；
- 第一次完整索引期间通过完整性状态阻止搜索；
- schema v6、任务尝试记录、检查点和进度字段已经存在；
- PDF 已有 `150 DPI` 预检、`200 DPI` 区域识别和低质量区域 `300 DPI` 升级；
- 图片 OCR 已有“960 检测、原图区域识别、低质量时原图分块”；
- OCR 识别已能在单张图内部按区域批量调用；
- 索引状态区已有两行布局；
- ETA 已改为单值显示，样本不足时显示“正在估算…”；
- 已有 `pause_requested → pausing → paused → resuming` 基础状态；
- 真正进入 `paused` 后，界面允许普通模式与性能模式切换；
- “拔掉 3 个传感器”当前能够命中正确 PDF；
- 当前源码自动化测试为 `142 passed`；
- 当前冻结版完成了 8 项基础命令验证。

但原始二期需求不能判定为完全实现，主要原因如下：

1. 文件发现、目录枚举、`stat`、完整哈希、ZIP manifest 和部分成员预抽取仍存在同步阻塞边界。
2. 缺少覆盖全执行链的“真实假死—回收—重建—后续文件继续”端到端验证。
3. PDF 仍以整文件为主要调度单位，页级任务多数只是由进度回调映射出的数据库记录。
4. 图片 OCR 与 PDF OCR 仍使用不同进程池，没有统一 OCR 常驻调度车道。
5. OCR 低质量回退仍先生成固定完整网格，再保守剔除空白块，不是未解决区域驱动的自适应分块 2.0。
6. OCR 微批只覆盖单图内部，未形成跨分块、跨页面、跨文件的统一微批。
7. 页图、PDF 嵌入图片、归一化图像和 crop 的跨来源精确复用没有完整实现。
8. 未完成 Paddle/MKL-DNN/ONNX Runtime/OpenVINO 的真实语料 A/B。
9. 当前资源监控主要记录峰值 RSS，没有根据运行时 CPU、RSS、磁盘和队列压力动态调节并发。
10. UI、ETA、安全暂停和模式切换已有基础实现，但缺少缩放矩阵、ETA 回放、资源空闲和真实长任务恢复验证。
11. 没有完成指定真实目录修改前后三次完整冷索引。
12. 当前性能证据没有达到二期目标：液路图 PDF 只降低约 7.20%，单张大图只降低约 4.47%，且不是三次中位数。
13. 当前发行包来自 `working-tree-with-changes`，没有可精确复现该发行包内容的最终 Git 提交。
14. 2026-07-30 同事现场首次索引产生 186 条“未成功索引”记录；当前完成判定把其中 158 条正常终态 `metadata_only` 也计为阻断，且没有人工排除失败文件、撤销排除和文件变化后自动重试的范围收口能力。

## 1. 强制开发规则

### 1.1 正确性优先

禁止通过以下方式换取速度：

- 跳过可解析文件；
- 将失败、部分成功、`ocr_disabled`、`converter_missing` 或密码文件记为成功；
- 截断 PDF 页、Office 段落、XLSX 行、ZIP 成员或 OCR 区域；
- 降低 OCR 原图识别分辨率；
- 只保留文件名、路径或低分辨率预览文字；
- 设置固定单文件总耗时上限；
- 以感知哈希或相似度直接复用 OCR；
- 提前开放未完成或混合版本的 FTS；
- 静默吞掉卡滞、转换失败、缓存损坏或进程回收错误。

人工排除不是“跳过可解析文件换取速度”。它只能由用户针对已产生明确终态诊断的文件显式执行，并必须保留失败状态、审计记录和醒目的范围限制说明；严禁把人工排除文件计入解析成功数、准确性通过数或性能优化收益。

### 1.2 产品边界

- 视频仍不解析正文，不抽帧、不 OCR、不转写音频；只登记文件名、路径和基础元数据。
- 不增加长文件后台慢任务队列。
- 除视频和用户显式人工排除的精确文件版本外，所有可解析文件都属于当前完整索引批次。
- 第一次完整索引只有在当前索引范围内的文件全部达到允许发布的终态、全部父子任务完成、FTS 原子发布、数据库完整性通过且解析进程空闲后才能搜索。
- 人工排除只改变索引范围，不改变源文件，不把失败改为成功；排除后的完成状态必须显示排除数量，且能够查看、导出和撤销。
- 普通模式和性能模式只能改变并发、批量和资源预算，不得改变正文、页序、OCR 区域、搜索命中或错误处理。
- 暂停必须发生在安全边界，不能使用 Windows 强制挂起线程。

### 1.3 开发顺序

每个阶段必须严格执行：

1. 先补充会在当前实现上失败的测试或验证工具；
2. 保存失败证据；
3. 再修改实现；
4. 运行该阶段单元测试；
5. 运行该阶段集成测试；
6. 验证正文摘要和关键搜索；
7. 通过后才进入下一阶段。

禁止只增加：

- 空接口；
- 配置项；
- 日志字段；
- 数据库列；
- mock 测试；
- 不进入真实调度路径的备用实现；

然后宣称需求完成。

### 1.4 性能结论

所有对外性能结论必须满足：

- 同一设备；
- 同一电源模式；
- 同一只读语料；
- 同一应用设置；
- 同一 OCR 模型；
- 相同缓存条件；
- 修改前后各至少 3 次；
- 报告每次原始数据和中位数；
- 使用真实完成时间，不使用 ETA 代替；
- 冷索引必须使用全新数据库、解析缓存、OCR 缓存和检查点目录。

## 3. S0-01R：全执行链可回收

### 3.1 当前问题

当前主要文件解析已经进入进程池，但以下操作仍可能在扫描调度线程同步执行：

- 目录枚举；
- 文件 `stat`；
- 文件类型与元数据准备；
- 指纹计算；
- 完整 SHA-256；
- 哈希同时写入 spool；
- ZIP central directory/manifest 扫描；
- ZIP 成员候选预抽取和哈希；
- 网络盘、同步盘、损坏介质上的文件打开。

如果这些系统调用在故障网络盘、异常过滤驱动或损坏文件系统上长期不返回，解析进程 watchdog 无法回收它们。

### 3.2 目标架构

新增可回收的准备任务域，至少包含：

- `root_scan`；
- `directory_enumeration`；
- `file_stat`；
- `source_prepare`；
- `content_hash`；
- `zip_manifest`；
- `zip_member_prepare`。

所有可能长期阻塞的操作必须满足：

1. 在可终止子进程中运行，或由等价的、可证明能取消的系统 API 执行；
2. 具有独立任务 ID；
3. 上报严格语义进展；
4. 具有按阶段配置的无进展阈值；
5. 超时后只终止本应用拥有的相关进程树；
6. 回收后可以重建执行器；
7. 后续健康文件能够继续；
8. 不允许将普通线程超时当作已经终止线程；
9. IPC 不传输大文件正文，使用有界描述符、spool 或批量元数据；
10. 父进程退出后不得残留准备进程。

### 3.3 目录扫描语义进展

目录扫描至少按以下任一字段真实前进：

- 已确认完成的目录数增加；
- 已确认发现的文件数增加；
- 已确认发现的字节数增加；
- 当前目录游标移动到不同目录；
- 扫描检查点版本递增。

仅有以下变化不得刷新无进展时间：

- 心跳序号增加；
- 重复发送相同目录；
- 重复发送相同文件数和字节数；
- CPU 或内存变化；
- 进程仍存活。

### 3.4 哈希与 spool 语义进展

哈希任务必须按实际读取字节上报：

- `bytes_read` 必须单调增加；
- 每次进展对应已进入哈希状态或已持久化 spool 的字节；
- 不能仅按循环次数递增；
- 检查点必须包含文件身份、大小、修改时间和已完成偏移；
- 文件在任务期间变化时必须使检查点失效并重新开始。

### 3.5 ZIP manifest 语义进展

ZIP manifest 至少上报：

- 已读取 central directory 字节；
- 已确认成员数；
- 当前成员序号；
- 已确认成员元数据或 CRC。

损坏、加密或不安全成员必须明确分类，不能因 manifest 回收而静默跳过。

### 3.6 测试先行

新增测试至少覆盖：

- 目录枚举子进程永久等待；
- `stat` 永久等待；
- 哈希读到一半停止前进；
- 哈希持续前进且总耗时超过基础阈值 3 倍；
- ZIP manifest 永久等待；
- ZIP manifest 重复报告同一成员；
- 故障任务回收后健康文件继续；
- 强制取消时准备进程和子进程全部退出；
- 网络路径断开时错误分类和失败文件展示；
- 恢复后不重复已确认的哈希区间。

### 3.7 完成条件

- 普通文本、目录发现、`stat`、哈希和 ZIP manifest 均有真实可回收边界；
- 注入假死后在配置阈值加 2 秒调度误差内回收；
- 健康超长任务不会因总耗时被终止；
- 回收后同车道健康文件成功；
- 退出后相关进程残留数为 0。

## 4. S0-03R：真实假死端到端恢复

### 4.1 验证工具

新增 `tools/validate_hang_recovery.py`，不得只调用内部函数或直接设置 `watchdog_timed_out=True`。

验证工具必须启动真实子进程并注入以下卡点：

1. 普通 TXT/CSV 解析；
2. 文件发现或 `stat`；
3. 完整哈希；
4. ZIP manifest；
5. ZIP 成员抽取；
6. PDF 原生页；
7. PDF OCR 页；
8. 独立图片 OCR；
9. 旧版 Office 转换器；
10. 数据库写入前的 spool 阶段。

### 4.2 每个卡点的断言

每个注入场景必须验证：

- 任务开始；
- 语义进展停止；
- watchdog 在规定时间内发现；
- 对应 worker 或进程树退出；
- 旧进程 PID 不再存活；
- 进程池完成重建；
- 健康后续文件成功完成；
- 已完成检查点未丢失；
- 相同卡点第二次发生后按固定策略失败，不再等待多个扩大周期；
- 失败文件阻止完整索引发布；
- 失败信息包含阶段、游标、等待秒数、重试次数和错误码；
- 应用退出后无残留进程。

### 4.3 健康长任务反例

必须同时提供健康长任务：

- 总耗时大于无进展阈值 3 倍；
- 每个安全单位持续产生语义进展；
- 任务最终成功；
- watchdog 不误杀；
- 正文和检查点完整。

### 4.4 冻结版命令

新增：

```text
--validate-hang-recovery
--validate-semantic-progress
```

冻结版必须从发行目录运行，不得依赖源码目录、开发 Python 或联网下载。

## 5. P0-01R：真正的 PDF 页级任务图

### 5.1 当前问题

当前数据库可以记录 `pdf_native_page` 和 `pdf_ocr_page` 子进度，但主调度仍以一个 PDF 文件任务为核心：

- 一个 PDF worker 打开整份文件；
- 收集原生页和 OCR 候选页；
- 在同一 worker 中循环 OCR 候选页；
- 子任务记录主要由进度回调生成；
- 其他 worker 不能独立领取这些页；
- 单个巨型 OCR 页仍可能长期占用该 PDF worker。

这不满足“持久化、可恢复、可独立调度的页级任务图”。

### 5.2 目标任务图

每份 PDF 至少拆成：

```text
pdf_document
├─ pdf_scan
├─ pdf_native_page:1..N
├─ pdf_ocr_page:候选页
└─ document_merge
```

任务职责：

- `pdf_scan`
  - 打开 PDF；
  - 检查密码和损坏；
  - 获取页数、页尺寸和页面身份；
  - 低成本判断原生页/OCR 候选页；
  - 创建持久化页任务。
- `pdf_native_page`
  - 提取单页原生正文；
  - 保存页级块；
  - 上报页级语义进展。
- `pdf_ocr_page`
  - 只负责一页 OCR；
  - 进入统一 OCR 车道；
  - 保存页级 OCR 结果和检查点。
- `document_merge`
  - 等待所有必需页任务成功；
  - 按页码和来源确定性合并；
  - 校验页覆盖和正文摘要；
  - 生成正式文档版本。

### 5.3 调度要求

- 页任务必须是数据库中的真实可领取任务，不是只用于展示的进度记录；
- 不同 PDF 的页面可以公平交错执行；
- 一个巨型页面不能阻止其他 PDF 页进入空闲 worker；
- 同一页同一时刻只能有一个有效执行租约；
- worker 崩溃后租约可恢复；
- 页级检查点必须包含 PDF 内容摘要、解析器版本、页号、页身份和 OCR 配置；
- PDF 修改后旧页任务和缓存必须失效；
- `document_merge` 必须幂等；
- 页块排序必须稳定；
- 页失败必须阻止父文档成功；
- 中间页结果不得提前发布到正式 FTS。

### 5.4 PDF 文件句柄策略

多进程页任务不得共享不可序列化或不安全的 `fitz.Document` 对象。

允许：

- 每个 worker 按需打开只读 PDF；
- 使用受控的本地只读副本；
- 对同一 worker 的连续页复用文件句柄；
- 使用页身份和文件内容摘要验证复用安全。

禁止：

- 在进程间传递打开的 PDF 对象；
- 在父进程中渲染所有页面后传大像素数组；
- 无界缓存所有页图；
- 因并发而改变页序。

### 5.5 测试先行

至少覆盖：

- 纯原生 500 页 PDF；
- 纯扫描 PDF；
- 原生与扫描混合 PDF；
- 单个超慢 OCR 页；
- 两份 PDF 页任务交错；
- 页任务崩溃后恢复；
- 暂停后从页级检查点继续；
- 取消后未确认页不发布；
- PDF 内容变化使旧页缓存失效；
- 页失败阻止 `document_merge`；
- 合并重复执行不产生重复块；
- 普通/性能模式页块摘要一致；
- “拔掉 3 个传感器”仍命中正确文件和页码。

### 5.6 完成条件

- PDF 原生页、OCR 页和合并任务均可在数据库中独立观察和恢复；
- 巨型页不独占整个 PDF 调度车道；
- 页面可跨 PDF 公平调度；
- 父文档只在全部必需页完成后成功；
- 页面排序、正文摘要和搜索结果稳定。

## 6. P0-02R：统一 OCR 常驻车道

### 6.1 当前问题

当前图片 OCR 和 PDF OCR 分别依附于不同执行器：

- 独立图片进入 `ocr` 车道；
- PDF OCR 在 `pdf` 车道内部执行；
- 两套 worker 可能分别加载 OCR 模型；
- PDF 页不能使用全局 OCR 排队和公平策略；
- CPU、RSS 和推理线程预算不能统一核算。

### 6.2 目标架构

建立单一 OCR 调度层：

```text
图片任务 ─┐
PDF OCR 页 ├─> OCR Scheduler ─> 1～2 个常驻 OCR Worker
ZIP 内图片 ┤
ZIP 内 PDF ┘
```

OCR 请求统一包含：

- `request_id`；
- 来源文件 ID；
- 父任务 ID；
- 页面或图片 ID；
- 图像 spool 路径；
- 内容 SHA-256；
- 原始尺寸；
- OCR 配置和模型指纹；
- 优先级；
- 预计像素成本；
- 检查点游标；
- 暂停/取消控制目录。

### 6.3 常驻模型

- 每个 OCR worker 每个模型只加载一次；
- 模型加载完成必须有明确状态；
- worker 回收后允许重新加载，但必须记录原因和次数；
- 不允许图片车道和 PDF 车道各自持有重复模型；
- 模型只能从包内或本地缓存加载；
- 冻结版离线运行不得访问模型下载地址。

### 6.4 公平性

调度必须避免：

- 单个巨型 PDF 把所有 OCR 请求占满；
- 大量小图片永久饿死 PDF 页；
- PDF 页永久饿死独立图片；
- 一个低质量页面的完整分块阻止其他请求进入微批。

建议采用：

- 来源级轮转；
- 每个父文档的最大在途页数；
- 大任务和小任务成本配额；
- 等待时间提升；
- 内存与像素硬预算。

### 6.5 暂停和取消

- 暂停后立即停止领取新 OCR 请求；
- 活动请求在当前检测批、识别批、区域或页级安全点返回；
- worker 可以保留已加载模型，但必须进入空闲；
- `paused` 后 OCR 完成数、像素数和正文块不得继续增加；
- 取消可以终止 OCR worker；
- 取消后不发布未确认结果；
- 继续后只恢复未完成区域。

### 6.6 测试先行

至少覆盖：

- 图片和 PDF 页同时提交；
- 验证它们使用同一 OCR worker 集合；
- 模型每个 worker只加载一次；
- 单个巨型 PDF 与小图片公平执行；
- OCR worker 崩溃后重建；
- 暂停后 worker 空闲；
- 模式切换后 OCR worker 数按新预算重建；
- 正文和页序不因调度顺序变化；
- 冻结版离线不下载模型。

### 6.7 完成条件

- 图片、PDF 页和 ZIP 内 OCR 来源共用统一车道；
- OCR worker、CPU 线程、RSS 和批量预算统一管理；
- 页级并行和来源公平性得到真实验证；
- 退出后 OCR worker 残留数为 0。

## 7. P0-03R：OCR 自适应分块 2.0

### 7.1 当前问题

当前低质量回退会：

1. 生成完整固定尺寸网格；
2. 根据首轮检测和空白判断剔除部分 tile；
3. 对保留 tile 再检测；
4. 合并重复区域。

这比无条件完整网格更好，但仍不是原始需求中的“文字热区和未解决区域驱动”：

- 完整网格仍然先生成；
- 没有持久化未解决区域图；
- 没有从大区域逐层细分；
- 没有四叉树或等价递归规划；
- 没有按区域质量持续更新覆盖状态；
- 检查点仍不足以精确恢复到单个区域。

### 7.2 目标流水线

建议实现以下阶段：

1. **预览检测**
   - 长边限制为 960；
   - 输出文字候选、置信度和坐标变换；
   - 不使用预览文字替代原图识别。
2. **原图区域识别**
   - 将候选映射回原图；
   - 对原图 crop 识别；
   - 高质量区域标记为已解决。
3. **未解决区域图**
   - 将整图划分为粗粒度覆盖单元；
   - 记录已解决、疑似文字、未知、确定空白；
   - 任何不确定区域必须保留。
4. **热区规划**
   - 使用边缘密度、连通域、局部对比度、首轮候选邻域等低成本特征生成文字热度；
   - 热度只决定检查顺序，不能直接跳过不确定区域。
5. **递归细分**
   - 从较大区域开始；
   - 只有区域过大、质量不足或结构复杂时才拆分；
   - 使用四叉树或等价层级规划；
   - 不先铺满固定 1280 网格。
6. **区域检测和识别**
   - 对未解决区域检测；
   - 推理前去重；
   - 识别后更新未解决区域图。
7. **完整性收口**
   - 所有疑似文字和未知区域必须得到确认；
   - 只有严格空白证据才能标记为无需 OCR；
   - 最终输出覆盖率和未解决区域数。

### 7.3 区域身份

每个区域必须有稳定 ID，至少由以下内容确定：

- 源图内容 SHA-256；
- OCR 策略版本；
- 层级；
- 原图坐标；
- 预处理参数；
- 模型指纹。

同一输入多次运行的区域 ID、处理顺序和正文排序必须稳定。

### 7.4 完整性保护

禁止设置“最多只处理 N 个区域”并丢弃剩余区域。

允许：

- 分批；
- 暂停；
- 降低同时在内存中的区域数；
- 延后低热度区域；
- 在严格空白判定后跳过；
- 复用完全相同区域缓存。

不允许：

- 以耗时过长为由提前结束；
- 只处理热区；
- 忽略低置信度文字；
- 使用预览图识别结果代替原图结果；
- 因分块过多将文件标记成功。

### 7.5 检查点

检查点至少保存：

- 策略版本；
- 源图 SHA-256；
- 已解决区域集合；
- 未解决区域队列；
- 已完成检测批；
- 已完成识别批；
- 已确认文字行；
- 正文排序键；
- 缓存引用；
- 检查点版本。

暂停、崩溃或 worker 回收后不得重新识别全部已确认区域。

### 7.6 指标

至少记录：

- `preview_detect_calls`；
- `preview_detect_pixels`；
- `adaptive_regions_created`；
- `adaptive_regions_split`；
- `adaptive_regions_pruned_blank`；
- `adaptive_regions_resolved`；
- `adaptive_regions_remaining`；
- `original_region_pixels`；
- `fallback_region_pixels`；
- `coverage_ratio`；
- `crop_dedup_hits`；
- `checkpoint_regions_reused`。

### 7.7 测试先行

至少包含：

- 13,837×9,637 液路图；
- 两张 3,072×4,096 微信图片；
- 大面积空白、小字号密集文字图；
- 稀疏工程图；
- 旋转文字；
- 预览漏检但局部结构明显的图；
- 多个相邻文字区域；
- 高质量首轮无需分块；
- 中途暂停和崩溃恢复；
- 相同输入多次运行区域顺序一致。

### 7.8 完成条件

- 低质量大图不再先生成完整固定网格作为唯一规划基础；
- 未解决区域图能解释为什么继续拆分或结束；
- 处理像素和检测调用数显著降低；

## 8. P0-04R：跨分块、跨页面、跨文件微批

### 8.1 当前问题

当前区域识别能在单张图片内部按固定批量调用识别器，但缺少：

- 跨 tile 汇聚；
- 跨 PDF 页面汇聚；
- 跨不同文件汇聚；
- 统一的短时聚合窗口；
- 动态批大小；
- 像素与 RSS 预算；
- 检测微批；
- 全局公平性和超时返回。

### 8.2 微批组件

实现统一微批器，至少分为：

- `detection_batcher`；
- `recognition_batcher`。

每个请求必须携带：

- 稳定请求 ID；
- 父任务和区域 ID；
- 像素尺寸；
- 语言、模型和预处理配置；
- 排序键；
- 提交时间；
- 取消状态；
- 结果回调或结果 spool。

### 8.3 聚合规则

- 聚合窗口建议 20～50 ms，可通过真实基准调整；
- 达到最大请求数、最大像素数、最大内存或最大等待时间后立即执行；
- 不同模型、语言或不兼容预处理参数不得放入同一批；
- 批大小根据平均 crop 尺寸和可用内存调整；
- 必须有请求数、像素数和内存硬上限；
- 超大 crop 单独执行；
- 小请求不得因等待大批量而明显增加延迟；
- 暂停请求后不再形成新批；
- 已进入推理的批在安全结束后返回。

### 8.4 结果确定性

推理完成顺序可以变化，但最终输出必须按稳定键排序：

```text
(source_order, page_number, region_top, region_left, region_id)
```

任何批处理都不得改变：

- PDF 页序；
- 同页阅读顺序；
- 文本行去重规则；
- 搜索上下文；
- 普通/性能模式正文摘要。

### 8.5 检测后端限制

如果当前 Paddle 检测接口不能可靠支持多图 batch：

1. 必须用真实实验确认；
2. 可以先实现跨页识别微批；
3. 检测仍需统一排队和资源核算；
4. 报告不能把“队列批处理”伪称为“推理 batch”；
5. 后续后端 A/B 中继续评估检测批处理。

### 8.6 指标

至少记录：

- `detect_requests`；
- `detect_inference_calls`；
- `detect_batch_count`；
- `detect_average_batch_size`；
- `detect_pixels`；
- `recognize_requests`；
- `recognize_inference_calls`；
- `recognize_batch_count`；
- `recognize_average_batch_size`；
- `recognize_pixels`；
- `microbatch_wait_ms_p50/p95/max`；
- `oversize_single_count`；
- `cancelled_before_batch_count`。

### 8.7 测试先行

- 同图多个 tile 进入同批；
- 两个 PDF 页进入同批；
- PDF 页和独立图片进入同批；
- 不同语言不能错误混批；
- 超大 crop 单独执行；
- 暂停时停止新批；
- 批内一个请求取消不破坏其他结果；
- 返回顺序变化但最终正文顺序稳定；
- 微批前后 OCR 结果一致。

| 状态 | 数量 | 是否真失败 | 当前是否阻断搜索 |
|---|---:|---|---|
| `metadata_only` | 158 | 否；其中 157 条无错误，1 条为 `ZIP_NO_SUPPORTED_MEMBER` | 是 |
| `failed` | 14 | 是 | 是 |
| `failed_retryable` | 1 | 是，且可重试 | 是 |
| `skipped` | 9 | 是安全上限导致的未解析终态 | 是 |
| `partial_success` | 4 | 部分正文已取得，但仍有成员失败 | 是 |

当前实现存在两个直接原因：

1. `DatabaseManager.failed_files()` 把 `metadata_only`、`skipped`、`partial_success` 等状态全部放进“失败文件”清单，导致正常终态和真正失败混在一起。
2. `DatabaseManager.stats()` 只把 `parse_status='success'` 计入 `complete_files`，其余所有非视频文件都进入 `blocking_files`；因此这 186 条记录会全部阻止 `index_readiness.ready`，包括 158 条并未解析报错的 `metadata_only`。

这不是单纯的解析器问题，还包含完成语义和失败清单分类错误。FTS-02R 必须同时修正，不能只增加一个把状态改成 `success` 的按钮。

### 11A.2 目标与非目标

目标：

- 对真正阻断首次索引的文件提供单选、多选和批量人工排除；
- 排除后，在所有剩余范围内文件完成且 FTS-01R 门禁通过时允许发布和搜索；
- 完成状态明确显示“当前范围完成（人工排除 N 个文件）”；
- 保留原始失败原因、来源身份、排除原因、时间和撤销历史；
- 文件被修复或发生变化时自动失效旧排除并重新进入解析范围；
- 正常 `metadata_only` 不再作为失败和阻断项。

非目标：

- 不删除、移动、重命名或修改用户源文件；
- 不把失败、部分成功或跳过状态改写为 `success`；
- 不自动放宽 ZIP 解压体积、成员数、递归深度等安全上限；
- 不提供按路径永久静默忽略所有未来版本的能力；
- 不允许用人工排除后的语料替代第 21、22、25 节规定的完整准确性和性能验收。

### 11A.3 状态与完成语义

解析状态和索引范围状态必须分离：

| 解析状态 | 默认完成语义 | 是否需要人工排除 |
|---|---|---|
| `success` | 范围内完成 | 否 |
| `metadata_only` 且解析流程正常结束 | 范围内“仅元数据完成”，不计解析成功，但不阻断 | 否 |
| `ZIP_NO_SUPPORTED_MEMBER` | 范围内“仅元数据完成”，不作为错误 | 否 |
| `failed` / `failed_retryable` | 阻断 | 修复重试或人工排除 |
| `skipped` | 阻断 | 调整安全设置后重试或人工排除 |
| `partial_success` | 阻断 | 修复成员后重试，或明确接受移除该容器全部索引后人工排除 |
| `converter_missing` / `password_protected` / `ocr_failed` / `unsupported` | 阻断 | 修复依赖、文件或设置后重试，或人工排除 |
| `ocr_disabled` | 仅当本批次开始前用户明确关闭对应 OCR 能力时为“配置范围内完成”；否则阻断 | 视批次设置而定 |

新增独立范围状态：

```text
included
manual_excluded
```

强制语义：

- `manual_excluded` 不能覆盖或清除 `parse_status`、`parse_error_code` 和 `parse_error_message`；
- `eligible_files = 活跃非视频文件 - 当前有效人工排除文件`；
- `complete_files = included 范围内的 success + 允许的非失败终态`；
- `blocking_files = eligible_files - complete_files`；
- 另行返回 `manual_excluded_files`、`metadata_only_complete_files` 和 `discovered_files`；
- UI 和导出不得把 `complete_files` 与“解析成功文件数”混为同一个指标。

### 11A.4 数据模型与审计

升级 schema，新增结构化排除历史，至少包含：

- 排除记录 ID 和文件 ID；
- 根目录 ID、规范化路径和显示路径；
- 排除时的源身份：大小、`mtime_ns`、稳定内容摘要或等价强身份；
- 排除时的解析状态、错误码、错误消息摘要和解析器版本；
- 用户填写或选择的排除原因；
- 创建时间、撤销时间、失效时间和失效原因；
- 所属候选索引版本和最终发布版本；
- 操作来源，至少区分 UI、迁移和验证工具。

约束：

- 同一文件同一源身份只能有一条有效排除；
- 排除、候选正文/元数据移除、任务关闭和 readiness 更新必须在同一受控事务或可恢复发布流程中完成；
- 失败或崩溃时不得出现“排除已显示但旧正文仍可搜索”的半状态；
- 历史记录不可硬删除，撤销只能写入撤销字段；
- 现有 `files`、`documents`、`content_blocks` 和 FTS 关系保持外键完整。

### 11A.5 UI 与操作流程

“未成功索引”页面必须拆分为：

- `阻断项`：真正阻止当前索引完成的失败、跳过和部分成功；
- `已人工排除`：当前有效排除及其原因；
- `仅元数据完成`：正常但没有正文的文件，不显示为失败。

阻断项支持复选框、全选当前筛选结果、`重新尝试`、`从当前索引范围排除`。排除前必须显示确认对话框，至少包含：

- 文件数量和可展开路径列表；
- 当前错误码和原因；
- “这些文件的文件名、路径和正文均不会出现在搜索结果中”的明确后果；
- “源文件不会被删除，之后可以恢复纳入”的说明；
- 可选排除原因。

操作限制：

- 正在被 worker 写入的文件不能直接改范围；必须先到达安全点并关闭对应任务，或提示用户暂停/等待；
- 批量操作必须全成或全不成；
- `partial_success` 被排除时，已产生的部分正文也必须从候选版本移除；
- 成功后刷新阻断数、排除数和候选发布状态；
- 搜索页和索引状态区持续显示“已排除 N 个文件”，点击可进入排除列表；
- 提供“恢复纳入并重试”，不得只提供单向排除。

### 11A.6 与 FTS 原子发布的关系

人工排除是候选索引版本的范围变更，必须进入 FTS-01R 的原子发布流程：

1. 验证所选文件仍是确认时的源身份和错误状态；
2. 停止或关闭相关未完成任务；
3. 从候选版本删除该文件全部正文块、ZIP 成员块和元数据搜索候选；
4. 写入有效排除审计；
5. 重新计算候选范围、父子任务和 readiness；
6. 只有其余门禁全部通过才构建并发布候选 FTS；
7. 原子切换后显示受限完成状态。

更新索引场景中，如果文件旧版本曾经成功索引、当前版本解析失败并被排除，新版本发布后不得继续搜索到旧正文。发布前旧活动版本如何提供服务沿用 FTS-01R 策略，但任何时刻不得出现新旧内容混合。

### 11A.7 变化失效、撤销与重试

- 文件大小、`mtime_ns` 或强内容身份任一变化时，旧排除自动失效；
- 失效文件重新进入 `included` 范围并按新版本解析，不能继承旧失败的排除决定；
- 文件被删除时走正常删除和候选发布流程，不保留可搜索旧内容；
- 用户撤销排除后，文件立即重新成为阻断项，直到解析成功、达到允许的非失败终态或再次被明确排除；
- 重启后有效排除和撤销历史必须保持一致；
- 解析器版本或关键设置变化时，产品应提示可重试排除项，但不得在没有源文件身份变化时静默撤销用户决定。

### 11A.8 现场失败原因与修复要求

当前环境存在 `D:` 盘，但 `D:\技术资料` 不可访问，因此本轮能够确认 CSV 记录和代码分支，不能对原文件执行文件头、ZIP CRC、OLE 或 Office 打开复核。下表中“待原文件复核”的原因不得写成已经确认的文件损坏结论。

| 类别 | 数量 | 当前可确认原因 | 必须处理 |
|---|---:|---|---|
| `metadata_only` 无错误 | 157 | 实际不是失败；失败清单查询和 readiness 把正常终态错误地当成阻断 | 修正分类、文案和完成统计 |
| `ZIP_NO_SUPPORTED_MEMBER` | 1 | ZIP 结构可读，但没有支持的正文成员 | 归入“仅元数据完成”，不作为失败 |
| `ZIP_SIZE_LIMIT` | 8 | central directory 声明的解压后总字节超过当前 1 GiB 安全上限 | 显示实际值/上限，允许调整设置后重试或人工排除；不得自动放宽 |
| `ZIP_FILE_COUNT_LIMIT` | 1 | ZIP 文件成员数超过当前 2,000 上限 | 显示实际值/上限，允许调整设置后重试或人工排除；不得自动放宽 |
| `ZIP_CORRUPTED` | 6 | `zipfile.ZipFile` 抛出 `BadZipFile`；可能是真损坏，也可能只是扩展名为 `.zip` 但内容不是 ZIP | 原文件复核文件头、central directory 和 CRC；可识别的错扩展名给出精确分类 |
| `ZIP_PARTIAL_FAILURE` | 4 | 容器内共有 8 个成员解析失败、9 个成员跳过；当前代码吞掉成员异常，只保留汇总数 | 持久化成员路径、成员解析器、错误码和原因；不得只报总数 |
| XML `UnicodeError` | 5 | 文本编码检测最终选择了需要 BOM 的 UTF-16，但实际流没有 BOM，打开流时失败 | 修复编码探测：验证候选编码，只有 BOM 或可靠字节特征时选择 UTF-16，并增加现场同型回归样本 |
| XLSM `BadZipFile` | 2 | `.xlsm` 按 OOXML ZIP 打开时发现不是 ZIP；可能是损坏或旧版 XLS 被改了扩展名 | 增加 OOXML 文件头/包结构预检；可识别 OLE 时走受控旧版 Excel 分支，否则给出 `OOXML_INVALID_FORMAT` |
| DOC `LEGACY_INVALID_FORMAT` | 1 | 扩展名为 `.doc`，但文件头不是 OLE | 原文件复核是否为 RTF、HTML、纯文本、错扩展名或损坏，并按签名路由或给出精确分类 |
| XLS `LEGACY_OPEN_FAILED` | 1 | 文件通过旧版 Office 前置检查，但 `Excel.Application.Workbooks.Open` 返回失败 | 用原文件验证 Excel/WPS/LibreOffice、加密和损坏情况；导出所有转换器尝试结果，保留可重试状态 |

上述 XML 编码误判和 ZIP 成员异常被吞属于可修复代码问题。人工排除功能不能替代这些修复；FTS-02R 达到“代码完成”前，必须至少关闭这两项红灯。

### 11A.9 测试先行

修改实现前至少建立以下失败测试并保存输出：

- 一个正常 `metadata_only` 文件不进入失败清单、不阻断首次搜索；
- 一个 `ZIP_NO_SUPPORTED_MEMBER` 文件进入“仅元数据完成”而非失败；
- 一个失败文件使首次索引保持不可搜索；
- 人工排除该精确文件版本后，其余文件完成时发布候选并开放搜索；
- `parse_status` 仍为失败，排除数为 1，UI 不显示“全部文件解析成功”；
- 排除文件的文件名、路径、正文和旧版本正文均不能被搜索命中；
- 排除 `partial_success` 容器时删除全部部分正文；
- 排除操作中崩溃后恢复为全排除或全未排除，不存在半状态；
- 文件内容变化后旧排除失效并重新阻断；
- 撤销排除后重新阻断并可重试；
- 重启和 schema 迁移后排除与审计不丢失；
- 活动 worker 写入期间不能竞态排除；
- ZIP 超限保留安全上限，只有用户操作后才改变范围；
- 无 BOM 的现场同型 XML 能按真实编码完成解析；
- ZIP 部分失败导出精确成员路径和错误；
- 源码和冻结版 `--validate-manual-exclusion` 均验证首次索引、更新索引和原子发布。

### 11A.10 完成条件

- 现场清单按新语义重放时，158 条 `metadata_only` 均不再被误报为失败或阻断；
- 剩余 28 条阻断项能够分别重试或由用户显式排除；
- 排除后搜索可用，状态明确显示排除数量，排除文件完全不出现在搜索结果；
- 排除可撤销，文件变化会使精确版本排除失效；
- XML 编码误判修复，ZIP 部分失败具有成员级诊断；
- 排除、候选清理、FTS 发布、崩溃恢复和 schema 迁移测试全部通过；
- 真实文件二进制复核完成并保存原始诊断结果；
- 未使用人工排除缩小第 21、22、25 节的基准验收范围。

## 13. P1-02R：运行时自适应资源调度

### 13.1 当前问题

当前硬件探测主要在运行开始或模式切换时生成静态配置，资源监控主要记录峰值 RSS，没有形成实时反馈控制。

### 13.2 采样输入

运行期间至少采集：

- 总 CPU 使用率；
- 本应用进程树 CPU；
- 总内存和可用内存；
- 本应用进程树 RSS；
- 各 worker RSS；
- 各车道待处理任务数；
- 各车道在途任务数；
- OCR 待处理像素；
- writer 队列深度；
- 本地磁盘吞吐和繁忙度；
- 网络路径读取延迟；
- 最近一段时间任务完成率；
- worker 回收和失败率。

### 13.3 控制状态

至少使用带滞回的状态：

- `stable`；
- `underutilized`；
- `memory_pressure`；
- `cpu_pressure`；
- `io_pressure`；
- `recovery_cooldown`。

禁止每次采样都改变 worker 数。必须有：

- 连续样本门槛；
- 最小状态持续时间；
- 扩容冷却时间；
- 缩容冷却时间；
- 上下限；
- 模式切换和暂停锁定。

### 13.4 行为

- OCR 默认 1 worker；
- 只有 CPU、RSS、可用内存、队列和磁盘均满足条件时才允许升到 2；
- RSS 超限或系统可用内存过低时减少并发；
- 磁盘持续繁忙时减少并发读取；
- 网络盘使用更保守并发；
- writer 堵塞时停止继续提交解析结果；
- 已在执行的安全任务不因缩容被强杀；
- 进程池变更必须在安全边界进行；
- 暂停时不扩缩容；
- 普通模式不允许超过普通模式硬上限；
- 性能模式不允许超过全局 CPU token 和内存预算。

### 13.5 指标

每次变化记录：

- 时间；
- 原 worker 数；
- 新 worker 数；
- 触发原因；
- CPU；
- RSS；
- 可用内存；
- 磁盘状态；
- 队列深度；
- 冷却时间；
- 是否成功；
- 回滚原因。

### 13.6 测试先行

- 低负载稳定扩容；
- 内存压力缩容；
- CPU 压力不扩容；
- 磁盘压力降低读取并发；
- 状态临界值附近不抖动；
- 暂停时不调整；
- 模式切换后应用新上限；
- 扩缩容不改变正文摘要；
- 峰值 RSS 不超过 4 GiB。

## 17. U0-03R：真正安全暂停与资源空闲

### 17.1 当前问题

当前 `is_safely_paused()` 主要依据：

- 没有未完成 future；
- writer 队列为空。

仍需证明：

- 所有子进程都已确认到达安全点；
- OCR、PDF、Office 等外部进程没有继续工作；
- 没有后台线程继续推进页、区域或字节；
- 没有持续数据库写入；
- CPU 和磁盘接近空闲。

### 17.2 明确状态机

```text
running
  └─ pause request
       ↓
pause_requested
       ↓
pausing
       ↓
paused
       ├─ switch mode → paused
       └─ resume → resuming → running
```

### 17.3 worker 确认

每个活动任务必须在安全点返回确认：

- `task_id`；
- worker PID；
- 安全单位类型；
- 已完成游标；
- 检查点版本；
- 检查点校验和；
- 返回时间；
- 是否仍持有外部子进程。

只有全部活动任务确认、writer 空闲、没有外部转换进程运行后才能进入 `paused`。

### 17.4 各格式安全点

- PDF：页完成、区域批完成或页级检查点；
- 图片 OCR：检测批、识别批或区域检查点；
- ZIP：成员完成；
- XLSX：工作表行批；
- OOXML：段落/工作表/幻灯片批；
- 旧版 Office：转换完成或受控取消后重启；
- 哈希：已持久化字节偏移；
- 目录扫描：已确认目录批。

### 17.5 资源验证

点击暂停后：

- 1 秒内停止提交新任务；
- UI 显示“正在暂停…”；
- 所有任务在一个安全单位完成后加 2 秒调度误差内进入 `paused`；
- `paused` 后连续观察至少 5 秒；
- 完成文件、页、区域和字节计数不再变化；
- 没有持续数据库写入；
- 进程树 CPU 接近空闲；
- 没有持续源文件读取；
- OCR worker可以保留模型但必须空闲；
- Office/WPS/LibreOffice 不得继续转换。

### 17.6 继续

- 继续后所有游标严格前进；
- 不重复正文块；
- 不重复已确认页或区域；
- 检查点损坏时明确失败或安全重做当前最小单位；
- 继续后 ETA 重新校准；
- 失败数不增加。
