# 统一生成提示：开发和配对验证记录

## 本轮边界

只增加最终生成提示的 `unified` 实验选项，不更改检索、BGE 分窗口最高分、简单选段、实际 Context、Gold、裁判和持久化设置。默认仍为 `baseline`，Domain Adapter、语义澄清、答案二次复核保持原设置。019 按用户要求冻结，但仍保留在固定统计集合。

运行前冻结协议：`reports/rag_unified_prompt_20261119/protocol.json`。AI bundle 为 `g000033-71ec3c52f3`；原提示与上一实验冻结值一致。源文件、代码、数据和配置共 396 个文件纳入哈希核对，包含 262 个真实原资料文件。

## 修改内容

- `local_full_text_search/rag/generation/openai_compatible.py`：增加用户确认的五部分统一提示及显式选项；原提示和默认值不变。提示不含题号、Gold、业务答案或少样本示例。
- `tests/rag/test_unified_prompt_20261119.py`：覆盖两种 API 请求格式、默认行为、用户输入与 Context 不变、无答案常量。
- `tools/validate_unified_prompt_20261119.py`：冻结输入、保存发送前请求及判分前原始回答、配对执行、只对执行错误做一次恢复。
- `tools/verify_unified_prompt_service_20261119.py`：真实本地召回和 AnswerService 入口验证，不用生成器隔离实验替代应用验收。
- `tools/report_unified_prompt_20261119.py`：沿用应用的各阶段排名和详细诊断格式，增加原提示/新提示前后对照，保留原资料定位按钮。
- `tools/check_unified_prompt_report_20261119.cjs`：校验页面题数、展示回答与原始记录一致、方案切换及资料按钮请求。

## 预先固定的实验

1. 111 个现有问题，各方案一次：50 reviewed、60 pending、1 disputed 分别统计。
2. 重点 7 题各方案总共 3 次：014、016、020、021、035、电压题、条码题。
3. 合计 250 个固定 Context 生成及独立判分任务；每个任务各有生成请求和裁判请求，不是 250 个 HTTP 请求。
4. 重点 7 题真实入口各方案一次，共 14 次。冻结 Context 与真实生成请求正文比对。
5. 不因答案不理想重试，不中途改提示，不删除难题。不因总一致数上升直接采用。

## 已完成的代码检查

相关单元及兼容测试 70 通过。全 RAG 测试 582 通过、10 失败、1 跳过、1 预期失败。10 个失败与上轮已记录的跨文档共识测试名称一致，不属于本轮新增失败，仍保留为仓库已有问题，不能称全套全绿。

## 运行后发现的独立兼容问题

候选提示的拒答句为“本次提供的资料中没有足够依据。”，现有 AnswerService 只对完全匹配的“资料中没有足够依据。”返回 insufficient。通过真实 AnswerService 加模拟生成器的确定性测试，前一句进入引用校验后报缺少引用，后一句正常返回 insufficient。

这是提示与既有输出协议不兼容，不是召回问题；测试未调用 API。证据保存于 `refusal_contract_audit.json`。当前配对提示已经冻结，不能边跑边换成修正版再把结果合并。本轮结果与后续兼容修正必须分开记录。

## 最终结果

结论：**有局部收益，但不整体替换默认提示。** 默认 `baseline`、持久化设置和所有上游模块均不变。统一提示作为显式实验选项保留，当前不应启用为正式默认。不是“提示完全无效”，也不是“检索已经没有问题”。

### 真实应用与输出协议

14次真实 AnswerService 验证中，两组实际发送的Context均与冻结值一致，正常返回13次，失败1次：020新提示引用不存在的S37，被现有硬校验阻止。该失败不属于网络错误，不重试到成功。

另有不调用API的确定性真实入口测试：候选拒答句“本次提供的资料中没有足够依据。”与现有只识别“资料中没有足够依据。”的精确协议不兼容。017新提示实际生成了无引用的候选拒答及说明，隔离裁判判一致，但应用不能直接按正常拒答返回。`output_contract_audit.json`将自动一致与格式可返回分开记录；这不是新增250次真实入口测试。

### 已定位的共同原因

1. **生成时保留事实不等于保留关系。** 021概括表和详细分支都已进入Context，新提示仍优先套用概括表；不是本轮检索漏掉详细证据。
2. **补充越多，越可能增加未绑定的主张。** 006多加气泡条件却引用了只写持续进空气的来源；待审题将存放通道条件套到放入区，或将保险丝通断测量的局部要求套到浮子传感器。
3. **提示要求引用，不等于保证引用编号合法。** 020两次出现S37，裁判还漏检一次。保留现有程序硬校验比依赖LLM判一致更可靠。
4. **提示输出须兼容应用协议。** 拒答语义正确仍可能因精确文本不匹配而被当成缺少引用。
5. **自动裁判仍有争议和漏检。** 034行为判断差异、020不存在引用仍判一致，均需与生成错误分开，不能用一个总分概括。

### 原资料核验和页面

27条新增文件/页或位置核验记录存于 `additional_source_audit.json`；包括液路PPT/PDF、条码不同平台、A&T电解质流程、BS-430序列号条件和维修手册电压表。原PDF第205页的J7接口表将+24V正常范围22.8～25.2V与P05控制相邻列出，第277页泵清单将P05对应DC24V，已渲染核对行列。PDF阅读器页码从1开始，分别对应页脚195、267，不可混用。

上轮021、035等原页核验通过同一文件哈希及相同Context复用，记录于 `source_verification_reuse.json`。新文本核验不自动证明复杂版式下的型号适用性；范围不清单列，不靠文件相邻或检索排名推断。

`manual_review.json`核对21个列出的业务问题与诊断事项，不代表250份回答均已人工审核。原始250个请求、回答、判分、14次真实入口事件均保留；Gold和审核状态没有修改。
