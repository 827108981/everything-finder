## 实验与结束条件

1. 保存全部 fixtures、评测代码、运行时代码、配置和持久化设置哈希；复制当前代码到只用于 A 组的隔离快照。保持 AI bundle 不变。
2. A：修改前 Adapter 开启的当前代码；B：重构后 Adapter 开启。另做 Adapter 关闭兼容检查，持久化默认保持 false。
3. 全量检索 91×2；同一冻结模型、相同生成 Prompt/参数对比 A/B Context。QueryPlan 与 Context 是被测数据，系统 Prompt 不随题号变化。
4. 两步答案计划属于生成机制变更，另外报告。使用同一固定 Context，旧生成与新计划验证各 3 次（预先固定重点题集合）；不按回答好坏重试。传输失败单列。
5. 不修改判分。新增安全审计只作为附加指标，不替代原判。未人工审核的题继续只诊断。业务可用性、语义范围/对象判断无法自动证明时明确待人工核查。
6. 所有退化保留：按引文首次丢失阶段定位，无法归因的不写成已确认根因。不为单题增加业务例外；不达到验收也完成全量报告，默认继续关闭。

## 实现边界

QueryPlan 只描述用户问题；兼容原字段，以规范化视图提供 intent/entities/scope/constraints/requested_fields/ambiguity/answer_mode/query_variants。证据事实来自实际正文与真实来源；生成计划逐条绑定 source_id、原文引文、对象、范围和确定性。相同值不同范围不合并；候选未进入 Context 不可成为引用。

答案计划采用可验证的原文主张，经结构、来源、数字、范围与对象核对后确定性渲染，避免第二次自由生成增加无来源结论。语义证据不足保留缺口，不能将字符串匹配称为完整语义证明。

交付 `report.html` 前后对照、审计清单、哈希核验、逐题失败定位、固定 Context 稳定性结果。HTML 复用当前原资料定位入口。
