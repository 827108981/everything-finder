## 结论与当前运行状态

已实现并验证“问题条件绑定 + 局部适用性判断”的可注入实验版本，完成四组91题对照、真实检索入口4题×2组、原文核验和8道新增资料保留检查。

**本轮组合方案暂不采用，应用继续使用已采用的A选段与原条件检查。** Domain Adapter仍默认关闭，持久化设置未改。原因不是最终答案不好（本轮没有生成答案），而是新条件检查本身已确认误删一段适用的多分支方法资料。

## 实现能做与不能做的事情

已实现：

1. “几乎所有发光项目”保留为most，并绑定发光项目；不冒充全部。
2. 区分single/few/multiple/most/all；可能重叠的范围判unknown，不能仅凭取值不同判冲突。
3. 判断前核对对象；个别项目不能直接作为多项目故障的完整依据，个别通道也不能与多个项目直接比较。
4. 多个已识别范围分支并存时，保留完整片段；包含目标分支不代表其他分支也适用。
5. 否定、猜测、引用、方法型分支不强行设为全局已发生条件。
6. 方向只在可绑定到相同局部对象时判相反；其他阶段可能是处理步骤，不能一律否定当前故障阶段。
7. 型号只有正文明确排他说明才可判冲突。文件名不用于新增的硬冲突判断。
8. 所有判断留下问题原文、对象、位置、来源理由、正文短句和候选排除理由。

当前局限：

- 这是确定性的保守解析器，不是通用中文语义理解模型。
- `单项目/多项目`等短表达和“只定一个项目”的动作数量没有完整区分，已造成真实误删，见第49张。
- 新数值/单位/阈值比较器尚未实现，数值仍保留在原问题/检索表达式中；不得宣称已完成任意阈值与单位推理。
- 型号判断能力依赖输入中已有MODEL条件；本轮没有另外开启Adapter或补全任意型号识别。
- 表格整行/多分栏的空间结构没有新增重建。局部关系不明时保留unknown；不能声称已经解决所有表格归属。
- 判断组保留A原有条件排序，不增加新加分；原有排序缺陷仍可能存在。

## 首次失败记录

第一次运行的局部判断错误保留了“新条件交给旧规则排序”的顺序，使正确资料被排到末尾。修复为固定A基线排序后重跑，属于实验实现接线错误修复，不是调权重或改Gold。首次结果保存在`attempt1_ordering_defect/`，没有覆盖。

另一次首次启动因评测函数收到EvidenceChunk而非快照字典报错，尚未生成完整四组结果；修正数据接口后运行。两种执行问题与最终业务误删分别记录。

## 下一步最小修复

下一轮仍只改条件解析，不动A及重排：

1. 先把数量表达按“故障涉及多少对象”“本次操作了多少对象”“通用方法的条件分支”分开。第49张的“一次只定一个项目”是操作范围，不应覆盖同段其他故障分支。
2. 只有完整识别了局部场景、且没有未解析的并列/对比分支，才允许整段硬排除。无法确认分支归属时保留unknown。
3. 用短数量词、动作数量、否定和多个对象的反事实用例测试；增加来自不同资料的真实冲突正负对，不靠补一个词让第49张通过。
4. 再跑相同四组和91题回归，逐条查被删除的非Gold方法资料。只有“正确证据不丢 + 真实误删消除 + 跨来源冲突检查有效”才考虑限定范围采用。

不需要用户重新确认第49张：现有原文足以认定这次整段删除错误。新增pending题若未来进入正式计分，仍需业务人员逐题审核。
