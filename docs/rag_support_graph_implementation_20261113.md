# 通用证据支持与字段级回答：开发说明

**历史实现说明：此轮实现已于2026-11-13按用户要求回退，以下内容记录实验时设计，不代表当前已启用链路。当前状态见 `rag_support_graph_rollback_20261113.md`。**

## 本轮边界

本轮开始时已有大量历史未提交文件，因此以 reports/rag_support_graph_20261113/baseline_src 为修改前快照，不以 Git HEAD 冒充基线。当前业务题库、所有状态和 evaluation 判分代码均被冻结。当前模型、API 连接和索引内容不变。未删除、重新分组或退休任何题目。

## 实际链路

1. QueryInterpreter 保留原问题，QueryAnalyzer 给出基础关键词和条件；高置信度领域配置仅提供实体及别名。
2. 增强解析将数量范围、阶段、方向、主题、泛设备类型降为软约束。明确型号及明确标识符冲突继续由原文约束；未提及不自动等于不适用。
3. BM25、向量、RRF、Cross Encoder 的主体算法未重写。新的字段覆盖只作用于已通过基本质量和明确冲突门禁的候选。
4. EvidencePolicy 保留原有顺序的两个锚点，最多补充两段新增字段/数值角色证据；被替代项不得贡献独有字段，精确代表及多来源代表不能被替代。原始顺序最终恢复。文档配额只为这两段明确互补证据豁免，总段数与字符预算仍有效。
5. ContextBuilder 只对实际发送的正文提取事实；事实拥有来源编号、原文行、文件页码、范围、条件和角色。丢弃候选不会伪装成来源。
6. Support Graph 记录 source→fact、fact→scope/condition、显式同对象同范围字段冲突、原文明确父子关系及同一来源内连续编号步骤。不同页相邻不构成步骤或场景延续证据。
7. 结构化计划允许多个真实引用共同支撑一个主张。短引文可以恢复到可验证的完整表格行或原文行；不能借另一个表格行的数值。数字、编码、范围、对象继续审核。
8. 若缺少请求字段，调用原自然语言生成，再从其初稿中提取可验证的缺失事实，重新执行原文绑定与逐主张审核，通过后才合并。初稿不是证据。
9. 若结构化链路发生基础设施/解析错误，只有旧答案的引用编号有效时才回退旧答案，记录具体原因，随后继续发布前审核。语义审核明确不支持的主张不能借回退复活。
10. 发布前审核以有证据的原子主张重建答案，不因一个字段不足丢掉其余事实。非严格模式审核失败保留初稿并提示未审核；这只是可用性回退，不是正确性证明。
11. 语义澄清必须存在会改变具体答案的缺失条件，并引用原文；概念、原因、一般排查、方法分支不强制先追问。部分可答时先继续生成、核验有依据的条件分支，再补充澄清问题；不得用原文摘录加追问替代可答的方法。
12. 最后分别核对每条主张引用、最终引用编号；引用有效与语义正确分开记录。

## 诊断字段的含义

- graph.field_support.partial_supported：原文包含相关字段信号，尚未证明能完整回答，不冒充 supported。
- not_found：当前已发送文本没有发现字段支持线索，不等于所有语料没有答案。
- conflicting：显式同对象、同范围、同条件、同字段值不同；不自动选一个版本。
- not_applicable：明确冲突门禁排除的候选；unknown/uncertain 不能被当成已适用。
- structural_rejections / semantic_checks：结构校验和语义审核分开保存，方便区分误删来自哪一步。
- fallback.used/reason/verified_claims_added：是否回退、触发原因、经核验补入的事实数量。
- claim_citation_checks：只说明编号映射是否有效，不替代事实和适用范围的审核。

## 配置与回滚

请求的五项设置已在新默认值和本机配置启用：QueryPlan=true、StructuredAnswer=true、AnswerReview=true、strict=false、SemanticClarification=true。原连接、密钥引用、模型、检索参数未改。已运行应用若缓存配置，需要重启或重新载入设置。

reports/rag_support_graph_20261113/settings_before.json 是只读备份；rollback_flags.cmd 仅恢复本轮五项设置，不覆盖其他设置。备份中原本没有的开关回滚为旧有效值 false，不能直接删除键后又落到新默认 true。

## 验证设计

- A 用冻结旧代码、旧配置；B 用冻结新代码和新开关。每题经真实 AnswerService，检索本地模型调用串行，远程请求可并发。
- 同主生成 Prompt 的 A/B Context 试验单列。完整 B 新增了计划/审核提示，所以端到端比较不是“所有请求 Prompt 完全不变”的单因素算法实验。
- 固定 B Context 重点 8 题各重复 3 次，普通生成与结构化生成分别保存。数字/范围/引用/事实集合对照，不把措辞变化自动判失败。
- 现有业务 Gold 判分保持原样；新增测试只检查机制。旧断言与本轮授权变化冲突时，保留失败并解释，不为了变绿改测试。
- 人工业务可用性、全量范围准确率、全候选相关性没有现成标签，只报告可验证代理指标和原始记录，不捏造百分比。

## 尚需谨慎解释的能力边界

- 字段词法线索不等于语义完整性；部分词法类型可能未覆盖，最终由原文审核判断。
- 只对显式结构关系建图，跨页仅相邻时保持不确定；不会猜测两个页面属于同一业务分支。
- 数值角色只保留原文，不计算单位换算或推断型号别名。
- non-strict 的兼容回退能避免全局失效，但没有通过语义审核的初稿只能明确标为未审核，不可称为已验证答案。
- 完整业务验收是否通过见本轮 report.html 和 final_acceptance.json；配置已启用并不表示已经通过。
