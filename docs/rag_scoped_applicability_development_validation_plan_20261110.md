## 2. 采用的设计原则

### 2.1 条件只作用于它所属的问题分支

问题表示必须能区分：整题共享条件、某一分支专属条件、共享的现象或比较指标，以及无法确定的关系。

040 的“所有项目”只属于第二分支；前半句的具体项目举例不能自动复制进第二分支。“重复性”是后半句省略但仍承接的指标，需要保留引用前文的关系。

结构中的业务属性允许来自问题本身，不能再把报警、阶段、机型、单个/多个项目等有限枚举当成全部业务。型号、方法、环境、版本、运行状态、数值范围都只是可能的属性；无法识别的属性保留原文和未知状态。

拟定的内部结构至少包含：

| 字段 | 用途 |
|---|---|
| `branch_id` | 指明条件属于哪个分支，不使用测试题号 |
| `question_spans` | 回溯用户原话及字符位置 |
| `global_conditions` | 明确共享的条件，不能靠猜测加入 |
| `local_conditions` | 当前分支的条件、否定、比较及假设关系 |
| `shared_references` | 省略指标或对象引用前文的位置和理由 |
| `attribute` / `relation` / `value` | 可扩展的语义属性，不限定为几个业务类别 |
| `resolution_status` | 已确定、未知或解析失败 |

原文子串存在不等于语义完整。还要核对否定、范围、指标、单位及修饰对象是否保留。不能仅用“每个字都来自问题”作为通过条件。

### 2.2 条件检查要区别相关性、适用性和答案充分性

- **相关性**：这段资料是否讨论用户问的现象。已有模型重排提供这个信号。
- **适用性**：这段具体说明属于哪个对象和条件分支。
- **充分性**：这些实际引用能否支持本题需要表达的事实。由最终证据和回答核验判断。

目录、项目列表、常规检测步骤中出现“所有项目”或“样本”，只能证明有这些词，不能直接证明支持当前故障处理。

拟定排序规则：先处理有依据的真实冲突；对其余候选保留现有模型重排顺序。UNKNOWN 不加硬性靠后分组，MATCH 也不能仅靠词项数量跨越相关性顺序。必要的正向适用性证明仍保留在记录中，用于后续核验。

这不是把 UNKNOWN 改成 MATCH，也不是取消所有条件检查。若无法证实适用，只能保留待核状态，不能据此断言某项操作一定适用。

### 2.3 冲突也必须绑定作用域

只有同一对象、同一分支、同一可比较属性上的明确互斥，才能作为硬冲突。资料中另一个对象或另一个条件分支的不同取值，不能用于排除当前证据。

一段资料如果同时说明两个条件，应分别建立局部绑定，不因其中一句与另一个分支不同而删除整段。只有所有相关用途都被明确排除，才可把它作为整段不适用处理。

证据判断至少记录：问题条件的原文位置、证据原文位置、所属对象/分支、支持/冲突/未知状态、可复查理由。模型置信度高、引文存在、同文件或同页，均不能单独授权硬删除。

### 2.4 本轮保持的边界

发布 bundle、原资料、Gold、题目状态、嵌入和重排模型、回答模型与模板、最终 8 段、单文件 3 段、12,000 字预算保持冻结。

行级补充、两阶段回答等历史候选维持当前实际启用状态，不恢复或叠加其他冻结方案。耗时不是本轮采用指标。

如果新的问题解释改变了派生的 `query_plan_summary`，必须归入条件层变量并保存实际请求差异；不能宣称两臂的生成输入完全相同。不得同时改写回答模板来补救失败。

## 5. 步骤 1：在固定候选上验证条件层，先不动召回

### 做什么

使用上轮保存的两个真实自动候选池：A 的重排输入/输出，以及 R0 的重排输入/输出。R0 含两段正确资料，适合验证下游；它不是可采用的生产基线。

从已保存数据重建候选和来源，不手工加入 Gold chunk。候选顺序、模型分数、正文和预算固定。先检查重建后的原条件层是否复现原来的第 7 和第 12/13 等位置。

每臂使用独立副本，清除旧条件判定、选文状态等下游派生字段后重算；不能让一个臂的排序或字段修改污染另一个臂。模型重排分数、来源和原重排顺序保持冻结。

开发条件层候选 C，进行三个有界局部对照：

| 局部对照 | 只改变什么 | 要回答的问题 |
|---|---|---|
| O | 对无明确冲突的候选保留原重排顺序 | UNKNOWN 的强制靠后是否直接造成证据丢失 |
| S | 条件附着于所属分支，保留原排序机制 | 整题统一条件是否导致误匹配或误排除 |
| C | S 与 O 合成的条件层修复 | 能否同时保住直接证据和真实冲突保护 |

这三个对照使用同一份输入，不各跑一轮全量回答模型。问题分支解析或必要的适用性辅助调用若使用当前模型，要单独记录提示、原始输出、输入跨度和次数；不能把“没有回答生成调用”写成“完全没有模型参与”。

现有题号和 Gold 只进入评测器，不进入 C。条件表示可以使用原文跨度和通用语义解析，但不能写“遇到 ALB/某报警/某题号就保护某页”。

### 开发检查

- 不同分支条件不得串用；共享指标必须能回指原问。
- 方法型问题允许列出条件路径，不因有多个分支自动要求追问。
- 相同词出现在其他对象、目录或表格其他行，不构成适用性支持。
- UNKNOWN 保持未知；明确且同作用域的冲突仍然有效。
- 否定、例外、版本和数值单位不被解析过程丢失。
- 多分支段落按局部用途判断，不全段误杀。
- 解析失败、超出适用范围、无分支的问题有可复现回退。
- 候选不读标签，不改变 source ID，不把未发送父块冒充实际引文。

### 完成标准与失败动作

在含两段的固定池中，C 必须把 040 两条引文完整送入现有预算的上下文；不新增真实冲突误用；原有应保留事实不丢失。

如果只改排序就有收益，记录该因果结果；不能据此跳过条件作用域保护。若 C 本身失败，本轮停止扩大实验，完成失败分析与报告；不改召回、TopK 或回答提示来弥补 C 的失败。

产物：`condition_unit_tests.xml`、`fixed_pool_ablation.jsonl`、`condition_bindings.jsonl`、`evidence_changes.md`。

## 6. 步骤 2：修复分支规划契约，再做四臂静态组合

步骤 1 通过后才执行。上轮 R0 的代码和报告完整保留，不覆盖历史结果。

### 做什么

1. 冻结一份只从用户原问生成的条件结构。C 和分支检索共享这份结构，不各自把同一个问题解析成不同含义。
2. 把分支转成自包含查询 R1：只继承确有原文依据的共享指标/对象，不继承前一分支的局部例子，不加入答案词。
3. 专门验证“省略的指标是否找回”；不能再次仅检查文本片段是否来自问题。
4. R1 与 R0 的实际查询、候选差异单列。R1 是新版本，不能把 R0 的历史结果算成 R1 的验证。
5. 保留原问查询，使用同一通道预算和融合公式。候选并集合并及其先验变化要透明记录。

### 四个对照

| 臂 | 召回 | 条件层 | 用途 |
|---|---|---|---|
| A | 当前原问召回 | 当前条件层 | 唯一生产基线 |
| R | 新分支召回 R1 | 当前条件层 | 看召回单独贡献与副作用 |
| C | 当前原问召回 | 新条件层 C | 看条件修复单独贡献 |
| R+C | R1 | C | 看缺失资料补齐后能否保留到实际上下文 |

同一问题的规划结果在四臂间固定；不因某臂效果差重新让规划器作答。只有指定的消费者使用新结构，避免把四臂实际变成四种不同解析。

040 的可解释预期是：C 能保住原来已有的分支，但不承诺补出未召回的另一段；R+C 才有机会同时得到两个分支。是否成立以实际结果为准。

### 静态范围与门槛

先在 D 执行，再覆盖固定 48 道正式题和 42 道历史回归题。这个阶段运行检索、重排、条件检查和上下文构建；暂不生成回答。

逐题保存：触发状态、条件绑定、每层排名、进入/退出原因、最终 included_text、来源和引文覆盖、候选新增与移除。相同来源可以复用但不能混算独立重复。

通过要求：

- 040 的两个必要分支均有实际正文及正确来源绑定；不使用第 15 张替代。
- 三道原保护题无新增错对象；其他原正确必要事实无已确认丢失。
- 新增的相似条件、错对象、不同方法或版本负例未被当成支持。
- 预算仍符合原设定，候选不是靠扩大上下文通过。
- 局部改善、无触发、无改善、退步能分别列出。

出现任一已确认的必要事实丢失、分支颠倒或错对象使用，该臂失败，不进入采用。另一臂如通过则可继续它的验证；不得因组合失败把有独立证据的 C 一并丢弃，也不得只因 C 通过就宣称 040 已修好。

## 7. 步骤 3：通过静态门槛后，验证真实回答

### 小集与完整回答流程

在 D 的最多 8 个业务组上，A 与通过门槛的候选各运行 3 次，按预定顺序交替。使用真实 AnswerService 入口，保留正常澄清、拒答、引用校验和答案复核行为。

候选选择规则预先固定：优先选择能够解决目标缺口且通过保护检查的最小组合；如果 C 单独足够，不叠加 R。R+C 才能修复 040 时，只把通过静态门槛的 R+C 送入回答阶段。

不调用所有失败臂的回答模型，也不在 040 答对后立即宣称通过。

### 判什么

- 是否回答用户真正问的每个必要分支。
- 是否把条件、对象、方法、顺序或单位说反。
- 是否把可能原因写成唯一确定原因。
- 每个关键断言实际引用的正文是否支持它；不能用答案没引用的资料补证。
- 是否出现多余的强制追问或本可回答却拒答。
- 是否把可选背景当成必答，导致得分看似提高。

040 至少要求三个重复均覆盖两种条件下的必要判断、引用对应正确、没有新增无依据断言。其他题的新错误不能用 040 的收益抵消。

自动裁判输出与人工式逐条引文复核分别保存；结果只能称自动判定和证据核验结果，不能冒称业务人员已审。

传输异常最多重试两次，保留全部尝试；质量差的回答不重试到满意。规划/检索/生成/判分故障分开记录。三个重复中若存在未完成调用，不能记为 3/3。

## 8. 步骤 4：独立验收与完整回归

### 独立验收

若 H 结果用于改规则，这批 H 立即变成开发/回归数据。本轮验收结论失败，不能继续在同一批数据上调好后称独立通过。

### 全量回归

对预先定义的“首轮两臂不同、裁判与引用核验不一致、未完成或存在不确定项”，各补到 3 次。复测规则在看到结果前冻结，不只重跑候选失败的题。预算上限是每题每臂 3 次；达到仍无法判断则列待核实，不继续无限重复。

分别报告：

1. 固定正式 48 题：逐题及按 group 汇总。
2. 历史回归 42 题：影子结果。
3. 新 H：独立影子结果，状态 pending。

不把题数变化、重复次数或同一问题的改写数量当成算法收益。必要时列出“哪一层改善了但最终回答没改善”的情况。

- 040 必须在完整入口下稳定改善，不能仅以召回率代替答案正确。
- 固定集合中无新增已确认的错对象、关键事实丢失或条件颠倒；任何已确认实质性退步均阻止本版本采用。
- 独立触发题须出现可复核收益，并至少涉及两个不同来源的业务组，才能提出跨业务有效的结论。
- 如果独立样本未触发或基线已经全对，只能说明没有观察到退步，不能声称证明了泛化收益。
- 所有来源争议、模型执行失败和裁判分歧单列；不能通过修改 Gold 消除它们。
- 小样本通过仍不等于“所有未测问题不受影响”，结论要说明已覆盖范围。

“已确认退步”需要实际回答、对应引用、两臂对照和预定复测记录共同支持；不能仅凭一次自动裁判标签认定。所有质量失败都保留，不得用择优挑选的重复结果掩盖退步。

## 9. 步骤 5：达到门槛后做最小集成与回退验证

原型先放独立工具中；以下生产位置只在对应证据通过后按需修改，不预先整批重写：

| 位置 | 可能需要的最小变更 |
|---|---|
| `rag/models.py` | 可选的分支作用域及来源绑定字段，兼容旧构造 |
| `rag/query_interpreter.py` / `query_analyzer.py` | 保留原话条件的归属，不把局部条件变全局 |
| `rag/constraint_matcher.py` | 局部适用性判定、真实冲突处理、去除 UNKNOWN 硬性靠后 |
| `rag/evidence_policy.py` | 核实必要条件门禁使用相同的作用域；不增加段数或放宽阈值 |
| `rag/answer_service.py` | 通过受控入口接入已通过的机制和诊断记录 |
| 检索适配位置 | 只有 R1 也通过时才接入；保留候选来源和预算 |

新增字段不能破坏历史 JSONL、trace、报告或缓存。调试信息和实际结果分开，不写回 Gold。

集成后核对：

1. 开关关闭：原行为、正文和来源顺序恢复，不能只说最终文字“大致一样”。
2. 开关打开：关键案例和触发/冲突代表题与已通过的候选一致。
3. 解析失败、空分支、辅助模型不可用和取消任务：有完整错误记录及明确回退。
4. 单元、集成、真实入口检查均完成；候选通过不自动等于生产接入通过。
5. 最终再核对索引、Gold、模型配置、原文件和非本轮代码的哈希。

Git 提交或合并、默认启用与“建议采用”分开说明，按当时用户授权执行。本轮规划本身没有做生产接入。

## 10. 单轮工作量与停止规则

- 不重复原资料已存在、原排名缺口已定位的旧诊断，除非输入变化。
- 局部 O/S/C 只在固定候选上做隔离，不各跑一轮全部回答。
- 四臂比较先看实际证据。只有通过的最小候选进入回答阶段。
- D 最多 8 组、H 目标 12 组，各臂 3 次；完整 90 题先各 1 次，仅按预定规则补测，最多每臂 3 次。
- 静态失败就完成失败报告；不扩大段数、换模型或追加业务词典救分。
- 独立验收失败就结束该版本；有新证据才另开下一版本，不能覆盖本轮失败记录。
- 某个阶段通过后自动继续执行已满足条件的后续阶段，不每完成一步都向用户确认。只有确切的业务资料矛盾才列具体问题，其他检查照常完成。

## 11. 最终交付清单

独立运行目录建议：`reports/rag_scoped_applicability_<日期>_<runid>/`。

必须包含：

- 输入冻结、代码变更及执行日志。
- O/S/C 固定候选消融与四臂静态对照。
- 每题新增、移除、保留和截断的实际正文；必要事实与对象绑定结果。
- 分支规划、共享信息继承及适用性判断的可追溯记录。
- 完整实际回答、真实请求配置/提示哈希、引用及独立判分。
- 正式、历史回归、新独立集合的分开统计，全部改善/退步/待核实清单。
- 集成、关闭开关及失败回退核验。
- 最终采用决定与结束哈希。

最终报告必须作出明确区分：

| 结果 | 可以说什么 |
|---|---|
| C 有跨题收益，R+C 失败 | 条件层可按验证范围考虑采用；040 尚未完整修复 |
| R+C 只改善 040，独立题无证据 | 仅局部有效，不建议通用启用 |
| 静态证据改善但实际回答未改善 | 未达到本轮目标，不把中间指标当成功 |
| 实际回答、独立样本、回归与集成全部通过 | 在已验证范围建议采用，并说明样本局限 |
| 任一关键门槛失败或证据不足 | 暂不采用，指出具体最早失败层和已有证据 |

本计划的结束点是有证据的采用决定，而不是“再提出一个实验”。
