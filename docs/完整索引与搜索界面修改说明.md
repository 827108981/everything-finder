# 完整索引与搜索界面修改说明

本轮修改以“搜索结果必须建立在完整索引上”为原则。

## 完整索引门槛

- 视频文件不做内容解析，只登记文件名和路径，并单独统计为“排除视频”。
- 视频不计入可解析文件分母，也不进入失败清单。
- 只有全部可解析文件状态均为 `success`、全文索引不脏、没有运行中的索引任务时，搜索才可用。
- `partial_success`、`converter_missing`、`ocr_disabled`、`failed_retryable` 等状态都会阻止搜索。
- 未成功文件产生的正文块不发布到可搜索索引。

## 无进展超时

- 删除固定的 120 秒单文件总耗时上限。
- 解析器按页、ZIP 成员、内容块、缓存哈希和 Office 转换阶段上报语义进展。
- 只有进展序号在设定时间内没有变化，才判定为无进展；日志刷新、文件时间变化等不算有效进展。
- 默认无进展阈值：普通 300 秒、Office/PDF 进程 300 秒、OCR 900 秒、ZIP 900 秒、老版 Office 1800 秒。
- 最多自动重试 3 次；PDF 和 ZIP 从已确认检查点继续，其他格式安全重启当前文件。
- 连续失败后保留明确的 `PARSE_NO_PROGRESS` 诊断，完整索引保持未就绪。

## 老版 Office

- `.doc/.xls/.ppt` 依次尝试 Microsoft Office COM、WPS Office COM 和 LibreOffice。
- 原文件始终只读，转换产物写入临时目录或内容哈希缓存。
- 区分无效 OLE、转换器缺失、打开失败、保存失败和未生成输出文件。

## 搜索和界面

- 中文查询自动忽略空白差异。
- 中间结果卡取消固定高度上限，完整显示路径和日期；超过 3 段的命中可展开。
- 右侧预览对当前搜索词使用与中间结果一致的黄色高亮。
- 搜索历史按钮改为系统图标，无历史时隐藏，避免与清空按钮或输入区重叠。
- 索引进度显示当前阶段、处理单元、距上次有效进展时间、重试次数和视频排除数。

## 搜索结果易用性固定需求

以下需求作为搜索界面改造的固定验收项，本轮按此实施并进行针对性冒烟验证，不跑原始数据集。

1. **候选文案明确**：普通用户界面不再单独显示容易误解的“候选”数量。结果区优先显示“找到 N 个文件”；诊断详情中如需保留该指标，明确写成“校验索引记录 N 条”，并说明一份文件可能对应多个正文块。
2. **结果数量口径明确**：区分最终文件数、正文命中次数、OCR 命中次数和 OCR 疑似命中数量；若结果数量不是完整统计值，必须标明“已显示前 N 条，可能还有更多”，不得把候选记录数当成文件数。
3. **命中位置可点击定位**：文件名下的“正文·第 N 页/工作表/幻灯片”等位置文本，以及右侧预览中的对应位置，均可点击执行“打开并定位”。PDF 优先定位到页码；Office、压缩包成员和不支持外部定位的格式提供明确降级提示，并保留打开文件和打开所在文件夹操作。
4. **OCR 选项可理解**：“包含 OCR”和“显示 OCR 疑似命中”提供悬停说明。未勾选疑似命中时只显示达到最低置信度的 OCR 结果；勾选后显示低置信度结果，并在结果卡和预览中同时标注“OCR 置信度”和“疑似匹配”。

## 文件信息与排序需求

- 搜索页采用“左侧结果列表、右侧命中详情”的主从布局。左侧只显示文件名、格式、路径、大小、修改时间、命中数量和可点击命中位置，不展示正文片段，避免列表拥挤。
- 右侧显示当前文件的全部命中上下文，不设置“展开全部/收起命中”控件；内容超过面板高度时使用鼠标滚轮滚动查看。
- 点击命中位置后必须按格式定位并反馈结果：PDF 定位页码，Word 定位正文段落/表格行，Excel 定位工作表和行，PowerPoint 定位幻灯片，文本定位行号。Office 定位后需反查当前位置，校验一致才显示“已定位”。
- 对压缩包成员、图片或本机缺少支持定位的阅读器等情况，只允许提示“文件已打开但未定位”，不得显示定位成功。
- 结果卡片和右侧文件预览固定显示文件大小、最后修改时间；大小使用适合阅读的 B/KB/MB/GB 单位，时间使用本地时间。
- 结果列表提供排序菜单：相关性（默认）、修改时间最新/最早、文件大小从大到小/从小到大、文件名升序/降序。
- 排序必须在当前筛选范围内生效，并保持稳定的次级排序规则；同一排序键相同时按相关性、修改时间和完整路径依次决胜。
- 文件大小和修改时间使用索引中的文件元数据；文件发生变化后由增量索引刷新，界面不得显示未更新的旧值而不作提示。
- 排序切换不得改变搜索条件、OCR 选项和当前范围；无结果或索引未就绪时排序控件禁用。

## PowerPoint 命中位置定位故障确认与修复需求

### 已确认问题

- 现场文件 `E:\MRCODE\化免\生化资料\全线生化\10-学习参考资料包\生化场景化培训教材-液路_1.0.pptx` 已成功索引，数据库中的第 46 张命中记录为 `location_text=第 46 张幻灯片`、`slide_number=46`，因此不属于索引错误，不需要重新索引。
- 当前页码提取逻辑能够把“第 46 张幻灯片”和“正文 · 第 46 张幻灯片”正确解析为数字 `46`。
- 实际失败发生在 PowerPoint 定位阶段：本机 `POWERPNT.EXE` 存在，但 `PowerPoint.Application` COM 自动化对象无法创建，现场验证出现 `0x80070490`（找不到元素）和 `0x80040154`（COM 类未注册）。
- 当前实现只调用 `DispatchEx("PowerPoint.Application")`。COM 在文件打开前失败时返回空结果，界面随后退化为普通打开文件，并错误显示“当前格式或本机阅读器不支持指定位置定位”，没有暴露真实原因。
- 左侧命中位置与右侧命中位置最终使用同一个定位函数，因此 COM 自动化不可用时，两侧都会无法定位；不能把该问题判定为单独的右侧控件故障。

### 修复要求

1. 搜索结果模型必须携带结构化位置字段，包括 `page_number`、`slide_number`、`sheet_name`、`cell_start`、`cell_end`、`line_start` 和 `line_end`。打开定位优先使用结构化字段，`location_text` 只用于显示和旧数据兼容。
2. 左侧结果卡中的命中位置链接和右侧预览中的命中位置链接必须调用同一定位入口，并传递完全相同的结构化位置数据。点击任一侧的“正文 · 第 N 张幻灯片”都必须打开文件并定位到对应幻灯片。
3. PowerPoint 定位按“已有活动实例、`Dispatch`、`DispatchEx`”顺序尝试 Microsoft PowerPoint，同时增加 WPS `KWPP.Application` 兼容；不得关闭或终止用户自己打开的 PowerPoint/WPS 实例。
4. 成功调用 `GotoSlide` 后必须读取实际 `SlideIndex` 反查；只有实际页码等于目标页码时才显示“已定位到第 N 张幻灯片”。
5. COM 不可用、Office 注册损坏、目标页不存在或文件打开失败时，必须记录 ProgID、HRESULT、异常阶段和目标页码。界面应提示“文件已打开，但 PowerPoint 自动化接口不可用，未能定位到第 N 张”，不得笼统显示“格式不支持”。
6. 所有定位失败都必须允许普通打开文件，但普通打开不得冒充定位成功。
7. 右侧底部“打开文件”按钮只负责普通打开文件，不参与命中位置定位，也不得改名为“打开并定位”。定位操作只由左右两侧可点击的命中位置链接触发。
8. 使用上述现场文件至少验证第 29、34、46、63 张；左右两侧的命中位置链接分别点击，实际 PowerPoint 页码必须一致。
9. PDF、Word、Excel、PowerPoint 和文本文件同步检查左右命中位置链接是否一致，防止其他格式出现一侧能定位、另一侧不能定位的问题。

## 数据库位置迁移需求

### 设置页

- 设置页增加“索引数据库位置”，显示当前数据库完整路径、数据库大小和目标磁盘剩余空间。
- 提供“选择目录”和“迁移数据库”操作。仅修改文本框不得立即切换数据库，必须经过确认和完整迁移流程。
- 数据库目录默认仍为 `%LOCALAPPDATA%\LocalFullTextSearch\data`，未主动迁移的旧用户继续沿用原路径，升级后不要求重新索引。
- 目标位置必须是本机固定磁盘上的可写目录；网络共享、不可用的移动盘、程序安装目录和权限不足的目录应拒绝或明确警告。

### 迁移流程和进度

1. 迁移前暂停并禁止新的索引、搜索、数据库更新和失败文件处理任务。
2. 检查所有数据库连接和程序进程，执行 WAL checkpoint，确认数据库可以安全迁移。
3. 检查目标空间，至少满足数据库及其临时文件所需空间，并预留校验和回滚余量。
4. 迁移使用临时目标文件或 SQLite Backup API，不允许直接复制正在写入的数据库文件。
5. 进度条至少显示“准备、传输、完整性校验、切换路径、重新打开、完成”六个阶段；传输阶段按已处理字节显示进度。
6. 目标库必须通过 `PRAGMA integrity_check`、数据库版本、关键表、索引范围数量和可搜索状态校验后才能切换。
7. 切换失败时继续使用原数据库；迁移成功并完成重新打开校验后，才允许清理迁移临时文件。
8. 正常完成后只保留一个活动数据库。回滚备份应明确标记、可人工恢复，并提供清理规则，不能长期产生多个来源不明的活动数据库副本。

## 数据库地址持久化（已实现）

- 数据库实际位置保存在独立于 EXE 安装目录的用户级配置文件 `%LOCALAPPDATA%\LocalFullTextSearch\config\database-location.json`，程序升级或更换目录不会覆盖该地址。
- 新版本在创建 `DatabaseManager` 前统一解析该配置；有效迁移地址继续使用原索引，无须重新索引。
- 配置缺失或损坏时回退旧默认路径 `%LOCALAPPDATA%\LocalFullTextSearch\data\search_index.db`；不会根据 EXE 所在目录推导数据库位置。
- 迁移切换使用临时配置和原子替换；只有 `migration_state=verified` 的地址可成为活动数据库。
- 未列入本轮交付范围的旧版本路径兼容、安装和降级方案均已删除。

## 应用单实例与重复启动需求

### 目标行为

- 同一 Windows 用户会话下只允许一个应用主实例运行。用户连续双击 EXE、重复点击快捷方式或在程序启动较慢时再次启动，都不得出现两个主窗口、两个后台索引任务或两个进程同时写入同一个数据库。
- 第二次启动检测到已有实例后，不再初始化数据库、索引器、OCR、Office 自动化或后台 worker；应将已有主窗口恢复、置前并获得焦点，然后由第二个进程正常退出。
- 已有窗口最小化到任务栏、被其他窗口遮挡或处于设置页、未成功索引页时，重复启动仍应激活同一个窗口，不创建新的窗口。
- 已有实例正在索引、搜索、迁移数据库或执行保底完成时，重复启动不得中断、重置或重复提交当前任务。

### 实现和异常处理要求

- 单实例互斥必须在创建数据库连接和启动后台任务之前完成；锁的作用域至少包含当前 Windows 用户和应用标识，不得仅依赖窗口标题判断。
- 第二个进程与主实例之间只传递“激活并置前”请求，不得直接操作数据库。主实例收到请求后在 UI 线程恢复并激活窗口。
- 应用异常退出后不得留下永久阻止启动的无效锁。操作系统互斥对象、命名管道或本地套接字失效时必须能够在确认原进程不存在后安全恢复。
- 检测、激活和退出过程必须写入启动日志，至少记录当前 PID、已有实例 PID（可获得时）、检测结果、激活结果和失败原因；不得记录数据库内容或用户文件正文。
- 如果已有实例存在但窗口激活通信失败，第二个进程应提示“程序已经运行，请在任务栏中打开”，随后退出；不得静默再启动一个可写数据库的新实例。

### 验收条件

1. 快速连续启动 EXE 两次和五次，始终只有一个主窗口和一个持有活动数据库的应用进程。
2. 主窗口正常显示、最小化、被遮挡及正在执行后台任务四种情况下重复启动，均激活原窗口且任务不重复。
3. 模拟应用正常退出和异常结束后重新启动，均能获得新锁并正常打开，不需要用户删除锁文件。
4. 检查启动日志，能够区分首次启动、重复启动激活成功和重复启动激活失败三种结果。

## 设置页布局与信息密度优化需求

### 已确认问题

- 当前设置页在宽屏窗口中把标签放在内容区左侧、控件和值集中到最右侧，形成大面积无效空白；右侧数据库路径、大小、schema、磁盘空间、目录选择和状态纵向堆叠，路径容易换行，局部拥挤且对应关系不清楚。
- 数据库信息与操作没有形成稳定的阅读顺序，用户难以快速判断“当前数据库在哪里、目标目录是什么、是否可以迁移、迁移状态如何”。
- 搜索体验、OCR 和索引设置的控件贴近最右侧，标签与控件距离过大；在较窄窗口下又容易挤压或截断。

### 布局要求

- 设置页主体使用居中且有最大宽度的内容区，不随超宽窗口无限拉伸。建议有效内容宽度控制在约 960 至 1200 像素，并在小窗口下自适应为单列滚动布局。
- 每个设置分区使用统一的标签与控件网格：标签列宽稳定，控件紧邻标签，输入框、下拉框和数值框设置合理的最小/最大宽度，不再贴到窗口最右边。
- “索引数据库”区域按以下顺序纵向组织：当前数据库、目标位置、迁移操作、迁移状态。各行保持左对齐，信息和值不得分散在区域两端。
- 当前数据库完整路径单独占据主要宽度，默认单行省略并提供悬停完整路径和复制入口；不得因路径自动换行而把后续信息压成窄列。
- 数据库大小、schema 版本、当前磁盘和可用空间作为一组紧凑摘要横向排列；窗口不足时按完整信息项换行，不得拆断单个标签和值。
- “选择目录”和“迁移数据库”紧邻目标目录显示；未选择目标目录时迁移按钮禁用，并在同一区域直接显示原因。
- 迁移状态和进度条放在迁移操作下方并占据可用宽度，显示当前阶段、已处理量和结果；未迁移时使用简短中性文案，不占用独立的远端列。
- 搜索体验、OCR 和索引设置继续按独立分区排列；二元选项使用复选框，数值使用数值框，模式使用下拉框，各控件与标签保持近距离对齐。
- “保存设置”固定在内容区右下角或底部操作栏，不得悬浮到超宽窗口最右边；滚动页面时不能遮挡设置项。

### 响应式与可读性验收

1. 在 1280x800、1920x1080 和当前宽屏窗口下检查设置页，数据库路径和操作关系清晰，不出现右侧局部拥挤、大面积无意义空白或控件贴边。
2. 使用长数据库路径、GB/TB 级剩余空间和较长迁移状态文案验证布局，文字可以整体换行或省略查看，但不得相互覆盖或挤出窗口。
3. 调整窗口宽度时，控件尺寸和行列结构保持稳定，不得因为动态内容导致按钮跳动、分区高度反复变化或横向滚动。
4. 键盘 Tab 顺序必须符合从上到下、从左到右的视觉顺序，焦点状态清晰；高 DPI 缩放下仍能完整显示标签、值和按钮。

## 未成功索引操作说明与保底开放需求

### 功能边界

- `重新尝试`与`保底完成并开放搜索`不是完全相同的功能，但二者的第一阶段存在重叠，界面必须明确说明差异，不能只依靠按钮名称或悬停提示让用户猜测。
- `重新尝试`只重新解析当前阻断文件，适用于文件已经修复、解密、解除占用或相关解析组件已经恢复的情况；该操作不得自动排除文件，也不得在仍有阻断项时强制发布索引。
- `保底完成并开放搜索`是最终兜底流程：先对全部剩余阻断项执行最后一次正常恢复重试；仍然失败时再次列出文件并取得用户确认，随后排除这些文件、收敛残留任务和索引状态并开放其余文件的搜索。
- 当阻断项为 0，但仍存在残留任务、未完成批次、脏 FTS、候选索引未发布或其他 readiness 未收敛状态时，`保底完成并开放搜索`必须能够执行状态修复并开放搜索，不得要求用户先制造或选择一个失败文件。
- 保底流程排除文件时只改变当前搜索范围，不得删除、移动或修改源文件；被排除文件的文件名、路径和正文均不进入搜索结果，并可在`已人工排除`页恢复纳入后重新索引。

### 界面常显使用说明

“未成功索引”页面必须在页签或筛选区下方、操作按钮上方常显紧凑的“如何处理未成功索引”说明区，不得只把说明放在 tooltip、确认弹窗、使用说明 PDF 或日志中。说明文案固定为：

1. `重新尝试`：文件已修复、解密或相关软件已恢复时使用；只重新解析，不会排除文件。
2. `从当前索引范围排除`：确认选中的文件不需要搜索时使用；源文件不会被删除。
3. `保底完成并开放搜索`：先进行最后一次重试；仍失败时再次确认排除，然后开放其他文件的搜索。

说明区应保持一屏可读，不使用大段技术术语；可以采用三步横向说明或三行短说明，但不得挤压表格标题和主要操作区。

### 动态状态提示

操作说明下方必须根据当前真实状态显示一条直接可见的处理建议：

- 存在阻断项：`仍有 N 个文件无法解析。建议先重新尝试；确认无法修复后再排除，或使用保底完成。`
- 阻断项为 0 但索引尚未开放：`没有失败文件，但索引发布状态未完成，请使用“保底完成并开放搜索”修复。`
- 索引已经就绪：`当前索引已完成，可以正常搜索，无需处理。`
- 索引、排除、迁移或保底任务正在运行：显示当前任务名称和进度，并提示`正在处理，完成后可继续操作。`

状态提示必须来自统一 readiness 判断，不能只根据表格行数判断索引是否可搜索。

### 操作区布局和按钮状态

- `保底完成并开放搜索`按钮始终显示在表格上方的操作区，避免用户在异常状态下找不到最终兜底入口。
- `重新尝试`改为普通次要按钮，不再与保底操作同时使用主按钮样式；仅在存在阻断项且没有互斥任务运行时启用。
- `从当前索引范围排除`使用次要按钮样式，仅在至少选中一个可排除阻断项且没有互斥任务运行时启用。
- `保底完成并开放搜索`仅在索引尚未开放且没有互斥任务运行时突出显示并启用，包括“有阻断项”和“零阻断但 readiness 未收敛”两种状态；索引已经就绪时保持常显但使用中性禁用样式。
- 索引已经就绪时，上述三个处理按钮全部禁用；正常的增量更新或全量更新应从“索引管理”页面发起，不复用`重新尝试`按钮。
- `导出明细`和`打开日志目录`属于诊断工具，应与三个处理操作在视觉上分组；空间不足时可放入独立工具区或`更多`菜单，但不能隐藏保底入口。
- 所有禁用按钮必须提供与当前状态一致的简短原因，但 tooltip 只作为补充，不能替代页面中的常显说明和动态状态提示。

### 保底流程确认文案

保底流程必须分两阶段确认，不允许第一次点击就直接排除文件：

1. 第一次确认显示：`将先对全部阻断项进行最后一次重试，不会立即排除文件。`同时显示待重试数量；用户取消后不得修改任务、文件状态或 readiness。
2. 最后一次重试后仍有失败文件时，第二次确认显示：`以下文件仍无法解析。确认排除后将开放搜索；源文件不会删除，但这些文件的文件名、路径和正文不会出现在搜索结果中。`同时显示失败数量、可展开路径和失败原因。
3. 第二次确认取消后保留现状，不执行排除，不把索引错误标记为已完成；用户仍可单独重试、选择排除或导出明细。
4. 用户确认排除后，排除、残留任务收敛、FTS 修复或发布、readiness 更新必须使用现有原子事务或可恢复发布流程；失败时整体回滚并明确提示，不能出现界面显示完成但仍无法搜索的半状态。
5. 零阻断但 readiness 未收敛时，不显示文件排除确认，只确认将修复残留状态并开放搜索；修复过程不得新增人工排除记录。

### 验收条件

1. 构造至少两个阻断文件，验证`重新尝试`只触发解析重试，不新增人工排除记录，失败后搜索仍保持未开放状态。
2. 在相同场景执行`保底完成并开放搜索`，验证先重试、后进行第二次排除确认；取消第二次确认时数据库和 readiness 不变。
3. 确认第二次排除后，验证源文件仍存在、排除记录可追溯、被排除文件不可搜索、其他已完成文件可以搜索，并且应用重启后状态保持一致。
4. 构造阻断项为 0 但存在残留任务或未发布候选的状态，验证保底按钮启用，完成后索引可搜索且没有新增排除记录。
5. 验证“有阻断项”“零阻断未就绪”“索引已就绪”和“任务运行中”四种界面状态，常显说明、动态提示、按钮名称、按钮样式和启用条件均符合本节要求。
6. 在 1280x800 和常用宽屏分辨率下检查说明区、操作区和表格，不得出现文字截断、控件重叠、横向挤压或必须滚动后才能找到保底入口的问题。
