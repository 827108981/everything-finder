## 兼容与开关

`rag_query_plan_enabled=false` 保持不变。新增 `rag_structured_answer_enabled=false`，只有 Adapter 实际激活且该开关开启才走两步生成。没有修改持久化用户设置，也没有简单打开旧 answer review 开关。

`QueryPlan.parsed_request` 提供 intent/entities/scope/constraints/requested_fields/ambiguity/answer_mode/query_variants；保留旧字段。answer_mode 是问题层面的请求模式，不能在没有证据时宣称可答或拒答。证据充分性继续由后续环节决定。

范围与对象缺失时使用 unknown，不当成已证实相同。事实合并要求字段、对象、范围、条件均一致；未明确对象/范围的事实局限于原来源。不同范围拆开，同范围不同值标记冲突，不用文本相似度代替关系证据。

## 生成核验的两轮区别

v1 错误地要求条件/范围概括也必须逐字出现在短引文中。v2 只对原文引文做逐字核验；对条件与范围的忠实概括交给独立语义审查，并要求逐条审查 text、object、scope、conditions。两轮原始结果均保留，v2 使用新文件而非覆盖失败结果。

仍保留的硬检查包括实际 Context 引文存在、数字和标识符来源、可能原因不能写成已确认故障、明确型号范围不能删除、未请求的更换结论不能添加。只有全部检查允许的主张才渲染，不再让第二次自由生成增加新事实。

这些检查仍有误伤：一条短引文只摘处理动作，行首编号在同一证据中但未被一并引用，会被删掉；方法问法若未识别到请求字段，会漏掉本来应该回答的条件分支。报告没有将这些失败隐藏为资料缺失。

## 验证协议

1. 91 题原生检索 A/B，使用同一已发布 AI bundle，保存全部阶段候选、排除原因和实际 Context。
2. 相同系统 Prompt、模型及参数，对 A/B 的实际 Context 分别生成并使用未修改的裁判。两侧均去掉动态 QueryPlan 指令，隔离 Context 变化。
3. 同一 B Context 分别进行原生成、结构化 v1、结构化 v2，全量结果分开报告。
4. 预先固定的 8 道重点题，各重复 3 次原生成和 v2，共 48 次。保存数值、引用、范围、确定性和主张集合；不以文字表面相似判定稳定。
5. 8 道重点题另走真实 AnswerService + 两步生成，验证连接实际生效。这与固定 Context 消融是不同实验。
6. 关闭兼容：91 题解析逐项一致；重新执行关闭模式 BM25，并对相同已保存重排候选回放约束、证据门禁和 Context。没有把这项回放冒充重新运行所有向量模型的端到端证明。
7. 现有单元测试不删除、不改断言。新语义不再满足旧平台共识/邻页规则等测试时，完整报告失败。

原请求同时要求“重构生成”和“A/B Prompt 不变”；因此生成重构单列消融，不能把它和 Context 对比合并成一个总增益。

## 已确认的主要缺口与下一步

1. **文档结构关系缺失。** 删除相邻页场景继承后，正文只写原因的后续页失去语义连接。下一轮需要从文档结构获得可验证的共享章节/表格/场景锚点，不能恢复固定邻页或固定题目保护。
2. **选段仍重数量限制、轻答案字段覆盖。** 同文档配额能挤掉定义、额定值等必要事实。下一轮应对已核实对象及范围内的不同字段做有界覆盖选择，而非增大每文档段数或保护所有精确命中。
3. **主张绑定单位过短。** 字符串检查只有短引文，无法利用经过核验的完整表格行关系。下一轮应让引文引用原始行跨度与表头，主张绑定到同一结构化记录；未知关系继续不确定。
4. **方法问法解析与步骤关系不充分。** 不应把“何时采取甲、何时采取乙”误当成未请求的操作。需要通用请求字段覆盖和显式流程关系，不把原文排列顺序自动当成必要先后。

以上问题不能靠改 Gold 解决。本轮验收结论以报告为准；未证明无退化前，两个开关都应保持关闭。
