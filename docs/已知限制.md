# 已知限制

- OCR 准确率受图片清晰度、倾斜、手写和模型影响，不能保证百分之百准确。
- PaddleOCR 未安装时，图片和扫描 PDF OCR 会记录为依赖缺失。
- 程序位于中文路径时，Paddle 模型会在首次 OCR 时额外复制约 140 MB 到 ASCII 缓存目录，以规避其 Windows C++ 推理层的 Unicode 路径限制。
- 加密 PDF 没有密码时无法提取正文。
- Word 页码无法通过 python-docx 准确获得，第一版只显示段落、表格、页眉页脚位置。
- 老版 DOC/XLS/PPT 第一版记录为暂不支持。
- Office 文本框、SmartArt、嵌入对象不保证完整提取。
- Office COM 精确定位、PDF 页内坐标高亮和搜索结果导出仍是后续增强。
- 文件变化监控默认关闭；启用后采用去抖增量扫描，启动时补偿扫描仍适合网络盘等不稳定目录。
- 正则表达式会流式检查满足范围筛选的内容；复杂或灾难性回溯表达式仍可能明显变慢。
- 当前解析采用普通、OCR、ZIP/老版 Office 三类独立线程通道，并为大型 DOCX/XLSX 设置独立进程池；数据库仍由主进程单写入路径批量提交，以符合 SQLite 单写者特性。
- 运行中的大型 Office 子进程不会接收线程取消令牌；取消扫描会阻止新任务提交，但需要等待当前文件解析结束后才能完整回收进程和临时结果。
