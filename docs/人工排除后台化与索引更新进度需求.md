# 人工排除后台化与索引更新进度需求

## 1. 背景

当前“从当前索引范围排除”操作由主界面线程直接执行。排除文件时，程序需要更新排除审计、删除不可搜索的 FTS 记录；当排除后没有剩余阻断项时，还需要重建 `content_fts` 和 `files_fts`。

在大型资料目录中，这些 SQLite 操作可能持续数十秒或数分钟。由于操作期间主界面线程被占用，窗口会显示转圈或“未响应”，用户无法判断程序是否仍在工作。

相关现有入口：

- `local_full_text_search/ui/main_window.py` 中的 `exclude_failed_files()`；
- `local_full_text_search/core/database.py` 中的 `exclude_files_from_index()`；
- `local_full_text_search/core/database.py` 中的 `_publish_current_scope_if_unblocked()`。

## 2. 目标

1. 将人工排除操作移到后台 worker 执行，主界面始终保持响应。
2. 在操作期间显示清晰的阶段状态和忙碌进度。
3. 保证排除、FTS 更新和索引就绪状态的事务一致性。
4. 排除失败、取消或程序关闭时，不产生半完成的可搜索索引。
5. 保留现有行为：只修改索引范围，不删除源文件；被排除文件的文件名、路径和正文均不得出现在搜索结果中。

## 3. 非目标

本需求第一阶段不要求：

- 对单条 SQLite 大型 `DELETE` 或 `INSERT ... SELECT` 提供精确百分比；
- 将 FTS 重建拆成可随时提交的多个独立事务；
- 重新解析源文件；
- 修改人工排除的审计结构和恢复逻辑。

## 4. 用户流程

### 4.1 开始排除

1. 用户在“未成功索引”页面选择一个或多个阻断文件。
2. 用户点击“从当前索引范围排除”。
3. 程序显示现有确认对话框，明确说明：
   - 源文件不会被删除；
   - 被排除文件不会参与文件名、路径和正文搜索；
   - 后台更新期间搜索和索引管理操作会暂时受限。
4. 用户确认后，立即启动后台排除任务。

### 4.2 操作期间

界面必须保持可拖动、可切换窗口和可关闭。页面显示：

- 主状态：`正在更新搜索索引...`；
- 当前阶段，例如：
  - `正在记录排除范围`；
  - `正在清理正文索引`；
  - `正在重建全文索引`；
  - `正在刷新索引状态`；
- 已处理文件数和总文件数（适用于排除审计阶段）；
- 当前是否正在执行大型 FTS 操作。

对于无法从 SQLite 单条 SQL 获得准确完成比例的阶段，使用忙碌进度条或阶段进度，不得显示误导性的精确百分比。

操作期间：

- 禁用“从当前索引范围排除”“恢复纳入”“强力完成”等互斥操作；
- 禁止启动新的索引任务；
- 搜索按钮可以禁用，或显示“索引正在更新，请稍候”；
- 防止重复启动相同的排除任务。

### 4.3 完成

后台任务成功后：

1. 原子提交排除记录和 FTS 变更。
2. 刷新失败文件、人工排除文件、统计信息和索引就绪状态。
3. 若当前范围已无阻断项，显示“当前索引已开放搜索”，并切换到搜索页面。
4. 若仍有阻断项，停留在“未成功索引”页面，并显示剩余阻断数量。
5. 恢复所有按钮和搜索控件的正常状态。

### 4.4 失败或取消

任务失败时：

- 回滚当前事务；
- 保留原有可搜索索引；
- 显示可读错误信息；
- 将详细错误写入日志；
- 恢复页面控件，不得留下永久的“正在更新”状态。

第一阶段只允许在安全边界取消任务。若 FTS 事务已经开始，取消请求应等待事务回滚完成，不得通过提交部分结果实现取消。

## 5. 后台任务设计

### 5.1 Worker 结构

复用现有 `ScanWorker` 和 `SearchWorker` 的 `QThread + QObject` 模式，新增人工排除专用 worker，例如：

```text
ScopeExclusionWorker
```

worker 至少提供以下信号：

- `progress(object)`：阶段、已处理数量、总数量、是否可取消；
- `finished(object)`：排除数量、索引状态和统计摘要；
- `cancelled()`：任务已安全回滚并取消；
- `failed(str)`：任务失败原因。

worker 必须使用自己的 `DatabaseManager` 连接，不得在线程之间共享 SQLite connection 对象。

### 5.2 处理阶段

后台任务按以下逻辑执行：

1. 校验选中文件状态和活动任务状态；
2. 写入 `index_scope_exclusions` 审计记录；
3. 清理不可见文件对应的 `files_fts` 和 `content_fts` 记录；
4. 若当前范围已经解除全部阻断项，重建并发布正文及文件名 FTS；
5. 更新 root、index run 和索引状态；
6. 提交事务并返回摘要。

所有影响搜索可见性的数据库变更必须在同一个原子事务中完成，或使用候选索引完成后再原子发布。任务失败时不得发布半成品 FTS。

### 5.3 进度语义

第一阶段采用阶段级进度：

| 阶段 | UI 展示 | 进度类型 |
|---|---|---|
| 排除审计 | 正在记录排除范围 | 文件数进度 |
| 删除不可见索引 | 正在清理正文索引 | 忙碌进度 |
| 全量 FTS 重建 | 正在重建全文索引 | 忙碌进度 |
| 文件名索引更新 | 正在更新文件名索引 | 忙碌进度 |
| 状态刷新 | 正在刷新索引状态 | 短暂确定进度 |

不得把“已经提交排除记录”显示为“整个索引已经完成”。只有 FTS 发布和索引就绪状态更新成功后，才允许显示完成。

## 6. 主窗口状态管理

`MainWindow` 增加排除任务状态，例如：

- `exclusion_thread`；
- `exclusion_worker`；
- `exclusion_running`。

需要新增以下处理入口：

- 启动排除任务；
- 接收并显示进度；
- 处理完成；
- 处理取消；
- 处理失败；
- 清理线程引用并恢复控件状态。

排除任务运行期间，其他会修改数据库或索引范围的操作必须被阻止。搜索读取是否暂时禁用由实现决定，但不能让用户看到未完成排除操作造成的混合结果。

## 7. 关闭和异常处理

用户关闭窗口时：

1. 若排除任务尚未开始事务，允许直接取消；
2. 若事务正在执行，先请求取消或中断 SQLite 语句；
3. 等待 worker 回滚并退出；
4. 超过关闭保护时间后，沿用现有强制关闭机制；
5. 下次启动时通过现有数据库恢复逻辑检查 `content_fts`、`index_state` 和排除审计的一致性。

禁止留下以下状态：

- 排除记录已提交但对应 FTS 没有清理；
- FTS 已清理但 root 被错误标记为 `ready`；
- `content_fts_dirty` 或 `full_batch_incomplete` 状态与实际 FTS 内容不一致；
- worker 已退出但 UI 仍显示任务运行中。

## 8. 日志和指标

每次排除任务至少记录：

- 任务 ID；
- 选中文件数量和实际排除数量；
- 是否触发完整 FTS 重建；
- 各阶段开始和结束时间；
- 总耗时；
- 数据库大小、正文块数量和 FTS 行数；
- 是否发生数据库锁等待、取消、回滚或失败；
- 最终 `ready` 状态和阻断数量。

日志不得记录完整正文内容。文件路径可按现有错误日志策略记录。

## 9. 验收标准

### 9.1 功能验收

- 点击排除后，主窗口不会进入 Windows“未响应”状态；
- 排除期间有持续的阶段状态提示；
- 排除后被排除文件不会被文件名、路径或正文搜索命中；
- 未排除文件仍可正常搜索；
- 排除最后一个阻断文件后，索引能够正确进入 `ready`；
- 排除失败或取消后，原有索引和排除审计保持一致；
- 源文件内容和源文件路径不被修改。

### 9.2 并发和稳定性验收

- 排除期间不能重复启动排除任务；
- 排除期间启动索引、恢复文件、强力完成等互斥操作会被阻止并给出提示；
- 关闭窗口后无残留 worker 或 SQLite 写事务；
- 数据库 `integrity_check` 通过；
- `content_fts` 与当前可见正文块数量和内容一致；
- 发生数据库锁或异常时，界面最终能恢复可操作状态。

### 9.3 性能验收

- 在大型测试数据库上执行排除时，主界面仍可响应窗口移动、页面绘制和取消请求；
- 进度或阶段状态至少每 1 秒更新一次；
- 不以固定秒数作为 80GB 资料的硬性完成承诺；
- 记录真实 FTS 重建耗时，为后续精确进度和分批重建优化提供数据。

## 10. 测试要求

新增或补充以下测试：

1. worker 成功排除并正确发布 FTS；
2. 排除最后一个阻断项时触发完整 FTS 重建；
3. 排除中途失败时事务回滚；
4. 排除中途取消时事务回滚；
5. excluded 文件搜索不到，included 文件仍可搜索；
6. UI 任务运行期间按钮状态正确；
7. UI worker 完成、失败、取消后线程引用和按钮状态均正确清理；
8. 大型数据库上验证主线程不执行阻塞式 FTS 重建；
9. 数据库锁竞争时能够记录等待和最终结果。

## 11. 实施顺序

### 第一阶段：后台化和阶段状态

- 新增 `ScopeExclusionWorker`；
- 将数据库排除调用移出主线程；
- 增加忙碌进度和阶段文本；
- 增加按钮互斥、成功、失败、取消和关闭处理；
- 补充 worker 和数据库一致性测试。

### 第二阶段：真实进度和可中断重建

- 将 FTS 重建拆成可观测的分批任务；
- 计算正文块或字节级进度；
- 支持安全取消和阶段恢复；
- 评估候选 FTS 表与原子发布方案；
- 增加 80GB 级别语料的压力测试和容量基线。
