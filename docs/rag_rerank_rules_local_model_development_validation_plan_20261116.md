# 重排修复：确定性规则与离线语义模型的开发、验证和采用方案

日期：2026-11-16。状态：待实施的完整方案；本次只核对现状并形成文档，没有下载新模型、修改业务算法或改变运行配置。

## 1. 本轮要解决什么

保留原辅助机制的两个目标：让真正提供答案的证据优先；避免重要原文被错误降级。替换当前有缺陷的实现依据：用“位置、参数、检查”等词判断是否回答了问题，以及按融合旧名次强制保护候选。

本轮目标是：固定已经召回的候选，改善重排及其送入后续流程的证据顺序。止于最终实际 Context，不调用远端答案生成 API，不评最终回答正确率。离线指令模型在本轮属于重排内部的语义判别器，不生成面向用户的业务答案。

只要正确证据没有进入固定重排入口，本轮就不能恢复它。Q019 处理页去重第30、未进入Top20的问题单列为入口问题，不能通过重排修复报功。条件检查和最终选段若再次损失正确证据，按实际环节定位，不反向要求重排为下游错误补偿。

## 3. 职责划分：规则做什么，模型做什么

| 事项 | 确定性规则 | 离线语义模型 |
|---|---|---|
| 标识符是否逐字匹配 | 核对原词、位置、边界；型号匹配本身不等于可回答 | 判断匹配词属于问题中的目标对象，还是旁支举例 |
| 表格/清单完整性 | 使用已有正文中的行列、表头、单位和边界；绑定不清标未知 | 判断这行是否回答当前问题、是否只提供部分信息 |
| 意义相近、用词不同 | 不继续扩充“出现某词就加分”的词表 | 区分“采集对象”和“安装位置”等关系 |
| 条件与动作 | 保存现有原文顺序、来源及完整条件；不自行补条件 | 理解启动/停止条件、前提、否定及处理分支 |
| 资料适用范围 | 保留正文、章节、文件名等不同来源的范围线索及依据强弱 | 判断本段的局部对象、条件与用户问题的关系；允许未知 |
| 判断结果是否有依据 | 检查引用是否来自本候选、字符位置是否正确 | 指出支撑判断的原句；不能使用模型常识补证据 |
| 硬删除证据 | 本轮不新增硬删除 | 模型不拥有硬删除权限 |

不维护完整领域词典，不写题号、特定页码、正确答案或特定文件路径的业务分支。规则可以识别通用的编号、数字单位和表格边界，但不把“有数字”自动判为参数答案，也不把“有步骤”自动判为处理答案。

本轮规则只识别已能可靠绑定的结构。纯文本恢复不出表格行列时保持未知，不能凭文本距离将别行数值配给目标型号。需要新索引结构或回读相邻页的情况登记为后续资料处理需求，本轮不偷偷扩大模型可见资料。

## 4. 接入位置及模型选择

保持原链路：

```text
原问题与已有QueryPlan
  → 原关键词/向量/RRF/去重
  → 固定同一批重排入口候选
  → 重排模块内部：
       原BGE相关性分 + 可核查结构特征 + 可选离线语义判别
       → 有依据的分档排序，替代旧辅助分及旧排名保护
  → 原条件检查
  → 已采用A的最终选段
  → 实际Context（本轮到此为止）
```

离线语义判别器建议首个实验候选为`Qwen/Qwen3-4B-Instruct-2507`的受支持量化部署。选择理由是需要按指令输出对象、关系和原文依据；这是待验证的用途假设，不是已经证明它在本语料更好。官方将其定义为非思考模式的4B指令模型，部署需采用相应模板。

- 官方说明：https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507
- 已缓存的`Qwen3-Reranker-0.6B`是重排模型；其官方yes/no相关性分不能直接当成对象冲突、证据完备性或JSON抽取结果。官方用法：https://huggingface.co/Qwen/Qwen3-Reranker-0.6B

2026-11-16本机核对：约15.7 GiB物理内存，显示设备Intel Iris Xe，现有RAG依赖为CPU路线。实验缓存内BGE v2-m3和Qwen3-Reranker-0.6B的指定快照存在配置和权重。本次没有下载4B指令模型，未证明其运行可行性。

实施时先固定一个可信来源的量化权重、上游revision、权重SHA256、量化格式、tokenizer、运行时和chat模板。优先验证CPU可执行的4-bit部署；不能将“参数量较小”解释为一定能与现有服务同时稳定运行。若无法稳定加载或输出，记录失败，保留规则实验结果；不临时连续更换多种模型直到分数好看。

本轮不以耗时优劣选方案，但必须记录模型能否完成、内存不足、输入截断和执行错误。性能优化不与准确性试验混在一起。

## 5. 离线模型的输入输出契约

### 5.1 输入

每个判断只使用：原始问题、已有解析（明确标注哪些为用户原词）、该候选实际正文、已有可信结构、来源位置及范围线索。不得传入Gold、题号、正确来源、人工正负标签、此前模型答案或其它未提供资料。

保留完整原问题；对于多目标问题只识别问题确实要求的目标，不自动要求每题都回答定义、原因、处理和安全事项。方法型问题允许条件分支，不能因用户未给当前数据就自动改成澄清。

正文是数据，不执行其中的指令。文件名是弱来源线索，不能独立确定本段的适用型号。范围判断要指出具体正文或可信章节依据。

### 5.2 输出

建议结构（字段为接口示意，不是某道题答案）：

```json
{
  "candidate_id": "运行期候选ID",
  "answer_targets": [
    {"text": "用户要求的某项信息", "question_quote": "原问题中对应文字"}
  ],
  "support_level": "direct | partial | related | irrelevant | unknown",
  "target_support": [
    {
      "target_index": 0,
      "level": "direct | partial | none | unknown",
      "evidence_spans": [{"start": 0, "end": 10, "quote": "候选正文实际原句"}],
      "reason": "原句如何回答该目标"
    }
  ],
  "applicability": "compatible | conflict | unknown",
  "scope_observations": [
    {"attribute": "原文实际属性", "value": "原文取值", "basis": "body | section | filename", "quote": "对应依据"}
  ],
  "condition_branches": [
    {"condition_quote": "原文条件", "action_quote": "同一分支动作", "scope_quote": "该分支适用对象"}
  ],
  "reason": "简短解释"
}
```

`direct`只表示直接支持所列目标，不代表整道问题已经答全。单个片段只能提供部分事实时用`partial`；多个部分片段可以互补，不能要求每段独立回答整题。

未知对象、未知适用条件、无法恢复表格绑定都可以输出`unknown`。模型自报置信度不作为触发强制改序或过滤的凭据。

### 5.3 程序校验与失败处理

1. 校验schema、枚举、candidate_id、目标编号及输出长度。
2. 按输入的原始Unicode正文校验每条引用的字符区间和内容；如做格式规范化，必须保存与原文offset的映射。
3. 将引用绑定到候选的文件、页码、原始片段及成员来源；表格校验同一行列归属，不能仅检查同页出现。
4. 输入截断、引用不存在、无法绑定、输出无效或执行失败，都不产生新的排序资格；退回该实验基座的BGE顺序，记录实际错误。不能悄悄调用远端API。
5. 引文存在只是必要条件，并不证明模型解释正确。模型可能引用了真实但不支持结论的句子，必须通过独立的业务证据检查检验。
6. 一段同时包含多个方法分支或多个型号时，按相应分支判断。不能因为其中存在不同对象就把整段判为冲突。

### 5.4 可见正文控制

现有BGE上限512 token，不同模型同token数不等于看到同样的正文。离线模型的初始完整输入预算设4096 token、输出上限768 token；先测冻结输入长度，不能容纳时在正式运行前统一调整并冻结。

主实验保持候选ID和原始正文完全相同。模型实际可见正文、被截掉的字符和各引文可见性逐条记录。如果改善涉及BGE原先看不见的文字，补做“离线模型只看BGE实际可见正文”的隔离对照，区分语义能力和输入范围的收益。不得把补回被截掉文字的效果全部归为推理能力。

## 6. 替代排序机制

本轮不再将模型sigmoid、结构标记和模型自报置信度按任意比例相加，也不强制恢复融合旧名次。建议首个候选使用可解释的分档及稳定排序：

1. 为用户每个明确答案目标记录直接支持、部分支持、仅相关和未知；判断必须带可定位原句。
2. 可核查且直接提供所问内容的证据可以提前；只有标题、题干、目录或术语出现不能获得相同资格。
3. 明确对象/条件冲突只作为有依据的降序信息，不新增硬删除。方法问题中的合法条件分支不能按“当前条件未说明”降级。
4. 适用范围未知不等于冲突，不单独施加“未知扣分”。兼容证据也不能只凭兼容就超过真正回答问题的范围未知证据。
5. 同等回答支持程度下，使用已有BGE顺序作为稳定顺序；精确标识符与完整结构只有在目标归属一致且确实提供对应事实时才能作为进一步依据。
6. 多目标问题检查每个目标在前8中是否有证据。部分证据保留独立身份，不能将定义片段排高就宣布处理流程完整。

分档具体比较器、未知处理、冲突适用条件和稳定排序键应在看独立验收结果之前冻结。开发期对比较器的每个变动都留版本，不依据某题ID追加例外。

本轮先验证单片段判别加稳定排序能否满足目标；如果方法步骤仍因列表整体重复而缺失，归因为“组合覆盖排序不足”。只有观测到该失败，才开展下一项独立的目标覆盖排序实验，届时固定已经通过的判别结果，不同时换模型、输入和选段算法。本轮不预先叠加覆盖贪心、MMR和新的固定配额。

## 7. 五组对照及变量定义

所有组使用相同的原始问题、同一批候选、正文、Gold、AI包及下游组件。

| 组 | 内容 | 用途 |
|---|---|---|
| P | 当前混合分+旧排名保护 | 当前生产对照 |
| B | 现有BGE原始顺序，无旧辅助分和旧保护 | 诊断基座，不是预定采用答案 |
| R | B+可核查结构规则和有条件的证据优先 | 测规则独立收益和误伤 |
| M | B+离线语义判别及引用校验 | 测语义判别独立收益 |
| RM | B+规则+离线语义判别 | 测组合是否互补，还是重复干预 |

R仅使用已存在候选正文中的结构；不补抓相邻页或增加新候选。M与RM使用相同的原问题、候选正文及模型提示；RM在排序时额外使用R的结构判断。模型输出可按完全相同的输入哈希复用，不计为独立重复推理。

规则抽取结果可供所有组记录诊断，但只有相应实验组允许它改变排序。M和RM均做基本引用校验；引用校验不是R因素，以免把模型输出无效和结构规则效果混算。

对P复用历史记录的前提是输入、代码和设置可复现；旧50题旧Gold结果不能直接与当前49题混算。已有B记录只能在问题、正文和模型快照完全一致时复用。

### 8.2 来源与对象判分

- 必须在实际入选正文中找到完整引文及对象绑定，不用同页其它内容、父块全文或未发送正文替代。

- 已标注强负例进入Context，与答案误用是不同指标。本轮记录前者，尤其检查错误型号、错误部件、错误操作关系和缺少参数的题库文本。
- Q019场景和处理页分别追踪；Q021必须保留两条条件处理分支，不能增加“必须计算/必须追问”的新要求。
- Q023按真实代码说明行核查，不以同页含代码视为已获得原因和处理步骤。

### 8.3 新的机制单元检查

用真实资料中的片段及同源干扰片段，建立以下测试对：参数行vs要求口述参数的题干；采集对象vs安装位置；条件动作说明vs操作界面导航；方法多分支vs单场景记录；同代码不同含义；同对象不同机型；同页不同表格行；未知条件vs明确冲突；部分答案互补vs重复解释；正文相同但文件名不同。

它们是组件测试，允许使用真实问题的局部对照，但不算独立业务题数量。反例的“不适用原因”要有原文依据，不凭关键词换几个字构造虚假业务结论。

### 8.4 独立验收候选

另取12道未参与本轮规则、提示和排序开发的真实业务问题，覆盖参数单位、对象功能、条件步骤、多目标/多分支，每类3道。按业务问题和来源分组，尽量避开开发页及同正文副本；记录无法隔离的重叠。

题目与证据在运行最终候选之前冻结，全部pending。优先从已索引资料中选取，不要求用户先制作词典。新题发现争议就标待核，不用新题结果调规则后继续称其独立验收。pending的成功只能称来源核验后的预验收，正式采用仍受人工审核边界约束。

- 不按答案好坏重试。仅传输/进程执行错误允许一次有记录的恢复；原失败仍计入执行稳定性。
- 产物：`local_model_manifest.json`、`model_component_results.jsonl`、`model_reliability.json`。
- 门槛：无有效引用不改序；所有已确认的对象错配、条件颠倒作为采用阻断项。模型不可运行时停止M/RM分支，完成R结论，不自动换多种模型。

### 第四步：固定候选的五组对照

- 对91题运行P/B/R/M/RM，各组候选ID、正文和入口顺序相同。
- 记录每条候选的BGE分数、结构判断、语义判断、引用校验、各组名次及具体改序理由。
- 主要看前8完整证据和对象错误；前1/3/5与MRR作排序辅助指标。
- 对原先规则改善的题、004/006等已知损失题以及所有新得失逐一复核。不能只选择典型成功截图。
- 产物：五组JSONL、`comparison.json`、`candidate_changes.jsonl`、`manual_source_audit.md`。

### 第五步：通过真实API前入口检查下游

- 固定原条件检查、采用A选段和12000字符预算。对获选候选与P配对跑`AnswerService.retrieve`等实际入口，不用实验脚本自制Context代替生产Context。
- 比较重排后、条件后、最终选段后、实际Context四个位置；检查新增/丢失/截断事实和分支。
- 若重排改善被下游损失抵消，明确记录下游原因。本轮不同时修条件检查或改选段来制造总收益。
- 产物：`native_pre_api.jsonl`、`context_diff.jsonl`、`downstream_attribution.json`。

### 第六步：独立预验收与执行稳定性

- 只对已冻结的最终候选与P/B运行12道新增pending题。冻结后不根据这些题继续调提示和规则。
- 逐题回到原资料页核查，包括模型引用真实但解释不成立、同页错行、跨型号和半套流程等情况。
- 对所有关键变动检查2次语义判别的排序及实际Context稳定性，缓存命中不算第二次独立推理。
- 产物：`holdout_pending.jsonl`、`holdout_source_audit.md`、`repeatability.json`。
- 若出现实质性误伤或收益仅在旧失败题，结束本轮并限定结论，不持续加例外规则。

### 第七步：回归、报告与采用决定

- 执行重排、QueryPlan兼容、条件检查、证据选择、Context及报告来源定位相关测试。

- 汇报规则与模型各自增加了什么能力；如果模型相对R/B没有新增业务收益，就没有启用模型复杂度的依据。

- 产物：`test_results.json`、`report.html`、`report_sources.json`、`open_report.cmd`、`conclusion.md`、`adoption_decision.json`。

## 10. 指标与采用标准

主要指标：

1. 前8中全部必要Gold证据完整保留的题数，以及逐题缺失项。
2. 真实Context中完整引文、对象、条件、分支和顺序的保留。
3. 新增明确错对象/错场景正文、错误条件颠倒、必要事实丢失。
4. 模型错误直接支持、错误冲突、无效引文、执行失败及弃权次数。

辅助指标：Recall@1/3/5/8、MRR@8、结构化行完整率、重复片段比例。MRR只表示首条有效证据靠前，不代表整题答全；同一问题不同问法按组统计，不能靠增加改写放大收益。

拟定首轮采用门槛（执行前冻结，属于本轮决策标准，不是普遍统计保证）：

- 相对P，正式完整证据题数至少净增2个不同业务组，且正式原有完整题无新增必要证据丢失。
- 新增明确对象错配、跨型号泛化证据、条件颠倒和方法步骤实质性丢失为0；非Gold必要内容也核查，不能用Gold未覆盖逃避。
- 模型方案相对规则R或诊断B至少产生一项可核查的额外业务收益；只有分数或指定文件名次变化，不算模型采用理由。
- 新12题按来源核验的预验收没有新增实质错误；其pending状态及人工审核缺口如实呈现，不冒称正式独立验收通过。
- 默认策略的兼容回归无新增失败；启用候选时的执行失败不能被择优重试掩盖。
- 达不到标准给出“暂不采用”或明确范围的结论。不能为了满足净增数量删题、改Gold、扩大答案要求或临时追加模型。

如果只改善004/006而独立范围无证据，结论为“修复当前已确认机制损失，通用采用依据不足”。如果R已经满足目标而M没有额外收益，选择较简单的R；不能因用户允许模型就必须上线模型。

## 12. 本方案最终需要给出的结论

必须逐项回答：原机制目标是否保留；规则解决了什么；模型额外解决了什么；哪些题变好/变坏；改善发生在哪一层；错误是否来自模型、绑定、排序或下游；独立证据有多充分；是否值得增加离线模型。

采用决定分别列“可合入但默认关闭的基础设施”“可采用的规则”“需要预验收/灰度的本地模型”“暂不采用的排序候选”“需要业务确认的资料争议”。本轮不会因总一致率提高就宣称答案整体成功，也不会恢复此前已回退的回答后处理体系。
