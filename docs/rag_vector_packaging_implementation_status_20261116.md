# 向量包装与结构化表示：实现及验证进度

本文件是执行进度，不是效果验收结论。完整实验结束后，以 `reports/rag_vector_packaging_20261116/conclusion.md`、`final_acceptance.json` 和 `report.html` 为准。`final_acceptance.json` 不存在或 `completed` 不为 true 时，不能认为完整方案已经验证通过。

## 本轮只改什么

只改变“资料正文在送入向量编码模型前如何表示”。原始问题、查询编码指令、模型权重、窗口边界、父块最大值聚合、BM25、RRF、BGE 基础排序、条件检查及最终选段保持原方案。实验不调用生成或裁判 API，不输出答案正确率。

新能力全部通过显式参数传入。没有把新策略接入生产默认配置，没有发布候选索引，也没有修改用户持久化设置或旧 Gold。

## 固定对照

| 方案 | 模型实际看到的内容 |
|---|---|
| W0 | 原来的文件名、位置、正文；超预算时沿用原正文回退 |
| W1 | 去掉文件名，保留位置与正文 |
| W2 | 去掉位置，保留文件名与正文 |
| W3 | 仅保留“正文”标签与正文 |
| W4 | 纯正文 |
| W5 | 可信原生标题，否则完整文件名提示；背景不超过 32 token，总长不超过 192；完整字段加入或省略，不截断正文 |
| W6 | 只有两个单表示出现符合冻结条件的互补收益时，才执行等预算双视图及重复视图对照 |
| F10 | W0 加入完整原生表格行 |
| F01 | 已冻结选定的单包装 P* |
| F11 | 与 F10 同一批结构行，使用 P* 包装 |
| F10_count_matched | 同等向量数量的结构替换敏感性，避免把多了向量全部归功于结构 |

若没有单包装通过门槛，P*=W0。此时 F11 和 F10 复用同一真实索引图，不能把 ANN 随机图差异误当成交互收益。

## 执行资源及真实性约束

六种包装加结构行共有约 27 万条不同编码文字；大量字符串不能复用旧向量，必须重新编码。因此完整实验尚需本地计算，不能从 W0 基线提前判断新策略有效。

隔离资料编码使用相同 BGE 权重导出的 FP32 ONNX 执行方式，不量化、不换模型、不删候选。256 条覆盖 3–192 token 的文本与原 PyTorch FP32 核对：最低余弦 0.9999998808，最大绝对误差约 2.14e-7，分词计数一致。两者不是逐比特相等，误差已记录于 `encoding_runtime_audit.json`。查询和重排仍走原实现；该执行后端不加入生产依赖和默认链路。

首轮错误导出未通过数值核对，被拒绝使用；仅验证通过的模型进入编码。编码结果写隔离缓存，每批落盘。过程、失败和修复记录保留，不按质量择优重试。

## 已知能力边界与待核事项

1. 结构补充仅覆盖简单原生 PPT 表格。已冻结 1,279 行、涉及 242 个父块。复杂合并表格、PDF、图片表格没有恢复，原表示保留。
2. 标题背景只来自可信 PPT 标题占位符；未提取到标题的其他格式使用文件名提示，文件名不充当适用范围硬证据。
3. 有一个 PPT 的标题占位符实际为图形框，读取失败后按记录回退，不假装原生结构已覆盖该文件。
4. 表格 firstRow 样式只提供结构线索，不能自动证明表头语义正确。实际列名与行值审计、错误对象和范围复核单独记录；待核实不能写成通过。
5. 新诊断资料中一份 BS-1000M 文档的文件名报警码与正文报警码不一致，已保留冲突；问题没有使用冲突码，不由模型猜测哪一个正确。
6. 父块命中与实际编码窗口承载是两种口径；实际 Context 只检查 `included_text`，同页其他文字不计命中。
7. API 后答案质量不在本轮范围；向量改善尚未传递到 Context 时，按最早丢失阶段说明。
