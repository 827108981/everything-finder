## 1. 目标和通用性边界

目标是建立一个支持中文短词、能够解释计分、对未知专业词有补充匹配能力的关键词基线。

线上处理只读取问题和索引数据，不读取用例 ID、Gold、参考答案、预期行为或诊断结论。不给 P02、制冷、试剂盘等案例添加专用规则，不识别“哪个是业务核心词”，不强制套用范围/方向/阶段等业务结构，不自动组合多个型号做 AND 硬过滤。

通用性的含义是处理流程不随专业对象逐个增加分支，不代表所有问题必然排对。分词仍可能失误，同义表达仍可能无法通过关键词找到；本轮应记录这些边界，而不是暗中添加业务词表。

## 3. 最终检索流程

```text
原始问题
  → 保护原文中的字母数字标识串
  → 通用中文精确分词，记录原文位置
  → 去除标点及重复查询词，保留单字、两字词
  → 词项倒排查找 + 完整查询词的原文补充查找
  → 合并同一词、同一字段、同一原文位置的匹配
  → 应用现有范围/扩展名/OCR过滤
  → 按统一词项公式计分
  → 排序输出 Top50，并记录每词贡献
```

补充匹配只是另一种定位方式，不是另一份相关性奖励。例如“制冷”同时通过分词索引和字符定位索引找到同一个位置，只计一次。

### 3.1 分词器选择

新增可替换的 `LexicalAnalyzer` 接口，初始实现采用离线 Jieba 精确模式，使用独立 `Tokenizer` 实例，避免全局词典状态污染。具体依赖版本在实施开始时验证兼容性后锁定；默认词典文件哈希和 HMM 设置进入索引指纹。

不使用搜索模式生成的全部重叠词直接累计打分，不加载针对这 8 题的自定义词典。

第一版不新增业务停用词表，也不预先删除“作用、方式、原因”等词。标点不作为词项；其他常见词的影响由语料词频和重复查询词去重控制。若后续需要通用停用词实验，单列实验，不与本轮基线混在一起。

参考：<https://github.com/fxsjy/jieba>。

### 3.2 标识串保护

保护字母数字混合串及其内部合法连接符，使 `P02`、`J8`、`BS-2800M` 不被拆成多个独立词。这里只识别文字形态，不宣称它是型号、部件或故障码。

匹配需核查边界：J8 不能命中 J80/AJ8，P02 不能命中 P020。大小写和全角半角处理必须由明确、有版本的检索规范化规则控制；不移除前导零，不擅自把 BS-2800M 与 BS2800 判为相同，不改变原始来源正文。

### 3.3 查询与文档一致性

文档正文、去扩展名文件名、查询使用同版本的分词器与检索规范化规则。

完整路径、页码、文件扩展名不进入本轮相关性计分。路径用于范围过滤和来源定位，页码用于展示和证据核查。

保留单字词，例如“泵”。它是否能排前由词频、正文命中及其他词项共同决定，不因为长度短就丢弃。

V2 的词项从 `QueryPlan.original_text` 独立生成，不复用旧 `_DOMAIN_TERMS`、`positive_core` 或旧 3/4 字窗口结果；旧条件分析仍供原有后续阶段使用，但不能悄悄改写 V2 的输入。

## 4. 完整词的补充匹配：解决分词错误，不重新引入窗口加分

使用中文连续字符的二字定位索引帮助找到原文位置，但二字窗口只作为定位键，不进入查询词列表和最终得分。

举例：查询词“超微流控”在文档中被分成“超微/流控”，词项索引可能没有完整词。补充索引使用“超微、微流、流控”的相邻位置定位，核查原文确实连续包含“超微流控”，最终只产生一条完整查询词匹配。

规则：

- 两字词直接定位；更长中文词按相邻位置核查完整字符串。
- 不允许“分别在不同句子找到几个二字片段”就认定完整词命中。
- 同一位置既被词项索引找到又被补充索引找到，合并为一次出现。
- 单字词只使用词项索引，不在全库启动任意单字子串扫描。
- 字母数字标识串使用精确词项和边界检查，不采用中文二字模糊匹配。
- 不跨不同正文块、不同表格单元格等结构边界拼接；若索引现有正文无法恢复结构，保留现有文本边界，不猜测补全。
- 规范化后的定位需要保留回原文的映射，以便报告高亮；规范化版本必须进入指纹。

这样未知专业词不会完全依赖词典，又不会重现“词切得越碎、累计分越高”的问题。

## 5. 统一计分规则

采用 BM25 形式的词项得分，区分正文与文件名辅助贡献。SQLite 负责存储倒排和位置，本轮的计分在一个独立模块内实现，避免原生 trigram BM25 与新词项分数直接混加。

设查询去重后的词项集合为 Q；N 为索引 chunk 数；df(t) 为包含该完整词的 chunk 数。词项索引与补充匹配的同位置出现合并后才统计 tf，df 按 chunk 去重。

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))

term_score(t, field, d)
  = idf(t) × tf × (k1 + 1)
    / (tf + k1 × (1 - b + b × field_length / avg_field_length))

body_score  = Σ term_score(t, body, d)
title_score = Σ term_score(t, title, d)

lexical_score
  = body_score + title_weight × min(title_score, Σ idf(t))
```

初始参数：`k1=1.2`、`b=0.75`、`title_weight=0.2`。这是明确的实验起点，不声称最优。空字段、零平均长度、零命中、超长词须显式处理。

正文和标题字段长度使用同一分析器产生的词项计数；完整词的原文补充匹配可能跨多个分词词项，这种扩展与标准纯词项 BM25 的差异必须在实现说明中记录。因此报告将分数命名为 `lexical_bm25_fields_v2`，不冒充数据库原生 BM25。

查询中同一词重复出现不额外加权。补充匹配不获得独立奖励，不根据“像型号/像部件”额外加分，不把不同词强制 AND，不加入业务适用性判断。

按得分降序，稳定 chunk ID 作为同分次序。旧分数为越负越前，新分数为越大越前，必须带 `score_kind` 和方向，禁止直接比较绝对值。现有融合使用名次，仍只接收 V2 最终关键词名次。

df 为固定语料统计；范围、扩展名、OCR过滤在最终截断前执行。不能先取全库 Top50 再过滤，导致范围内应入选内容无机会进入。

## 6. 数据结构与文件设计

### 6.1 新增模型

建议放在 `rag/retrieval/lexical_models.py`，避免继续膨胀所有业务共用的模型文件。

```python
@dataclass(frozen=True)
class LexicalToken:
    text: str
    normalized: str
    start: int
    end: int
    surface_kind: str  # 普通词 / 受保护标识串；不是业务角色

@dataclass(frozen=True)
class LexicalQuery:
    original_text: str
    tokens: tuple[LexicalToken, ...]
    analyzer_fingerprint: str

@dataclass(frozen=True)
class LexicalTermContribution:
    term: str
    document_frequency: int
    body_frequency: int
    title_frequency: int
    body_score: float
    title_score: float
    match_methods: tuple[str, ...]
```

实际类型还应包含版本、来源位置、异常状态和最终得分；上述为责任划分示意，非已实现代码。

### 6.2 独立关键词索引文件

本轮优先采用**绑定现有 AI bundle 的独立关键词索引文件**，不直接修改已发布的 `metadata.db`，不重建普通全文索引或向量库。这比升级整个 AI bundle 更容易隔离变量，并避免仅关键词升级触发 Gold 快照不匹配。

建议目录：

```text
rag/lexical/<source_bundle_id>/<index_fingerprint>/lexical.db
rag/lexical/<source_bundle_id>/active.json
```

索引构建先写独立临时目录，完成校验后原子发布。索引指纹变化产生新的关键词索引版本，旧版本保留；稳定 chunk ID 仍指向原 AI bundle 的正文。

建议表：

```text
lexical_meta
  schema_version, source_bundle_id, source_content_digest,
  analyzer_fingerprint, chunk_count, state, created_at

lexical_documents
  stable_chunk_id PRIMARY KEY, body_length, title_length

lexical_terms
  term_id PRIMARY KEY, term_kind, term_text
  UNIQUE(term_kind, term_text)

lexical_occurrences
  term_id, stable_chunk_id, field, start_offset, end_offset
  PRIMARY KEY(term_id, stable_chunk_id, field, start_offset, end_offset)
```

`term_kind` 区分完整词与中文二字定位键；检索使用各自索引，不把定位键当成查询词。添加必要的 term_id 和 chunk_id 索引，批量写入。正文仍从原 metadata.db 只读加载，不重复储存正文全文。

来源摘要覆盖排序后的 chunk ID、正文哈希、文件名等所有影响关键词索引的字段。分词器版本、词典哈希、HMM 设置、规范化规则、schema 版本进入索引指纹；排序参数写入运行配置，不因改变标题权重就重建词项索引。

## 7. 兼容、复用与配置

新增 `rag_lexical_backend = legacy | word_v2`。验证期间两者显式选择，不使用含糊的自动切换。

- `legacy` 保留现有行为，作为对照与回退。
- `word_v2` 必须加载与当前 bundle、内容摘要和分析器指纹一致的已完成关键词索引。
- 缺失、损坏或版本不符时返回明确“关键词索引未就绪”，不能静默退到 legacy 然后把运行标为 V2。
- V2 与旧 `rag_lexical_multi_route_enabled` 同时启用时配置检查报冲突；不将旧多路线混入此次实验。
- 普通问题查询不现场构建大索引；由明确的关键词索引准备步骤完成。
- 同来源、同指纹再次准备时复用同一关键词索引，不产生新数据库。
- 来源或分析器版本改变才创建新版本。来源快照切换时，查询同时固定原 bundle 和关键词索引引用，不能混用。
- 构建取消或失败不发布半成品；进程崩溃后旧 active.json 仍有效。
- 回退只切配置/关键词指针，不清理用户已有索引。构建产物清理另行按既有保留策略处理。

先提供独立构建命令和评测入口；默认切换前，再接入桌面 AI 索引准备流程。现有 AI 索引无变化而提前返回的路径，也要检查关键词附属索引是否就绪；不能把“AI 正文没变化”误当成“新增关键词索引已存在”。

## 8. 报告与可观察性

每个运行记录实际的：后端、源 bundle、关键词索引版本、分析器指纹、标题权重、评分公式版本。

每个问题展示：

1. 原始问题、实际词项、词项对应原文位置、重复词去重结果。
2. 每个词的全库 df、词项查找到的候选数、完整文字补充查找到的候选数。
3. 过滤前/后的候选数、完整计分的候选数、最终 TopK 数量。
4. 分词、候选定位、正文加载与补充核查、计分、排序的耗时。
5. 每条 Top50 候选的命中正文/标题、词频、得分贡献和最终分数。

默认折叠逐词明细；关键词页首先显示一句可读解释，如“正文命中 P02、BS-2800；标题无贡献”。全部正式贡献保存在 JSON，便于程序独立复核。

过载/取消必须记录为未完成或明确降级。不得在未说明的扫描上限处停止后把缺失候选描述成“全库没有”。最终 Top50 截断与候选扫描中止是两种不同状态。

## 9. 验证：先验证机制，再看真实分数

### 9.1 单元及小语料集成测试

| 类别 | 输入/场景 | 必须验证 |
| --- | --- | --- |
| 短词 | 制冷、校准、压力、泵 | 两字和有意义单字可以独立索引与命中，不仅测试“制冷” |
| 未知编号 | J8、P02、XQ17 等自动生成编号 | 精确边界有效，不能命中延长或前缀不同编号 |
| 未知中文词 | 无自定义词典的新造术语，问题和正文分词不同 | 原文补充匹配可找到完整词，不能跨不相邻位置拼成词 |
| 重复证据 | 同一位置同时命中两套定位索引 | tf 仍为 1，不能双倍得分 |
| 查询重复 | 相同词在问题中重复多次 | 仅因重复询问不使该词贡献倍增 |
| 字段干扰 | 多份文件名重复泛称，正文无所问事实 | 文件名贡献受上限控制，路径重复文字完全不改变分数 |
| 路径不变性 | 只移动目录、正文和文件名不变 | 得分和排序不变；索引绑定信息按规定更新 |
| 词项统计 | 手工可算的小语料 | 独立核算 df、tf、idf、各字段得分与并列排序 |
| 极端输入 | 空问题、全标点、长问题、引号与SQL字符 | 无崩溃/注入；过限给明确状态，不隐式漏词 |
| 否定/比较 | 不是A而是B、A与B有什么不同 | 保留实际词项与原问题，不擅自生成硬业务过滤 |
| 过滤 | 指定范围、扩展名、OCR条件 | 在TopK之前过滤，后面的范围内候选可补入 |
| 兼容性 | legacy报告、缺失贡献字段、两种分数方向 | 旧报告可读，新分数方向正确，融合仍只取名次 |
| 版本/取消 | 同指纹复用、词典变化、构建取消、半成品、并发切换 | 不复用错误版本，不发布半成品，不混合来源 |

不写“实现生成几个词、测试就断言相同几个词”的镜像测试作为主要证明。优先验证能否找到实际正文、得分是否独立可算、无关变化是否影响排序。

### 9.3 消融实验

| L2：L1加有上限的文件名辅助 | 测文件名是否值得保留及其回退 |
| L3：L2加完整词的原文补充定位 | 测未知词/切词差异补救 |

输出各配置的词项、Top50、每条Gold排名和原因差异，不能只给一张汇总成绩。

初始参数先冻结。若调标题权重，只在预先限定的小范围内比较并记录，最终配置在未参与调试的题目上确认；不能根据这8题逐题设权重。

### 9.4 真实评测与泛化验证

- 使用真实现有 SQLite 正文、本地模型和保存的索引；本轮主实验为 retrieval-only，不调用 LLM。
- 原18题和跨领域8题都跑；Gold、问题、快照、过滤条件冻结。
- 候选Top50输出预算一致，同时报告原始读取量和计分量；新实现检查更多候选时，不能声称同算力预算。
- 主指标：关键词 Hit@5、Hit@50、MRR、按题平均Gold覆盖。
- 次指标：保持其他模块一致时的上下文Gold覆盖，以及指定反例排名。未标注候选不能自动视为负例。
- 004、005等未标注替代依据单独列出，不修改正式Gold分数。
- 按事实主题划分调试集与留出集，不能把同一事实的问法变体分别放两边冒充独立验证。
- 留出集应包含不同专业对象、未知编号、短词、长术语、无型号问句、比较问句；已有新Gold需先核实reviewed与索引快照，未审核题不计正式分数。
- 自动生成的编号/词序变体只证明机制鲁棒性，不代替真实资料留出评测。

### 9.5 性能与资源

记录关键词附属索引大小、构建耗时、峰值内存；分别测冷启动、首次查询和预热后查询。固定问题顺序交错运行 L0/V2，预热后每题多次重复，报告中位数、P95和最大值。

词频缓存必须绑定索引指纹，失效规则有测试。性能优化不能偷偷缩小候选扫描范围改变排名；如需要预算限制，作为单独配置与明确降级状态验证。

## 10. 建议验收门槛

以下是建议目标，不是当前已实现或保证达到的成绩，用户可审核调整：

1. 全部机制和版本安全测试通过；V2实际启用可从报告核实。
2. 跨领域8题关键词Hit@50至少达到6/8；003、005、006各自的声明Gold进入Top50作为重点检查项。任何未达项必须报告具体原因，不靠改Gold过关。
3. 原18题非拒答16题不新增整题Gold漏召回；逐条证据覆盖不能被整题命中数掩盖。
4. 未参与调试的已审核留出题，整体覆盖与Top5结果不低于基线；逐题退化必须可解释并列出。
5. MRR、Top5与覆盖共同评估，不因一个中间MRR微小变化一票否决；最终上下文出现核心依据丢失必须审查。
6. 建议关键词预热P95不超过legacy的2倍，且本机单题P95不超过500ms；实际基线测得后确认是否符合桌面交互预算。不能以功能提分掩盖不可接受的延迟。
7. 重复准备相同关键词索引复用原文件；原AI bundle、向量和普通索引不改变，失败或取消后旧配置仍可正常查询。

若未达门槛，交付失败分析和实验产物，保持可选实验状态，不把“代码合入/测试通过”描述为检索质量达标。
